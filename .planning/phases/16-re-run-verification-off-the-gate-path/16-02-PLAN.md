<objective>
Deliver REQ-P16-01: the `dsx-reproduce` skill that re-runs `reproducibility.entrypoint` OFF the gate
path, compares the fresh headline numbers to declared `results.tests`, and writes `REPRO-REPORT.md`
with a machine-readable number block plus an explicit status field; the `templates/REPRO-REPORT.md`
that fixes that block's schema; and the capability registration that advertises the skill.

Purpose: Phase 16 splits "reproduce" cleanly across a purity boundary. The SKILL may execute the
entrypoint (it runs in the agent runtime, not the deterministic gate); the GATE (16-01) only checks
that the produced report exists and its numbers overlap. This plan builds the produce half. The
template is the contract that couples the two halves: its fenced `metric: number` block and its
`status:` field are exactly what dsx/checks/repro.py::_check_reproduce_report reads, and its
SKIPPED/UNABLE status is what lets an honest missing-interpreter run avoid a gate exit 1 (D-11).

Output: `templates/REPRO-REPORT.md` (new), `skills/dsx-reproduce/SKILL.md` (new), and a one-line
registration in `capabilities/dsx/capability.json`.
</objective>

registration. The executing surface lives entirely in the skill runtime — OFF the deterministic gate
path — and this plan touches no dsx/ module, so it adds no runtime gate surface. The template and
skill are authored text. No network/auth/session surface is introduced. No npm/pip/cargo install
occurs, so T-16-SC is N/A this plan.

| Boundary | Description |
|----------|-------------|
| skill runtime → entrypoint | The skill executes `reproducibility.entrypoint` via Bash in the agent runtime. This is the ONLY sanctioned execution site; the gate never crosses this boundary (D-01). |
| skill → REPRO-REPORT.md → gate | The skill writes the report + stamps `reproduce_report`; the 16-01 gate then reads the report's numbers. The skill cannot force a pass — the gate re-derives overlap and ignores any verdict line (D-04). |
