## Blocker — wave-merge gate red on TWO out-of-scope baseline files

The D-02 rebase makes DSX-EXP-051 fire on two known-bad fixtures that declare **no family and no
`results.tests`** but set `comparisons_looked_at: 5`. With the plan's mandated formula
`looked > max(len(family), len(tests))` this is `5 > max(0,0)=0` → fires. This is the sanctioned
behaviour (family-independent firing), not a bug in the implementation.

That firing invalidates baseline locks in two files **not listed in this plan's `files_modified`**:

| Failing test file (out of scope) | Fixtures | What the framework asks for |
| --- | --- | --- |
| `tests/test_causal_verb_golden.py` (`_GOLDEN_SHIP_FINDINGS`) | `full-frame-cleaning`, `post-hoc-procedure-switch` | add `DSX-EXP-051` to each fixture's golden ship set |
| `tests/test_known_bad_corpus.py` (`_INCIDENTAL_GAP_CODES`) | `full-frame-cleaning`, `post-hoc-procedure-switch` | document `DSX-EXP-051` as an incidental gap with its cause |

Both messages explicitly instruct documenting the new incidental finding in those baseline files
— the sanctioned path — but doing so requires editing files this plan did not authorize. Per the
executor's STRICT SCOPE rule ("modify ONLY the plan's files_modified … STOP and report rather than
expanding scope"), I did **not** touch them.

### Orchestrator decision required (two options)

1. **Accept the firing (recommended, matches the plan's mandated formula and D-02 intent):**
   authorize a scope extension to add `DSX-EXP-051` to the two fixtures in
   `tests/test_causal_verb_golden.py::_GOLDEN_SHIP_FINDINGS` and to
   `tests/test_known_bad_corpus.py::_INCIDENTAL_GAP_CODES` (with a one-line cause). Purely
   mechanical baseline updates; no source-check change.
2. **Suppress the degenerate `tests=0 && family=absent` case:** add a `base >= 1` guard in
   `_check_exploratory_looks` (in-scope `dsx/checks/design.py`) so DSX-EXP-051 only fires when
   there is a reported baseline to exceed. This keeps both baselines green and still satisfies
   D-15c (family absent, tests=3, looked=5 → fires) and the good/bad verdicts — but it deviates
   from the plan's verbatim formula and narrows the check. Not applied unilaterally because it
   contradicts the plan text.

## Resolution (orchestrator, §4 persona round — Option 1)

The blocker above was decided by a two-persona round (Statistician `dsx-statistician` +
Auditor `dsx-ml-integrity-auditor`, both opus, concurrent), tie-break rigour > reliability >
flexibility. **Unanimous: Option 1.**

- **Statistician — TRUE POSITIVE, not a false fire.** Both fixtures declare
  `comparisons_looked_at: 5` with no `multiplicity.family` and no `results.tests`, and report a
  single winner ("the fifth candidate ...") with no correction — total non-disclosure of a
  comparison family (naive FWER 1−0.95⁵ ≈ 23%). Option 2's `base >= 1` guard is **non-monotonic
  and perverse**: it fires on partial disclosure (base=1) but exempts total non-disclosure
  (base=0), removing a genuine catch Phase 12 (REQ-P12) would score as a coverage regression.
- **Auditor — Option 1 is honest surfacing, not laundering.** DSX-EXP-051 is nobody's target
  code, so it is eligible for the GLOBAL `_INCIDENTAL_GAP_CODES` and the anti-laundering guard
  `test_incidental_allowlist_names_no_slugs_own_target_code` still passes. Both fixtures still
  **BLOCK** on their target codes — the verdict is unchanged, so this is not the map-editing the
  T-11.2-13 / plan-06 prohibition forbids. Option 2 reverses a plan-checker-approved formula
  without re-check (governance gap) and shrinks the catch surface.
