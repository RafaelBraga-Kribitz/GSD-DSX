## Deviations from Plan

The plan's Task-1 acceptance asserts the new cases fail RED. Two clarifications, neither a scope change:

**1. [Clarification, not a fix] The content-lock regression passes at RED time by design.**
- **Found during:** Task 1 (RED).
- **Detail:** `tests/test_frame_prereg.py::TestExclusionsContentLock` exercises the EXISTING `frame_digest`/`DSX-PRE-020` machinery, which already hashes the whole `validity_frame` subtree. Its whole point is "no new machinery," so it necessarily passes without any code change — it is a regression guard, not a RED-failing case. The genuinely RED-failing cases were the 5 `DSX-VAL-080` / `DSX-SPEC-083` fire assertions, which failed exactly because those checks were unimplemented. This matches the plan's must_haves (the content lock covers the sub-block "with no new machinery").

**2. [Rule 1-adjacent — dead-code avoidance] Removed the `_EXCLUSIONS_CITATION` constant.**
- **Found during:** Task 2 (GREEN).
- **Issue:** The plan's sibling checks keep a citation CONSTANT because they reference it in a per-check `DecisionRecord` inside `check()`. The plan scoped Task 2 to cloning the `_check_sampling_frame` HELPER + wiring dispatch, and did not ask for an exclusions `DecisionRecord`. A citation constant with no `DecisionRecord` consumer would be dead code.
- **Fix:** The citation lives inline in the `_check_exclusions` docstring (which is what `TestValCitationObligations` reads and requires), so the standalone constant was dropped rather than left unused.
- **Consequence / known gap:** The exclusions judgment point emits no `DecisionRecord`, so it does not appear in `dsx explain`'s decision trail (every other val.py check does append one). This is consistent with the plan's helper-clone scope and breaks no test; a follow-up could add the trail entry for parity. Flagged here for visibility.
- **Verification:** `bash scripts/check.sh` → all checks passed (no linter flags the removal; full suite green).
