# Phase 11.1.1 Plan 04: Detection code hardening (gap closure) Summary

**Closed all three reproduced code defects (fallback fit-keyword reordering, prose-masked
false positives on DSX-CODE-020/030/031, and a malformed-notebook AttributeError crash)
that failed SC2/SC4/SC5 at verification, plus a pre-existing `ast.Compare` false-positive
bug in `_first_argument` discovered while writing this plan's own SC2 false-positive-guard
test.**

## Performance

- **Duration:** ~45 min (six task commits span 23:01:52-23:13:10, plus upfront plan/source
  reading and empirical verification of every fixture against the shipped code before
  writing each test)
- **Tasks:** 3 (each executed as a RED test commit then a GREEN fix commit, per `tdd="true"`)
- **Files modified:** 2 (`dsx/checks/code.py`, `tests/test_dsx.py`)

## Accomplishments

- **GAP-1 (SC2):** `FIT_CALL_RE` widened with a bounded `{0,8}` repetition (inner run
  `{0,80}`) that skips non-allowlisted `name=value,` pairs before the recognised keyword, so
  `model.fit(y=y_train, X=full_frame)` after a split now fires DSX-CODE-021 on the fallback
  path exactly as it already did on the parsed path. A `(?!=)` guard keeps an equality
  comparison (`model.fit(a==b, y)`) from being misread as a keyword assignment. The false
  parity claim ("the two mechanisms agree ... instead of disagreeing on it") is removed from
  both places it was written, replaced with the actual, narrower scope.
- **GAP-2 (SC4):** `_first_full_frame_cleaning_line` and `_stat_test_lines_referencing` both
  gained a `masked: frozenset[int] = frozenset()` parameter, wired to the same `prose_mask`
  frozenset `check()` already computes once per call. A module or function docstring merely
  describing a cleaning idiom, or mentioning a statistical-test call on the declared target,
  no longer decides DSX-CODE-020/030/031 on the parsed path. Real executable code at the same
  positions still fires at the same line numbers (both controls pinned).
- **GAP-3 (SC5):** `_read_source`'s `.ipynb` branch now guards `isinstance(nb, dict)` before
  `nb.get("cells")` and `isinstance(cell, dict)` before the first `cell.get(...)`, returning
  `None` (not `continue`) on either failure so the document routes into `check()`'s existing
  "could not be read" `report.ok(...)` branch instead of raising `AttributeError` out of
  `check()` with exit code 1 -- indistinguishable from a legitimate gate block.
- **[Rule 1 deviation, found while writing GAP-1's own false-positive-guard test]**
  `_first_argument` now also excludes an `ast.Compare` resolved node. `model.fit(a==b, y)`
  produced a nonsensical CRITICAL finding ("fits on 'a == b'") on the primary (AST) path
  before this fix -- reproduced against the shipped code, unrelated to the regex widening,
  and required by this plan's own acceptance criterion that this input stay silent on
  *either* path.

## Decisions Made

- Widened `FIT_CALL_RE`'s skip fragment with explicit `{0,8}` (whole repetition) and `{0,80}`
  (inner run) bounds, rather than an unbounded skip -- both counts are pinned by
  `test_keyword_beyond_the_skip_bound_stays_uncaught_by_design_on_the_fallback`, which stays
  silent for a real leak whose recognised keyword arrives after 9 skipped keywords (one more
  than the bound).
- `_stat_test_lines_referencing`'s window filter drops masked indices by recomputing each
  candidate's absolute line index (`window_start + offset`) rather than re-deriving the mask
  or re-walking the tree -- the same `prose_mask` frozenset is read, never recomputed.
- The notebook cell-loop fix returns `None` on a non-dict cell rather than `continue`:
  measured while planning, `continue` would read a malformed-only-cell document back as the
  empty string, producing a silent "entrypoint parsed with ast" pass over nothing scanned --
  exactly what SC5 forbids -- and would renumber every line below the dropped cell.
- `[Rule 1 - Bug]` `_first_argument` excludes `ast.Compare` alongside `ast.Constant` --
  see Deviations below.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `_first_argument` did not exclude a resolved `ast.Compare` node**

- **Found during:** Task 1, while writing
  `test_equality_comparison_first_argument_is_not_read_as_a_keyword_on_either_path`.
- **Issue:** The plan's own behavior/acceptance-criteria text states
  `model.fit(a==b, y)` "stays silent on both paths." Measured against the shipped code
  (before any change in this plan) via `dsx.checks.code.check()`: the AST/primary path
  already fired DSX-CODE-021 CRITICAL with detail `"fits on 'a == b'"`, because
  `node.args[0]` for `a==b` is an `ast.Compare`, not `ast.Starred` and not `ast.Constant`, so
  `_first_argument` resolved it and `_render_token`/`_is_training_frame` treated the rendered
  comparison text as a non-training-frame token -- a false positive naming a token that was
  never a candidate frame reference. This is a pre-existing bug, independent of the
  `FIT_CALL_RE` widening (the fallback already stayed silent for this input, both before and
  after the widening -- confirmed separately).
- **Fix:** `_first_argument` now returns `None` when the resolved node is an `ast.Compare`,
  in addition to the existing `ast.Constant` exclusion. Minimal, single-line change; the
  docstring's point 4 was rewritten to document both exclusions and why.
- **Files modified:** `dsx/checks/code.py` (`_first_argument`, part of Task 1's GREEN
  commit).
- **Verification:** `test_equality_comparison_first_argument_is_not_read_as_a_keyword_on_either_path`
  passes on both the natural (parsed) and forced-fallback runs; no other `TestPhase11_1Code`
  or `TestPhase3Code` test references a `Compare`-shaped first argument, so this exclusion
  introduces no regression (confirmed: full 894-test suite green).
- **Committed in:** `dd7f923` (Task 1 GREEN commit).
