## Decisions Made

- Did not write `test_non_utf8_notebook_is_named_not_scanned_without_raising` and did not widen the read-and-decode tuple with `UnicodeDecodeError` — both were originally planned but corrected out of scope before execution began (see the CORRECTION truth in the plan's `must_haves.truths`). A non-UTF-8 `.ipynb` already exits 2 with a clear `dsx: invalid input` message via `dsx/cli.py`'s top-level `except ValueError` handler; adding a local catch in `_read_source` would have converted that correct, loud failure into a silent exit-0 "NOT scanned" pass — the exact failure mode the `.py` branch's own comment at `code.py:1078-1089` rejects for the analogous case.
- Made the `cells` guard stricter than the code review's suggested fix (CR-02: `cells is not None and not isinstance(cells, list)`): a document with no `cells` key at all, or `cells: null`, now returns `None` (routes to NOT scanned) rather than falling through to the empty-string return. Letting it through would print the affirmative "entrypoint parsed with ast" pass line over a document nothing was actually read from — the same silent-pass shape plan 04's own guard exists to prevent for non-object cells.
- The control test (`test_empty_cells_list_still_scans_as_an_empty_notebook`) calls `code_mod.check()` directly with no `model` section, instead of the class's shared `_check()` helper (which always declares `model.task`). A declared model block with no split marker in a genuinely empty entrypoint legitimately fires `DSX-CODE-010`, which would make the control assert something outside SC5's scope; isolating the model section keeps the assertion to exactly the property being pinned.

## Residual List for Plan 07 (README text is written from this)

Plan 07 owns the README text; this plan owns handing it the exact list of what still degrades and how. Four entries:

1. **The two `.ipynb`/`.py` reads are NOT symmetrically "both reported, one scanned and one NOT scanned."** (This entry was corrected before this plan executed — see the CORRECTION truth; do not use the originally-planned version.) A `.py` file whose bytes are not valid UTF-8 is still scanned, with the undecodable bytes replaced. A `.ipynb` file whose bytes are not valid UTF-8 is NOT scanned in the "NOT scanned" passing-outcome sense at all — it is rejected outright with exit code 2 ("could not run") and a `dsx: invalid input — ...` message, the same code and message family the gate uses for a missing spec. This is a genuine difference in kind, not degree: the other four shapes this plan closes get a passing exit code 0 with a "NOT scanned" line; this one gets a blocking exit code 2 with no pass line at all. Plan 07 must describe this distinction accurately, not fold it into the "NOT scanned" family.
2. **A notebook nested more deeply than the running interpreter's recursion limit is reported as NOT scanned rather than scanned**, so a legitimately very deeply nested document would read as unscannable.
3. **A notebook large enough to exhaust memory during the read is reported as NOT scanned if the failure surfaces as `MemoryError`, and no size bound is enforced before the read** — the same exposure the `.py` read already has.
4. **NOT scanned is a passing outcome with exit code 0, and its pass line is only printed under `--verbose`**, so a notebook corrupted deliberately or accidentally makes the leak scan quiet rather than loud. This is the disclosure half of WR-02 and must be handed over as a limit to disclose, not as a defect to fix.

WR-02 (the missing `scan_path:not-scanned:<reason>` DecisionRecord) and the D7/D8 README-tone judgment are both **carried forward unresolved** — no task in this plan touched either. Confirmed: `grep -v '^#' dsx/checks/code.py | grep -c "scan_path:not-scanned"` returns 0.
