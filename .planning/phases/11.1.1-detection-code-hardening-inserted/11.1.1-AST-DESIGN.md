## 1. Parse entry point

### 1.1 Source acquisition (`_read_source`)

`_read_source(path: Path) -> str | None` keeps its signature and its "return `None` and skip
the check" contract. Three changes.

**(a) `.py` is read with `encoding="utf-8-sig"`, not `"utf-8"`.**
`utf-8-sig` decodes BOM-less UTF-8 identically and strips a leading byte-order mark when one
is present. A BOM currently reaches `ast.parse` as `U+FEFF` and raises
`SyntaxError: invalid non-printable character U+FEFF`. `examples/analysis/charts.py` is a
real in-repo UTF-8-with-BOM file that fails to parse when read the way `_read_source` reads
it today; it is never an entrypoint, so nothing in the suite moves, which is exactly why
this fix must ship with a synthetic BOM fixture of its own (§10) rather than unpinned.

**(b) the read is guarded against `ValueError` as well as `OSError`.**
`path.read_text` raises `UnicodeDecodeError` (a `ValueError`) on a non-UTF-8 entrypoint,
which today propagates out of `check()` and turns the gate into an exit-2 error. It becomes
`return None` — the same disposition as any other unreadable entrypoint.

**(c) `.ipynb` takes CODE CELLS ONLY. Markdown cells become blank lines.**

This is the fix for the measured false positive: a notebook whose only markdown cell reads
"We must never call `scaler.fit(X)` before the split", with a clean `pd.read_csv` code cell,
is blocked `DSX-CODE-001` CRITICAL today, because `dsx/checks/code.py:495` whitelists
`{"code", "markdown"}` and joins both with `"\n"`. That whitelist dates to the module's
original commit `86f449f` (2026-07-28) and has never been revisited.

The naive fix — keep code cells, drop markdown cells — is rejected, because it renumbers
every line of every notebook. The rule instead is:

| cell type | contributes |
|---|---|
| `code` | its source, verbatim |
| `markdown` | exactly as many EMPTY lines as its source has lines |
| anything else (`raw`, unknown) | nothing — dropped, exactly as today |

Chunks are still joined with `"\n"`, exactly as today. The number of lines a markdown cell
contributes is `max(1, len(src.splitlines()))`, and its contribution is
`"\n".join("" for _ in range(that count))`.

**Consequence, and it is the point of the design:** the reconstructed source has
**byte-identical line geometry** to today's concatenation. Every code line keeps the exact
index it has today. `Line N` for a notebook means the same thing before and after this
change, so no notebook line number moves — which matters precisely because no notebook is
pinned by any committed test and a silent renumbering would be invisible to the suite.

**Notebook line-number coordinate space, stated because §4 pins it.** For a `.py`
entrypoint, `Line N` is the Nth physical line of the file. For a `.ipynb`, `Line N` is the
Nth line of the reconstructed cell concatenation described above — **not** the Nth line of
the `.ipynb` JSON file, which the user cannot usefully open at that offset either way. This
was already true before this change; this design does not improve it and does not claim to.
It is named in §8 as a standing limitation and must be named in the module docstring.

**Module docstring at `dsx/checks/code.py:3` must change with the code.** It currently
advertises "`.ipynb` via json cell source concat in line order", which stops being true.
Replacement text is specified in §10.

### 1.2 Parse (`_parse_source`)

```
_parse_source(source: str, suffix: str) -> tuple[ast.Module | None, str, int | None]
```

Returns `(tree, degraded_reason, degraded_line)`. On success `("", None)` accompanies a
tree; on failure the tree is `None` and the pair carries a short reason and, when the
exception supplies one, a 1-based line number.

Order of attempts:

1. `ast.parse(source)`.
2. If that fails **and** `suffix == ".ipynb"`, apply the magic repair (§1.3) and retry once.
3. If that fails, return `(None, reason, line)`.

The repair is attempted **only** after a failed parse, and **only** for notebooks. That
ordering is deliberate: a line beginning with `%` is legal Python inside a parenthesised
expression, so blanking such lines unconditionally could damage a file that parses fine.
Repair-after-failure can only ever turn a non-parse into a parse.

### 1.3 The notebook magic repair

Jupyter cell sources routinely contain line magics (`%matplotlib inline`), cell magics
(`%%time`), and shell escapes (`!pip install pandas`). All three raise `SyntaxError` from
`ast.parse` (measured). A code-cells-only reader that stops there would send most real
notebooks down the fallback and would therefore preserve, for notebooks, the exact false
positive this phase exists to remove.

The repair replaces each line whose stripped form starts with `%`, `%%` or `!` with an empty
line — **in place**, one blank line per blanked line, so line count and every other line's
index are unchanged. Then it re-parses.

Not repaired, and named in §8: the `?`/`??` introspection suffix (`df.head?`). A rule that
blanked any line ending in `?` would blank the valid statement `s = "why?"`. A notebook
using `?`-help lands on the fallback.

## 2. Fallback contract

### 2.1 When the fallback runs

The parse is attempted **once per `check()` call**, over the whole source. Outcome is a
single module-level state for that invocation — `tree is not None` or `tree is None`. There
is no per-code fallback and no partial tree.

Rejected alternative: per-code fallback (AST for the call-shaped codes, text for the rest,
independently). It was rejected because two scanners would then disagree about `first_split`
inside one run — `DSX-CODE-001` would order itself against an AST split index while
`DSX-CODE-003` ordered itself against a text split index — and a gate whose codes disagree
about where the split is cannot be used as evidence. One flag, one `first_split`.

The exception guard is:

```
except (SyntaxError, ValueError, RecursionError, MemoryError)
```

- `SyntaxError` — the ordinary case; `IndentationError` and `TabError` are subclasses.
  Unclosed parenthesis, Python-2 `print`, a markdown cell that reached the parser, an
  unrepaired magic, a lone trailing backslash.
- `ValueError` — `ast.parse` raises it for a source string containing a null byte.
- `RecursionError` — **measured this session: a chain of ~4,000 binary operators raises
  `RecursionError`, not `SyntaxError`, in about 0.03 s (2,000 still parses).** A guard of
  `except SyntaxError` alone therefore crashes the gate on an ordinary long chained
  expression. This is the single most important line in this section.
- `MemoryError` — reachable on a pathologically large entrypoint.

`KeyboardInterrupt` and `SystemExit` are not caught (they are not `Exception` subclasses and
are not in the tuple).

### 2.2 What the fallback does

It runs the existing text scan for every code — the same functions, same regexes, same
skip guards that ship today, with two deliberate corrections carried over from the
superseded plans so that the degraded path is not silently weaker than it needs to be:

1. **The literal re-check at `dsx/checks/code.py:532` is deleted.**
   `if "fit(" in line or "fit_transform" in line or "partial_fit" in line` exists only to
   undo `FIT_LEAK_MARKERS`' own `\s*` tolerance and is the whole of finding CR-03: today
   `model.fit (df)` before the split draws nothing while `scaler.fit_transform (df)` fires.
   This is superseded plan 01's fix, unchanged, applied to the fallback.

2. **`FIT_CALL_RE` is widened for keyword arguments and `_fit_call_arguments` switches from
   `search` to `finditer`.** This is superseded plan 02's CR-04 + WR-01, unchanged, applied
   to the fallback. The pattern becomes:

   ```
   FIT_CALL_RE = re.compile(
       r"\.(?:fit_transform|partial_fit|fit)\s*\(\s*(?:[A-Za-z_]\w*\s*=\s*)?"
       r"([A-Za-z_][\w.\[\]'\"]*)\s*[),]"
   )
   ```

   The capture group is the argument VALUE, never the keyword name — that is threat
   T-11.1.1-07 and it is the reason `model.fit(X=X_train)` must stay silent. The trailing
   `\s*[),]` still makes a call with no closing parenthesis fail to match rather than
   capture a truncated token (the T-11.1-02 degrade contract). `partial_fit` joins the
   alternation so the fallback's method set agrees with the AST path's.

   **Exactly one extraction path per mechanism survives.** No `search`-based variant remains
   beside the `finditer` one — superseded plan 02's prohibition 3, satisfied literally.

**Not carried over:** `_join_backslash_continuations`. The superseded plan's index-preserving
join was measured quadratic in its naive form (13.784 s for 40,000 continued lines against
0.0147 s for the list-accumulating form) and existed only to let a regex see across a
physical line break. The AST path handles explicit line joining natively; the fallback does
not handle it at all, and that is named in §8. Threat **T-11.1.1-02 (quadratic join) is
retired by never being written**, not by being fixed.

### 2.3 How the user is told which path ran

A blocking gate that quietly degrades to a weaker scan and still prints a pass is the exact
failure superseded plan 01 was written to close. The degraded path is signalled on **four
channels**, none of which needs a new DSX-CODE number (D-05/D-06 are not engaged):

1. **`report.ok(...)`, always, exactly one of two lines.** Either
   `entrypoint parsed with ast (call-level scan)` or
   `entrypoint NOT parsed — text-only fallback scan (syntax error at line N)`. This renders
   in the markdown report's `## Passed` section (`dsx/cli.py:665`) and in verbose terminal
   output (`dsx/findings.py:171`).

2. **Every finding carries `scan=` in its `data` dict.** Value `"ast"` or
   `"text-fallback"`. This is additive structured evidence, exactly like the existing
   `fit_line=` kwarg at `dsx/checks/code.py:227`, and it appears in `Finding.to_dict()`.

3. **Every finding emitted on the fallback path gets a sentence appended to its `detail`.**
   Verbatim: ` [scanned as text only: this entrypoint could not be parsed as Python (syntax error at line N), so the weaker text scan ran and may have missed leaks it cannot see].`
   This is the channel the brief requires — the finding itself tells the reader which path
   ran, in the default non-verbose output.

4. **Both decision records gain an `inputs` entry** `scan_path:ast` or
   `scan_path:text-fallback:line-N`. This is the durable channel: it lands in
   `DECISIONS.jsonl` and is replayable through `dsx explain`.

Channels 2 and 3 are applied by a single post-pass immediately before `check()` returns:

```
if degraded_note:  # frozen dataclass -> dataclasses.replace, order preserved
    report.findings[:] = [
        replace(f, detail=(f.detail + degraded_note).strip(),
                   data={**f.data, "scan": "text-fallback"})
        for f in report.findings
    ]
else:
    report.findings[:] = [replace(f, data={**f.data, "scan": "ast"}) for f in report.findings]
```

`Finding` is `@dataclass(frozen=True)` (`dsx/findings.py:49`), so `dataclasses.replace` is
required; a list-slice assignment preserves order, which the determinism guarantee depends
on. Doing this as a post-pass keeps all eight `report.add(...)` call sites untouched, which
matters because `scripts/gen-finding-catalogue.py` parses those call sites with its own
`ast` and requires the first three arguments to stay plain string literals
(`scripts/gen-finding-catalogue.py:133-145`).

**The three "Line N" substring assertions are unaffected** — they use `assertIn`, so an
appended suffix cannot break them, and their fixtures parse cleanly anyway.

**Note for the implementer, and it must be written into the test itself:**
`test_malformed_fit_calls_no_finding_no_exception` (`tests/test_dsx.py:4690`) feeds
`imputer.fit(df` with an unclosed parenthesis. `ast.parse` raises
`SyntaxError: '(' was never closed` on it, so that test is **already** the only committed
pin on the fallback path — it is not new coverage, and it must not be "fixed" to parse.
Annotate it explicitly or the next reader will mistake it for an AST test.

## 3. The AST walk

### 3.1 One walk, one call list

```
@dataclass(frozen=True)
class _CallSite:
    line: int          # ZERO-BASED physical line index (see §4)
    col: int           # node.col_offset, for source ordering only
    name: str          # resolved final callee name, "" when unresolved
    node: ast.Call
```

```
_call_sites(tree) -> tuple[_CallSite, ...]
```

Walks the tree **once**, collects every `ast.Call`, resolves its callee name, and returns
the tuple sorted by `(line, col)`.

Sorting is not optional. `ast.walk` is breadth-first and is **not** source-ordered. The
caller at `dsx/checks/code.py:252-258` takes the first qualifying token and `break`s, so
walk order would decide which token is reported. `(lineno, col_offset)` is a total order
over the call sites in one file, so the result is deterministic and stable across runs —
superseded plan 02 truth 6, satisfied.

Every consumer below reads this one tuple. Nothing re-walks. That is a correctness
requirement for §6 as much as a performance one.

### 3.2 Callee name resolution

| `node.func` shape | resolved `name` | example |
|---|---|---|
| `ast.Name` | `func.id` | `train_test_split(X, y)` → `train_test_split` |
| `ast.Attribute` | `func.attr` | `model.fit(df)` → `fit` |
| `ast.Attribute` over a `Call` | `func.attr` | `StandardScaler().fit_transform(X)` → `fit_transform` |
| `ast.Attribute` over a dotted path | `func.attr` | `sklearn.model_selection.train_test_split(...)` → `train_test_split` |
| anything else | `""` (unresolved) | `getattr(m, "fit")(df)`, `handlers["fit"](df)` |

Only the FINAL segment is used for matching. A dotted path is deliberately not required to
match in full, because `sklearn.model_selection.train_test_split(...)` and a bare
`train_test_split(...)` must be treated identically — the corpus fixture uses the first form
and `examples/analysis/leaky_model.py` the second.

A chained receiver is resolved for free: `StandardScaler().fit_transform(X)` is an outer
`Call` whose `func` is an `Attribute` whose `.value` is the inner `Call`. The outer call is
the fit call, its first argument is `X`, and the inner `StandardScaler()` call is a separate
`_CallSite` whose name is `StandardScaler` and which matches nothing. **Verified this
session against `examples/analysis/leaky_model.py`: `first_fit` resolves to 0-based index 6
with argument token `X`, matching today's finding exactly.**

Unresolved callees (`""`) match nothing and are named in §8.

### 3.3 Fit-call detection

```
FIT_METHOD_NAMES = frozenset({"fit", "fit_transform", "partial_fit"})
```

Identical to `FIT_LEAK_MARKERS`' method set, so the AST path and the fallback agree.

**`partial_fit` is included for `DSX-CODE-021`, not only `DSX-CODE-001`.** Today it is in
`FIT_LEAK_MARKERS` (`dsx/checks/code.py:35-39`) but absent from `FIT_CALL_RE`
(`dsx/checks/code.py:114-116`), so `model.partial_fit(data)` before the split already fires
001 while the same call after the split draws nothing. Holding the AST method set at
`{fit, fit_transform}` to preserve that asymmetry would mean deliberately writing a blind
spot into new code; superseded plan 03's own docstring protocol says the honest route is to
let it fire. There is no committed `stays_uncaught_by_design` test to promote — plan 03 was
never executed — so nothing is deleted by this choice. **`grep -rn "partial_fit" examples/
tests/` returns nothing, so no fixture can move.** The widening is announced in §9.

### 3.4 First-argument extraction

```
_first_argument(node: ast.Call) -> ast.AST | None
```

1. If `node.args` is non-empty and `node.args[0]` is **not** `ast.Starred`, return
   `node.args[0]`.
2. Otherwise return the value of the first keyword, in source order, whose `arg` is in

   ```
   FIT_FIRST_PARAM_NAMES = ("X", "x", "data", "df", "frame", "features")
   ```

   `arg is None` (a `**kwargs` splat) is skipped.
3. Otherwise return `None` — no token, no finding.

This handles `model.fit(X=data, y=target)` → `data`, `model.fit(data=data)` → `data`, and
`scaler.fit_transform(X=data[['Age']])` → `data[['Age']]`, which are superseded plan 02
truths 1 and 2 verbatim. It captures the argument **VALUE**, never the keyword name, so
`model.fit(X=X_train)` yields `X_train`, `_is_training_frame` returns True and no finding is
drawn — superseded plan 02 truth 3, the false-positive guard, threat T-11.1.1-07.

**An allowlist, not a blocklist, and that is a decision.** A blocklist ("any keyword except
`y`, `sample_weight`, `groups`") would report the value of an unrelated keyword as "the
frame this was fitted on", which is precisely the false-positive flood T-11.1.1-07 names —
"as damaging to a blocking gate as a blind spot, and faster to erode trust". The allowlist
costs a false negative on `model.fit(training_frame=data)`, which is pinnable and is named
in §8. `ast.Starred` first arguments (`model.fit(*args)`) are likewise a named miss.

### 3.5 Token rendering

```
_render_token(node) -> str:  return ast.unparse(node)
```

**`ast.unparse`, one rendering path, no `ast.get_source_segment`.** Reasons:

- `_is_training_frame` (`dsx/checks/code.py:579-583`) PREFIX-matches the token against
  `TRAINING_FRAME_NAMES`. The leading identifier is never quoted, so unparse's
  normalisations cannot change any membership verdict.
- `ast.get_source_segment` needs the original source threaded through every helper, returns
  `None` when position info is incomplete, and reproduces a multi-line argument as
  multi-line text that would then be pasted into a single-line `detail` string.
- unparse collapses a multi-line argument to one line, which is what a `detail` field wants.

**Verified this session:** `ast.unparse` of the corpus fixture's fit argument returns
`data[['Age']]` — byte-identical to the token in today's `DSX-CODE-021` detail string, which
is why `tests/test_known_bad_corpus.py`'s expectation does not move.

**Stated normalisation, because it is user-visible:** unparse renders string literals with
single quotes. A source token written `data[["Age"]]` is reported as `data[['Age']]`. The
verdict is unaffected (prefix match on `data`); only the quoted `detail` text differs from
the source. This is the one place the AST path's output text is not byte-identical to the
source, and it is named in §9.

### 3.6 Split-marker detection as calls

```
SPLIT_CALL_NAMES = frozenset({
    "train_test_split", "TimeSeriesSplit", "GroupKFold", "StratifiedKFold",
    "StratifiedGroupKFold", "KFold", "ShuffleSplit", "GroupShuffleSplit",
})
```

`first_split` on the AST path is the lowest `line` among call sites whose resolved `name` is
in that set. The module-level `SPLIT_MARKERS` tuple (`dsx/checks/code.py:23-33`) is left
untouched — it is the fallback's detector — and the new frozenset is its call-name
equivalent, deduplicated (`TimeSeriesSplit` appears twice there, `KFold(` and
`TimeSeriesSplit(` carry parentheses that a name set does not need).

**An import can never be mistaken for a split, structurally.** `ast.ImportFrom` and
`ast.Import` are not `ast.Call` nodes, so they are never collected. Today the same outcome
depends on the explicit `re.match(r"^(from|import)\b", stripped)` guard at
`dsx/checks/code.py:511`, and it is load-bearing: `examples/analysis/leaky_model.py` imports
`train_test_split` on line 4 and calls it on line 8, and `DSX-CODE-001` fires only because
`first_split` is the call's index (7, zero-based), not the import's (3). **Verified this
session: the AST detector returns 7 on that file — unchanged.**

**A string literal stops counting as a split.** Today `s = "train_test_split"` on line 1
silences `DSX-CODE-001` because the detector is a substring scan. Under AST it is a
`Constant`, not a `Call`, so the file has no split and 001 (and possibly 010) fires instead.
This makes the gate stricter and is announced in §9.

### 3.7 The prose mask — how the docstring false positive is closed for the text checks

`DSX-CODE-001`'s docstring false positive is closed structurally: a module docstring reading
`"""We never call scaler.fit(X) on the full frame."""` contains no `Call` node at all, so
there is nothing for the fit walk to find. Reproduced, and reproduced in the control
direction: deleting that one sentence makes the identical file pass today.

The checks that STAY-TEXT (§5) have the same defect and no such structural cure, so the walk
also produces:

```
_prose_line_indices(tree) -> frozenset[int]   # ZERO-BASED
```

- **Rule A** — for every `ast.Expr` whose `.value` is a `str` `ast.Constant`: mask
  `lineno-1 .. end_lineno-1` inclusive. This is every docstring (module, class, function)
  and every bare string statement.
- **Rule B** — for every `str` `ast.Constant` with `end_lineno > lineno`: mask
  `lineno .. end_lineno-1` — the INTERIOR and closing lines of a multi-line string, not its
  opening line.

Rule B deliberately spares the opening line, because that line can carry real code
(`sql = """`). Rule A is safe to mask in full because an expression statement that is only a
string is only prose.

**Why Rule B is not "mask every line any string touches":** the line
`df['Age'] = df['Age'].fillna(df['Age'].mean())` contains three single-line `str` Constants.
A naive mask would hide it and delete `DSX-CODE-020` outright — including on the corpus
fixture. Only whole-line prose is masked.

Every primary-path text scan skips masked lines: `DSX-CODE-002`, `DSX-CODE-003`,
`DSX-CODE-020`'s predicate loop, and `DSX-CODE-030/031`'s target-reference window. On the
fallback path the mask is empty, so the fallback keeps the docstring false positive — stated
plainly in §8, because that is the honest description of a degraded path.

### 3.8 Comment guard for `DSX-CODE-002` and `DSX-CODE-003`

Measured today: `# StandardScaler().fit_transform(X)` fires `DSX-CODE-002` HIGH, and
`# never use SMOTE before the split` fires `DSX-CODE-003` HIGH. The two inline loops at

## 4. Line-number mapping

`ast` node positions are **1-based**. `dsx/checks/code.py` is **0-based** throughout:
`_first_line_matching` returns an index into `lines`, `first_fit < first_split` compares two
such indices, `f"Line {index + 1}"` renders them, `lines[cleaning_index]` dereferences one,
and `fit_line=first_fit + 1` (`dsx/checks/code.py:227`) re-derives the 1-based value from
it.

**The rule: conversion happens once, at construction of `_CallSite`, and nowhere else.**

```
line = node.lineno - 1
```

`_CallSite.line`, `_prose_line_indices`, and every AST-derived helper return **0-based
physical indices**. `check()`'s body is arithmetically unchanged — `first_fit < first_split`
keeps meaning what it says, `Line {index + 1}` stays honest, and `lines[index]` still
dereferences the right line.

This is superseded plan 01's Decision 1 restated for the new mechanism, and it is the single
most dangerous carry-forward in the phase: an unconverted `node.lineno` would shift every
comparison and every printed line number by one, silently, in the same direction, so nothing
would look obviously wrong.

**`Call.lineno` is the physical line where the call expression begins.** For a statement
spanning several lines the reported line therefore moves EARLIER, never later, relative to a
per-line scan that would find the token on a later line — so `first_fit < first_split` can
only become more true and no existing finding can become a miss (superseded plan 01
Decision 1, threat T-11.1.1-05, accepted low). **Verified this session:** 20,000 backslash-
continued `model.fit \` / `(df)` pairs produce 20,000 `Call` nodes whose last `lineno` is
39999 — the physical line of `model.fit`, not of `(df)`.

**Detail text still quotes `lines[index]`, never `ast.unparse` of the statement.**
`DSX-CODE-020` and `DSX-CODE-030` render `lines[index].strip()[:120]` verbatim
(`dsx/checks/code.py:240, 352`). That must not change to an unparsed rendering or the corpus
fixture's detail string changes. The only place unparse output reaches a user is
`DSX-CODE-021`'s argument token (§3.5).

**All four committed line numbers on the corpus fixture reproduce exactly under this
mapping. Verified this session against `examples/known-bad/full-frame-cleaning-entrypoint.py`:**

| what | today | AST, after conversion |
|---|---|---|
| `first_split` | 0-based 42 → "line 43" | 0-based 42 |
| `DSX-CODE-020` cleaning line | "Line 26" | (text path, unchanged) |
| `DSX-CODE-021` fit line + token | "Line 51", `data[['Age']]` | 0-based 50, `data[['Age']]` |
| `DSX-CODE-030` stat-test line | "Line 38" | 0-based 37 |

The `train_test_split` call opens on line 43 and closes on line 45; `Call.lineno` is 43.

## 6. Performance

### 6.1 What replaces the quadratic-join concern

Superseded threat **T-11.1.1-02** (high, denial of service — quadratic string accumulation
in `_join_backslash_continuations`, measured 13.784 s for 40,000 continued lines against
0.0147 s for the linear form) is **retired by never writing the helper**. `ast.parse`
performs explicit line joining itself.

Superseded threat **T-11.1-01** (high, denial of service — catastrophic regular-expression
backtracking) is **narrowed, not retired.** It is structurally closed for whatever the AST
path replaces, because parsing is linear and does not backtrack. It stays open for:

- every pattern reachable on the **fallback** path — `FIT_LEAK_MARKERS`,
  `PIPELINE_FIT_TRAIN_RE`, `FIT_CALL_RE` (now widened), `STAT_TEST_CALL_RE`,
  `_IMPUTE_*`/`_SPREAD_*`, `SCALER_FULL_RE`, `RESAMPLE_BEFORE_RE`;
- every pattern that STAY-TEXT keeps on the **primary** path — `SCALER_FULL_RE`,
  `RESAMPLE_BEFORE_RE`, `_IMPUTE_*`/`_SPREAD_*`, and the per-target `reference_re` built
  fresh inside `_stat_test_lines_referencing`.

The fallback is reachable precisely when the input fails to parse, which an adversary
controls trivially. **No size cap or line cap is introduced** — a cap would silently stop
scanning large files, which is a worse failure for a blocking gate than a slow scan. The
mitigation is measurement: every pattern above carries, or gains, a committed timing test on
non-matching input (§10). Two exist already (`FIT_CALL_RE`, the two full-frame predicates);
`SCALER_FULL_RE`, `RESAMPLE_BEFORE_RE`, `PIPELINE_FIT_TRAIN_RE` and `FIT_LEAK_MARKERS` do
not and must gain one.

### 6.2 The bound, and how it is measured

`ast.parse` + `ast.walk` are linear in **node count**, not character count. That distinction
is load-bearing and is the honest headline: 2,000,000 characters inside a single string
literal parse and walk in **0.008 s**, while 3,000,000 characters of dense call syntax take
**2.7 s**. Cost tracks roughly 1.1 microseconds per call node.

**Uncommitted session-time measurements, CPython 3.12.10, this machine, taken while writing
this design.** Full pipeline means `ast.parse` + `ast.walk` + sort + `ast.unparse` of every
fit argument — i.e. everything §3 does.

| input | measurement |
|---|---|
| 5,000 lines of `model.fit(df)` | **0.067 s** full pipeline |
| 20,000 lines of `model.fit(df)` | **0.305 s** full pipeline |
| 40,000 lines of `model.fit(df)` | **0.795 s** full pipeline |
| 40,000 physical lines of backslash-continued `model.fit \` / `(df)` | 0.153 s parse; last `Call.lineno` = 39999 |
| 12,500 → 200,000 semicolon-joined calls on ONE line | 0.155 / 0.318 / 0.882 / 1.254 / 2.699 s parse+walk — **roughly 2× per doubling, i.e. linear** |
| 2,000,000 characters in one string literal | 0.008 s parse, ~0.000 s walk |
| chain of 4,000 binary operators | **`RecursionError` in ~0.03 s** — see §2.1 |

**Two honest consequences, stated rather than buried:**

1. The superseded plans' bar — "40,000 continued lines in under one second" — is met
   (0.795 s full pipeline at 40,000 lines), but with less headroom than the regex path had.
2. On the one input where the regex path was measured fastest — 200,000 semicolon-joined
   fit calls on a single 3,000,000-character line, `finditer` at 0.078 s — the AST path
   takes **2.7 s and exceeds the 1.0 s house budget.** It is linear, not catastrophic, but
   it is roughly 35× slower on that shape. This is a real cost of the mechanism change and
   is not presented as a wash.

**The committed timing test therefore pins a size the design can actually hold, and the
larger figures live in this table as evidence of linearity rather than as assertions.**
House shape, ascending sizes, **no `subTest`** (a super-linear regression must abort at the
small size rather than hang the suite at the large one):

```
for size, budget in ((5_000, 0.5), (20_000, 1.0)):
```

against measured 0.067 s and 0.305 s — between 3× and 7× headroom. The test's real subject
is **our** code, not CPython's parser: it is the regression guard against re-walking the
tree once per code, rendering tokens for every call instead of only fit calls, or any
accidental quadratic in the call-site assembly. §3.1's "one walk, one call list, every
consumer reads it" is a performance requirement as much as a correctness one.

**Rule carried forward verbatim from `11.1.1-RESEARCH.md` Pitfall 6:** a sibling's proven
linearity is not admissible evidence for a new or widened pattern. The widened `FIT_CALL_RE`
in §2.2 must be re-measured on non-matching input during implementation, not inherited from
superseded plan 02's 0.0008 s figure.

## 8. What remains uncaught

Nothing in this design makes any DSX-CODE sound, complete, reliable or exhaustive. A clean
scan is not proof that no leak exists. The following are **real leaks the scanner does not
see**, listed so that a reader can match them against their own code.

**Uncaught because the callee cannot be resolved to a name**

1. Dynamic dispatch — `getattr(model, "fit")(data)`, `handlers["fit"](data)`.
2. A bound method held in a variable — `f = model.fit` on one line, `f(data)` on another.
3. A fit performed inside a helper the entrypoint calls — only the declared entrypoint file
   is scanned; imported modules are not.
4. A split performed by a helper, an alias, or by slicing (`train = df[:800]`) — none is a
   call to a name in `SPLIT_CALL_NAMES`, so the file reads as having no split.

**Uncaught because of the argument rule**

5. A keyword whose name is outside `FIT_FIRST_PARAM_NAMES` — `model.fit(training_frame=data)`
   draws nothing. Deliberate: an allowlist trades this miss for immunity from a
   false-positive flood (§3.4).
6. A starred first argument — `model.fit(*args)`.
7. A full frame laundered through a training-frame-shaped name — `X_train_like = data;
   model.fit(X_train_like)` passes, because `_is_training_frame` prefix-matches on the name
   and never follows the assignment.

**Uncaught because the file did not parse (the fallback path)**

8. **Everything the regex era missed, plus the docstring false positive, comes back on any
   entrypoint that fails to parse.** The fallback is a per-physical-line text scan: it
   cannot see across a newline (multi-line calls), does not resolve chained-call arguments,
   and still blocks CRITICAL on prose that mentions `scaler.fit(X)` inside a docstring or a
   comment. This is stated, signalled on four channels (§2.3) and **not** narrowed further
   in this phase.
9. Notebooks reach the fallback more often than `.py` files do. Magics and shell escapes are
   repaired (§1.3); `?`/`??` introspection lines are not, and a notebook using them parses
   nowhere.
10. Backslash line continuation is caught on the AST path and **not** on the fallback path —
    the joining helper was deliberately not written (§2.2).

**Uncaught or imprecise by design in the checks that stay on text**

11. `DSX-CODE-002`'s prior-frame guard is a raw substring scan: a line reading
    `x_trainer = 1` anywhere above the scaler call suppresses the finding. Retained
    deliberately (§5).
12. `DSX-CODE-003` fires on a name mention with no call anywhere — a bare
    `from imblearn.over_sampling import SMOTE` is a HIGH finding. Intended, not a bug.
13. `DSX-CODE-020`'s co-occurrence is per-LINE. A `fillna` whose `.mean()` sits on the next
    physical line is missed. The AST widening to per-STATEMENT was considered and **not**
    taken.
14. `DSX-CODE-030/031` are a proximity heuristic. A target reference four or more lines above
    the statistical-test call is missed; an unrelated reference within three lines fires.
15. `DSX-CODE-020`'s prose mask spares the opening line of a multi-line string and does not
    mask a single-line string literal assigned to a variable — a cleaning idiom written
    inside `sql = "…fillna…mean()…"` on one line still fires.

**Uncaught because the gate does not run the code**

16. Anything that exists only at runtime — `exec`/`eval`'d source, generated code, a frame
    mutated between the split and the fit.

**Coordinate-space caveat**

17. For a `.ipynb`, `Line N` indexes the reconstructed cell concatenation, not any file the
    user can open at that offset. This design preserves that numbering exactly rather than
    fixing it, and does not claim to fix it.

## 9. Behaviour changes to announce

The announcement venue is **`README.md`** — beside `### Migrating a pre-v2.0.0 spec`
(`README.md:135`) and inside `## Known limits` (`README.md:309`). No `CHANGELOG.md` exists

silently gets stricter costs its users trust they do not get back.

**Two superseded README sentences plan 03 mandated become FALSE and must be REWRITTEN, not
carried:** its Section B item 1 ("the check reads the entrypoint as text, one line at a time,
and is not a Python parser — that single fact explains every limitation below it") and item 5
("closing all three needs a parser-based scan rather than more text patterns, and this change
deliberately did not attempt one"). Its Section A item 4, announcing the
`DSX-CODE-001`/`021` continuation asymmetry, describes an asymmetry this change retires.

**The announcement now runs in BOTH directions, which plan 03's did not.**

*Stricter — files that pass today start failing. Every one of these is a TRUE POSITIVE: the
leak was always there and the scan could not see it.*

- whitespace or a tab before the parenthesis — `model.fit (df)`, `model.fit\t(df)`
- a fit call split across physical lines by a backslash or by an open parenthesis
- a keyword-argument fit — `model.fit(X=data, y=target)`, `model.fit(data=data)`
- a second fit call on a semicolon-joined line — `imputer.fit(X_train); scaler.fit_transform(data)`
- a chained-call argument — `model.fit(loader.get_full_frame())`
- `model.partial_fit(data)` after the split (before the split it already fired)
- a file whose only "split marker" is a string literal or a comment now reads as having no
  split, so `DSX-CODE-001` and `DSX-CODE-010` can fire where `DSX-CODE-021` used to
- a `SMOTE`/scaler mention in a comment stops firing (looser) while the same call in code is
  unaffected

*Looser — files that are blocked today start passing. This is the more dangerous direction
to leave unannounced, because nobody files a bug about a gate that stopped complaining.*

- a module, class or function **docstring** that merely mentions `scaler.fit(X)` no longer
  blocks CRITICAL. Reproduced with a control: deleting that one sentence makes the identical
  code pass today.
- a `.ipynb` whose **markdown** cell describes leakage no longer blocks CRITICAL. Notebook
  line numbers are unchanged by the fix.
- a comment mentioning `SMOTE` or `StandardScaler().fit_transform` no longer draws
  `DSX-CODE-003`/`DSX-CODE-002`.

*Cosmetic*

- a `DSX-CODE-021` token written with double quotes is reported with single quotes
  (`data[["Age"]]` → `data[['Age']]`). The verdict is unaffected.

*Degraded scans are now visible*

- an entrypoint that cannot be parsed is scanned by the weaker text path, and every finding
  says so in its detail, plus a `## Passed` line and a decision-record input.

**A new `## Known limits` subsection is required**, replacing plan 03's promised
"What the fit-before-split scan does not catch" with content re-derived from §8 — not copied

## 11. Left open for the orchestrator

These are calls this design deliberately does not make on its own authority.

1. **Success-criteria wording.** ROADMAP SC1 names "backslash line continuation" and SC3
   names "a semicolon-joined line carrying two fit calls" — both are mechanism-shaped
   phrasings that no longer describe anything the primary path distinguishes; the AST walk
   satisfies both by construction. Restate them as behavioural outcomes, or leave them and
   let the plan record that they are satisfied a fortiori.
2. **The phase's headline number.** The committed 6/13 table is function-level against
   `FIT_CALL_RE` only and structurally excludes the `DSX-CODE-001` whitespace defect. A
   like-for-like after figure needs a NEW committed end-to-end table (fixture in → exit code
   plus finding codes out). Recommendation: commit one, and retire the function-level table
   as the basis for the phase's number rather than putting the two side by side.
3. **Requirement IDs.** ROADMAP says "Requirements: None new". The false-positive fixes
   (docstrings, markdown cells, comments) are user-visible behaviour the "remediation of
   detection-coverage gaps" framing did not contemplate. D-05/D-06 are not engaged (no new
   `DSX-CODE-*`), but whether the false-positive fix earns a requirement ID is a call to make
   explicitly, not by default.
4. **Where the reversal is recorded.** The instruction that excluded AST ("Do NOT propose a
   rewrite of the check architecture") exists in no committed file — only as a quotation
   inside `11.1.1-RESEARCH.md:79`, sourced from an uncommitted spawn-time prompt. There may
   be no D-NN or M-NN to file a REV-NNN against; this may belong in the phase record and the
   ROADMAP rather than in `REVERSALS.md`. Filing an empty or misdirected reversal is what the
   SELF-001 convention exists to catch.
5. **Wave structure.** Waves 1 and 2 existed because `DSX-CODE-001` and `DSX-CODE-021` lived
   at two disjoint code sites needing separate git attribution. One shared walk removes that
   rationale, and the ROADMAP's "CR-04 and WR-01 must be fixed together" constraint is
   satisfied a fortiori. Wave 3's rationale (documentation describes shipped behaviour; the
   `06ff2d7` diff assertion is phase-level) is unchanged. The notebook reader touches a
   different function and a different failure class and may warrant its own plan.
6. **Scope cut, if one is needed.** The two items most separable from the core are the
   comment guard for `DSX-CODE-002`/`003` (§3.8) and the fallback hardening (§2.2 items 1
   and 2). Cutting either leaves the phase coherent; cutting the fallback hardening means
   SC1/SC2/SC3 are met on the parsed path only, and §8 must say so.
7. **Two human-check judgement calls**, answered at `/gsd-verify-work` because
   `workflow.human_verify_mode` is `end-of-phase`: is the §9 announcement adequate, and does
   any shipped sentence present `DSX-CODE-021` as sound?
