<objective>
Make DSX-CODE-021 see the two argument shapes it is blind to today: a keyword-argument fit
call (finding CR-04) and the second and later fit calls on one physical line (finding
WR-01). These land together, in one plan, one wave and one source commit, because the
ROADMAP requires it — both live in the same first-argument extraction logic and both make
the same check fire more often, so they are one behaviour change and are tested as one.

Purpose: `FIT_CALL_RE` requires the first character after the opening parenthesis to open
the captured token. A keyword form puts an identifier and an equals sign there instead, so
the whole match attempt fails and the call is reported as absent rather than as
unrecognised. Separately, `_fit_call_arguments` extracts only the first match per line, so
a safe call followed by a leaky one on the same line hides the leak completely. Both
failures are silent, and both end with the gate printing an affirmative pass line over a
file that leaks. These are ROADMAP success criteria 2 and 3.

Output: `dsx/checks/code.py` with `FIT_CALL_RE` widened by one bounded optional group and
`_fit_call_arguments` extracting every match per line; regression tests in
`tests/test_dsx.py::TestPhase11_1Code` covering the keyword forms, the keyword
training-frame negative, the semicolon-joined ordering case, the preserved degrade
contract, and a timing bound measured against the widened pattern rather than inherited
from a sibling.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired on this phase with `kind: pluralization` — a second
thing appears where there was one. It is right, and the noun it points at is concrete.

**The noun that is now primary:** *the fit-call argument tokens on a line* — plural. Today
`_fit_call_arguments` already returns a list, but it can only ever put one token per line
into it, so the plural type is a lie the singular implementation tells. After this plan the
type and the behaviour agree.

**Decision: promote.** The all-matches form replaces the single-match form in place. The
single extraction call inside `_fit_call_arguments` becomes an all-matches loop; no second
"get every match" helper is added beside a still-primary single-match one, and no
single-match helper is left behind.

**Rationale, in one line:** adding alongside would leave a working single-match path in the
file, and the next caller that reaches for it reintroduces exactly the bug SC3 closes —
and it would read as ordinary code, not as a regression, so nothing would catch it.

**Invariant that encodes the generalized intent** (implemented in task 1, not merely
suggested): `test_fit_call_arguments_extracts_every_call_on_a_line` asserts that a line
carrying three fit calls yields three tokens in source order. A future change back to
single-match extraction turns that test red on the count, which is the signal that the
plural assumption was silently re-narrowed. Task 2's acceptance criteria add a source-level
guard: no single-match extraction call on this pattern survives anywhere in
`dsx/checks/code.py`.

This checkpoint is advisory. It records a decision; it does not block the phase.
</assumption_delta_decision>
