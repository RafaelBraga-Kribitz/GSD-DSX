<objective>
Restore DSX-CODE-001's whitespace tolerance (finding CR-03) and extend it to backslash
line continuation, so a fit-before-split leak is caught whatever whitespace the author
put between `.fit` and its opening parenthesis.

Purpose: `_first_fit_leak_line` re-checks a hardcoded literal substring after the regex
has already matched, and that literal check is stricter than the regex it gates. It
silently defeats the whitespace tolerance the regex declares. A generated pipeline that
writes `model.fit (df)` before the split passes the gate today with an affirmative "OK"
line — the worst possible failure for a blocking gate, because it looks like a pass.
There is no safety net behind it: DSX-CODE-021 only fires at or after the split, so a
leak before the split is skipped by construction. This is ROADMAP success criterion 1.

Output: `dsx/checks/code.py` with the redundant literal re-check removed and a new
`_join_backslash_continuations` helper wired into `_first_fit_leak_line` only; a group of
regression tests in `tests/test_dsx.py::TestPhase11_1Code` covering every whitespace
variant, the backslash-continuation variant, the empty and adjacency edges, and the
join's linear scan time.
</objective>

<decisions_settled_here>
The researcher left two questions open and asked the plan to decide both. Both are
decided here, with the reason, so no executor has to guess.

**Decision 1 — reported line numbers stay in original physical-line space.**
`_join_backslash_continuations` is *index-preserving*: the list it returns has exactly
the same length as the list it was given. A continued statement's joined text is folded
onto the index of the statement's **first** physical line, and every physical line the
statement consumed after that becomes an empty string. Empty strings match nothing and
are skipped by every existing guard, so they are inert.

Why: `check()` compares `first_fit` (from the joined view) against `first_split` (from
the original unjoined view, computed by `_first_line_matching`). If the join shortened
the list, those two indices would live in different coordinate spaces and the comparison
would quietly stop meaning anything. Preserving length keeps one coordinate space and
keeps every `f"Line {index + 1}"` in the module honest. This matches the researcher's
recommendation (preserve the original physical line number) and implements it in the way
that also protects the split comparison.

One consequence, stated rather than discovered later: for a statement like an assignment
whose right-hand side is continued onto the next line, where the `.fit` token itself sits
on the continuation line, the reported line moves **earlier** — from the line carrying
`.fit` to the first line of the statement. Verified during planning against eleven
concrete cases. The movement is always earlier, never later, so it can never turn an
existing finding into a miss: `first_fit` can only get smaller, and smaller makes
`first_fit < first_split` more likely to hold, not less. This is announced in plan 03.

**Decision 2 — the join is scoped to `_first_fit_leak_line` only.**
`_fit_call_arguments` (DSX-CODE-021) and `_first_full_frame_cleaning_line`
(DSX-CODE-020) keep operating on unjoined physical lines.

Why: ROADMAP success criterion 1 names backslash line continuation for DSX-CODE-001 and
nothing else; criterion 2 scopes itself explicitly to the keyword-argument class. The
resulting asymmetry is real and must be written down rather than left to be discovered:
a backslash-continued fit call **before** the split is caught by DSX-CODE-001 after this
plan, while the identical construction **after** the split stays invisible to
DSX-CODE-021. That asymmetry is recorded in the source comment written in task 2 and
announced to users in plan 03. This matches the researcher's recommendation, including
the instruction to document the asymmetry rather than silently have one.
</decisions_settled_here>

    - Signature `_join_backslash_continuations(lines: list[str]) -> list[str]`.
    - **Index-preserving.** The returned list has exactly the same length as the input. A
      continued statement's joined text is written at the index of the statement's first
      physical line; every physical line the statement consumed after that becomes the empty
      string. Empty strings match no pattern and pass every existing guard untouched, so
      they are inert.
    - **Linear in total characters.** Accumulate the fragments of one logical line into a
      list and join that list once, when the statement closes. Do NOT build the logical line
      by repeatedly concatenating onto an accumulator string — that is quadratic and was
      measured during planning at 13.784 seconds for 40,000 continued lines, against 0.0147
      seconds for the list-and-join form. This is not a style preference: an entrypoint file
      is untrusted, unbounded input to a blocking gate, and a quadratic preprocessing pass
      over it reopens exactly the denial-of-service class that threat T-11.1-01 exists to
      keep closed.
    - **Continuation test:** a physical line continues the next one when its right-stripped
      form ends in an odd number of backslash characters. An even number is an escaped
      backslash inside a string literal, not a continuation.
    - **Comment lines never continue.** A line whose stripped form begins with a hash never
      opens a continuation, matching Python's own rule that explicit line joining does not
      apply inside a comment. Without this, a comment that happens to end in a backslash
      would swallow the executable line beneath it and hide a real leak.
    - **Unterminated tail:** if the final physical line opens a continuation that never
      closes, flush the accumulated fragments at the statement's first index rather than
      dropping them or raising.
    - Join fragments with a single space, and strip the trailing backslash plus surrounding
      whitespace from each fragment before joining. Never re-insert a line terminator: every
      string here arrived from `source.splitlines()` and is already terminator-free, and
      adding a carriage-return or newline back would break the terminator-free invariant
      every pattern in this module relies on.

    Then make `_first_fit_leak_line` call the helper on its `lines` argument once, at the
    top, and iterate the joined result. `check()` is not modified at all — it still passes
    the original `lines`, and because the join is index-preserving the index that comes back
    is still comparable against `first_split`, which is derived from the original list.
