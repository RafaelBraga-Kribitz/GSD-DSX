<objective>
Close the honesty half of ROADMAP success criterion 2 and all of success criterion 4 for the
re-scoped, AST-based scanner: pin what the new mechanism still cannot see, prove the
properties the mechanism change puts at risk (determinism, line-index stability, the
performance bound, and the visibility of a degraded scan), announce a behaviour change that
now runs in BOTH directions, and reconcile the known-bad corpus by measurement rather than
by inheritance.

Purpose: plans 01 and 02 replace a line-ordered regular-expression scan with a Python `ast`
parse over call nodes, keeping the text scan as a fallback. That is a mechanism change under
an unchanged set of finding codes, which is the shape of change most likely to move a
verdict quietly. Three things go quiet by default. First, the uncaught set changes
completely — the regex era's three known gaps close and a different, longer set opens, so
copying the old honesty text forward would ship a false statement. Second, the change is
LOOSER as well as stricter, and the looser half is invisible to its victims. Third, the
mechanism introduces coordinate systems, an interpreter dependency and a degraded path that
no committed test currently constrains. This plan turns all three into shipped artefacts:
tests that fail if a knowingly-uncaught form silently starts being caught or a caught form
silently stops, a README a user actually reads, and a committed end-to-end table that is the
phase's number instead of a claim about it.

Output: an uncaught-by-design test block and a non-regression test block in
`tests/test_dsx.py::TestPhase11_1Code`; a committed end-to-end variant table driving a
data-driven test; timing pins for every pattern that survives and for the AST pipeline, run
on both interpreters; two new `README.md` sections; and a clean run of the full suite, the
known-bad corpus, the catalogue check, the capability validation and the phase gate, with
the numbers recorded as literal values.
