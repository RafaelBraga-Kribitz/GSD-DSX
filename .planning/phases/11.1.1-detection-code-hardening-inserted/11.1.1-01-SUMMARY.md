**Replaced DSX-CODE-001's line-ordered regex scan with a single `ast.parse` + `ast.walk` over the entrypoint (text-scan fallback retained), closing the whitespace/tab/backslash/multi-line detection gap and two measured prose false positives, while making a degraded or skipped scan impossible to mistake for a clean one.**

## Accomplishments

- `dsx/checks/code.py` now parses the entrypoint with `ast` first; the existing line-ordered
  text scan survives unchanged as the fallback for source that cannot be parsed.
- `DSX-CODE-001` (fit-before-split) is decided from `ast.Call` sites on the parsed path:
  whitespace, tabs, backslash continuation, and open-paren multi-line calls all fire; a module
  docstring or a notebook markdown cell merely mentioning a fit call no longer does.
- `_source_lines` replaces `str.splitlines()` as the one line axis every index in the module is
  expressed in, closing a desync bug against form-feed and Unicode line-separator characters.
- A degraded (unparseable) or skipped (unscannable/undeclared) scan is signalled on four
  channels — a pass line, per-finding `scan` data, a detail-string sentence, and a
  decision-record input — so it can never read as a clean parsed pass.
- `first_split` is the union of the AST split-call index and a prose-masked text-marker scan:
  an aliased or helper-wrapped split still counts; a split marker mentioned only inside a
  docstring no longer does.
- The DSX-CODE-002 quadratic (already over the house performance budget on the primary path)
  is fixed by hoisting a misplaced `break`, proven behaviour-preserving. `PIPELINE_FIT_TRAIN_RE`
  is made genuinely linear on its adversarial shape by bounding its repetition — the plan's own
  proposed unbounded-character-class fix was measured NOT to fix it.
- Full test suite: 837 tests OK (baseline 807 + 30 added). Known-bad corpus, finding catalogue,

## Decisions Made

- **PIPELINE_FIT_TRAIN_RE fix corrected relative to the plan's own design doc.** The design
  (`11.1.1-AST-DESIGN.md` §Decision 9) proposed replacing `.*` with an unbounded `[^)\n]*`,
  claiming this "makes it linear by construction." Measured this session: it does not. On the
  adversarial shape `"Pipeline(" * n + ").fit(X_trai"`, the unbounded swap is still quadratic
  (0.1357s at n=4,000, vs 0.1357s for the old `.*` pattern — no material improvement), because
  `re.search` still retries an O(remaining-length) scan for the single `)` from each of the n
  literal `"Pipeline("` starting positions when the overall match fails everywhere. Bounding the
  repetition to `[^)\n]{0,200}` is what actually caps each retry at O(1): measured 0.0048s at
  n=4,000 and 0.33s even at n=256,000. Implemented the bounded version; documented the
  discrepancy in a source comment above the pattern.
- **Notebook markdown false positive closes one task earlier than the plan's own task
  boundaries assumed.** Task 2's acceptance criteria expected
  `test_notebook_markdown_cell_mentioning_fit_draws_no_code_001` to still fail until task 4's AST
  walk. It passes already after task 2, because character-wise blanking removes the
  false-positive text from `lines` entirely — before either scanner (old regex or new AST) ever
  reads it. Strictly earlier coverage, not a bug; documented in the task 2 commit message.
- **The "multi-line open-paren is uncatchable by a per-line scan" framing does not hold for this
  specific implementation.** `model.fit(\n    df\n)` already fired `DSX-CODE-001` under the
  unmodified (pre-plan) regex scanner, because the substring `.fit(` is complete on the call's
  first physical line and the scanner never validates balanced parentheses. The pinning test
  (`test_fit_multiline_open_paren_before_split_fires_code_001`) is still correct and still
  fires both before and after this plan — it just isn't new coverage the way the plan's prose
  claimed. Documented for accuracy rather than silently absorbed.
- Kept `FIT_METHOD_NAMES` including `partial_fit` (per the design's §3.3 rationale) even though
  `first_fit`'s fallback counterpart, `FIT_LEAK_MARKERS`, already had it and `FIT_CALL_RE` (a
  different, `DSX-CODE-021`-only pattern owned by plan 02) still lacks it — no fixture references
  `partial_fit`, so nothing moved.
