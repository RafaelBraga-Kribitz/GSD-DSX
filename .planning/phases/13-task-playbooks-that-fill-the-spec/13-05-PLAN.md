<objective>
Certify the phase's centre-of-gravity scope bound (REQ-P13-06): Phase 13 mints ZERO new `DSX-*`
finding codes. The existing count invariant (`_EXPECTED_TOTAL = 256`) catches any pure addition, but
leaves a swap hole — a mint-one/drop-one that preserves cardinality passes it. So this plan rides
BOTH (D-07): (a) `gen-finding-catalogue.py --check` exit 0 + the count invariant stay green, AND
(b) a set-identity diff against a frozen Phase-12 code-set snapshot, asserting
`current_code_set == phase12_code_set`.

Purpose: a diff is a set comparison, strictly stronger than a count. Freezing a byte-copy of the
generated catalogue and comparing distinct-code SETS closes the cardinality-preserving laundering the
house style exists to block, and it does so CRLF-safely on a repo that checks out `\r\n`.

Output: a new frozen snapshot fixture `tests/fixtures/finding-codes-phase12.md` and an extension of the
existing D-18 invariant test `tests/test_finding_catalogue_invariant.py` with the set-identity diff.

Fixture-vs-extend decision (Claude's Discretion per 13-CONTEXT / D-07): EXTEND the existing
`tests/test_finding_catalogue_invariant.py` rather than author a new test file. Reason: it already
ships the CRLF-safe `_ROW_RE` row parser, `_CATALOGUE_PATH`, and `ROOT`, so the set-diff reuses the
exact same distinct-code parser as the count invariant — no parser drift between "how the count is
read" and "how the set is read" — and the D-18 count invariant (cardinality) and the D-07 set-identity
diff (membership) live co-located as one coherent catalogue contract. This is the stronger choice under
rigour > reliability.
</objective>
