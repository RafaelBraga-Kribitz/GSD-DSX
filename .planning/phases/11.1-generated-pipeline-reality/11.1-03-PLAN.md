<objective>
Catch leakage that manifests as evaluation rather than training: a statistical test computed over
the frame using the declared outcome column, whose result then decides which features survive.

Purpose: the existing scan is keyed entirely on fit-shaped calls. The reproduction's hypothesis
stage contains no fit call at all — it cross-tabulates a candidate feature against the outcome
column and runs a chi-square test, then appends the accepted hypotheses to the dataset for the
downstream stages. No fit-scan can see that, which is the requirement's own phrasing.

Output: a statistical-test marker family and a target-reference scan in `dsx/checks/code.py`, two
new finding codes, tests, a decision record, and a current finding catalogue.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| analyst entrypoint file to regex engine | The statistical-test pattern and the target-reference pattern both run over arbitrary analyst-authored text. |
| declared target column to regex construction | `model.target` is analyst-supplied text that is interpolated into a pattern. Unescaped, it is a pattern-injection surface. |
| repository fixtures to regression suite | The committed good and bad specs are what `scripts/check.sh` measures the gate contract against. |
