# Phase 11.1 Plan 08: Commit the Full-Frame-Cleaning Known-Bad Fixture and Catch Attribution Summary

**Committed the tenth known-bad corpus fixture — a reproduction of "The AI Data Scientist" (arXiv:2508.18113v1) whose full-frame cleaning, hypothesis test and post-split scaler above an honestly-declared training-only preprocessing boundary passed the gate with zero findings before this phase — extended the corpus harness so any fixture's declared entrypoint can now be resolved from a fresh temporary phase directory, and recorded the catch attribution (DSX-CODE-020/021/030 CRITICAL, DSX-ML-090 HIGH, all at `dsx gate execute`) with every ship-point CRITICAL/HIGH finding accounted for.**

## Accomplishments

- `tests/test_known_bad_corpus.py::_seed_entrypoint(tmp, spec_path)` added: copies a fixture's declared `reproducibility.entrypoint` into the temporary phase directory `_gate_findings` gates against, at every gate point (unconditional — the entrypoint check is registered at `execute` as well as `verify`/`ship`). The premise was measured before writing it: `dsx gate execute` against `examples/good-ANALYSIS-SPEC.yaml` with a fresh `tempfile.mkdtemp()` phase-dir fires `DSX-REP-031` ("declared entrypoint does not exist") and `code.check`'s own findings are empty — confirmed no fixture in the corpus declared an entrypoint before this plan (`grep -n entrypoint examples/known-bad/*.yaml` matches only prose comments), so the helper is a no-op for every pre-existing fixture.
- `_TARGET_DEFECT_CODES`'s type widened to accept a bare code string or a `frozenset` of several codes per gate-point key; `_own_target_codes` fixed to flatten a multi-code value into its individual codes (it previously collected the raw container) and to accept synthetic maps as parameters so the flattening is independently provable. A second bug of the identical shape was found and fixed in `_effective_target_map` while wiring the new fixture's real multi-code entry — its union step also assumed every point-value was a bare string.
- The full-frame-cleaning fixture triple committed: the entrypoint transcribes "The AI Data Scientist" (Akimov et al. 2025) Sections 2.1-2.3 in the paper's own stage order (full-frame mean imputation and a spread-based row filter, a chi-square hypothesis test against the target, a legitimate split, then a `StandardScaler` fitted on the full frame rather than `X_train`); the specification clones `validity_frame`/`inference`/`design`/`metrics`/`data`/`analysis` wholesale from `post-hoc-procedure-switch-ANALYSIS-SPEC.yaml` (already measured clean at plan/execute), renamed to a churn-retention narrative, with a deliberately non-cloned `inference:` block (see Key Decisions) and a new `model:` block declaring an honest `train_only` whole-pipeline boundary and no selection ledger.
- Catch attribution recorded: `_TARGET_DEFECT_CODES["full-frame-cleaning"] = {"execute": frozenset({DSX-CODE-020, DSX-CODE-021, DSX-CODE-030}), "ship": "DSX-ML-090"}`; `_EXPECTED_CAUGHT_DEFECTS["full-frame-cleaning"] = frozenset()` (empty by design — this fixture's codes fire at `execute` only, not both `plan` and `execute`, so the both-points map has nothing to claim). A dedicated positive-direction test, `test_full_frame_cleaning_fixture_blocks_execute_naming_its_three_codes`, proves the execute-block-plus-plan-clears shape directly against a real gate run.
- No `_INCIDENTAL_GAP_CODES` entry added: every CRITICAL/HIGH finding this fixture produces at ship (`DSX-CLM-031`, `DSX-COH-031`, `DSX-MET-040`, `DSX-NAR-001` beyond its own four codes) was already a documented corpus-completeness gap before this plan.
- `references/finding-codes.md` needed no regeneration — `python scripts/gen-finding-catalogue.py --check` reports the catalogue current both before and after this plan, because all four codes this fixture attributes (`DSX-CODE-020/021/030`, `DSX-ML-090`) already shipped in earlier Phase 11.1 plans (11.1-01, 11.1-03, 11.1-06).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — bug, directly caused by this task's own changes] `_effective_target_map`'s union step did not flatten a multi-code `_TARGET_DEFECT_CODES` value**
- **Found during:** Task 3, wiring `full-frame-cleaning`'s real `"execute": frozenset({...three codes...})` entry — the first entry in this corpus to actually exercise the multi-code shape task 1 enabled at the type-annotation level.
- **Issue:** `_effective_target_map`'s loop called `merged.setdefault(slug, {}).setdefault(point, set()).add(code)`, assuming `code` was always a bare string. For a frozenset value, this added the whole frozenset as one hashable-but-wrong element of the point's set, so the resulting `expected` frozenset (after `frozenset(codes)`) contained one nested frozenset instead of three flat code strings — `_classify_target_defect`'s `missing = expected - set(critical)` could never match, and the generic test failed with `expected` printing as `[frozenset({...})]`.
- **Fix:** Branch on `isinstance(code, str)`: add the bare string, or `.update(code)` for a container — the identical flattening `_own_target_codes` already performs, for the identical reason.
- **Files modified:** `tests/test_known_bad_corpus.py`
- **Commit:** `4fcb49e`

**2. [Rule 1 — ripple-effect test updates, directly caused by committing a tenth known-bad spec] `test_dsx.py`'s hard-coded spec count and `test_frame_val.py`'s fixture-matrix guard**
- **Found during:** Task 2, running `python -m unittest discover -s tests` after writing the fixture.
- **Issue:** `test_every_committed_spec_declares_a_valid_estimand_type` (`tests/test_dsx.py`) hard-codes the total committed-spec count (its own comment already anticipated a tenth spec: "a tenth spec added later inherits this assertion via glob"). `test_discovered_fixture_set_equals_the_expected_dictionarys_key_set` (`tests/test_frame_val.py`) requires every glob-discovered fixture to have a measured entry in `_EXPECTED_VAL_CODES`.
- **Fix:** Bumped the count 9 → 10; added `"full-frame-cleaning-ANALYSIS-SPEC.yaml": set()` to `_EXPECTED_VAL_CODES`, measured directly via `dsx.frame.val.check()` against the loaded fixture (empty — the cloned `validity_frame` block is clean).
- **Files modified:** `tests/test_dsx.py`, `tests/test_frame_val.py`
- **Commit:** `537ae63`
