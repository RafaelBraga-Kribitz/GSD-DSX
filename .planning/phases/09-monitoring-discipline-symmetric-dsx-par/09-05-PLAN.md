<objective>
Ship `DSX-PAR-002`: requiredness and symmetry for `inference.paradigm_justification`, and the
requiredness message for a missing `inference.paradigm`.

Purpose: `PARADIGM_JUSTIFICATIONS` already exists with all seven members, already carries the comment
that no description ranks one reason above another, and is already membership-validated by
`DSX-SPEC-085`. What is silent today is **absence** — `_validate_inference_shape`'s membership loop
skips blank values, so declaring no justification at all produces no finding. That gap is this code's
entire content.

The second half is the requiredness message for a missing paradigm. Plan 09-03 already closed the
undeclared-paradigm escape at `dsx gate plan` by having the undeclared case select both halves of the
pair. `DSX-PAR-002` adds the part that names the missing declaration explicitly, at HIGH, so the whole
escape story lives inside one family and the symmetry audit can enumerate every path in one place.

Purpose of the fourteen-case test: the failure mode brief D-12 names is that `team_convention` or
`vendor_constraint` quietly acquires a weaker-reason code path later and nothing catches it. The
comment in `dsx/spec.py` states the property; nothing enforces it. This plan makes it mechanical.

This plan runs in parallel with plan 09-04. It touches no file that plan touches, and `DSX-PAR-002`
does not fire on any fixture in the known-bad corpus or on either canonical fixture — all of them
declare a `paradigm_justification`.

Output: one private function inside the existing `dsx/frame/paradigm.py`, the last `_NOT_SHIPPED`
entry removed, a regenerated catalogue, and a fourteen-case symmetry proof.
</objective>

the same private-helper shape the monitoring check uses, and call it from `check()` before
`return report`.

Its logic is requiredness only, and the two cases are mutually exclusive by construction — one
requires a declared paradigm, the other requires a blank one — so at most one finding is ever emitted:

  - When `inference.paradigm` normalizes to a member of `PARADIGMS` and `inference.paradigm_justification`
    is blank or absent, emit `DSX-PAR-002` at severity `HIGH` with `where` naming
    `spec.inference.paradigm_justification`.
  - When `inference.paradigm` is blank or absent **and** `design.peeking_policy` normalizes to
    `uncontrolled_continuous`, emit `DSX-PAR-002` at `HIGH` with `where` naming
    `spec.inference.paradigm`.
  - Otherwise emit nothing.

Severity `HIGH` matches this code's nearest sibling `DSX-SPEC-085` and keeps a missing *justification*
from blocking `plan` the way a genuinely uncontrolled *design* does. Do not raise it to CRITICAL: the
undeclared-paradigm escape is already closed at `plan` by plan 09-03's union-selection rule, and
raising this code would make a missing justification as severe as an uncontrolled design.

Never test membership. `DSX-SPEC-085` owns membership and a committed test pins it at exactly three
findings on the canonical bad fixture; a `DSX-PAR-002` that re-checked membership would emit two codes
for one defect, and removing the row from `_INFERENCE_MEMBERSHIP` to avoid that would turn that test
red and silently narrow a shipped code. Do neither. Read `PARADIGM_JUSTIFICATIONS` only to list the
allowed reasons in the remedy text.

Write the remedy so no reason is ranked above another. List the seven allowed values by iterating the
vocabulary in sorted order and joining them — never a hand-written list, never a subset, never an
adjective distinguishing one from another. The failure mode brief D-12 names is that
`team_convention` or `vendor_constraint` quietly acquires a weaker-reason path later; a sorted join
over the live vocabulary makes that impossible to introduce by accident here. Write the detail text
so it says what the declaration is for — the justification is what makes an honest paradigm choice
cheaper to declare than a dishonest one — and does not imply the reason's quality is judged.

For the missing-paradigm case, write a remedy naming `inference.paradigm` and both members of
`PARADIGMS`, and add one sentence saying that with no paradigm declared every paradigm-conditional
check applies, so declaring one narrows the checks rather than adding to them. That sentence is what
keeps this finding from reading as a penalty for honesty, which is the brief-D-10 property the whole
family protects.

Build each title as a single f-string literal at the `report.add` call site — never a pre-assigned
variable — for the catalogue's abstract-syntax-tree extractor.

Give the function its own docstring carrying a `Citation:` line and a `Structural criterion:` line.
The catalogue resolves citations from the nearest enclosing function, so a citation on `check()` or on
the module will fail `scripts/gen-finding-catalogue.py --check` even though it is visibly present.
Cite Deng, Lu & Chen (2016), the same primary source the family already uses, for the proposition that
a decision procedure's realised error rate is paradigm-dependent — which is what makes an undeclared
or unjustified paradigm a real gap rather than a formality — and carry forward the same
unverified-locator flag shape the module already uses if no more precise locator is warranted. The
`Structural criterion:` line must state that this is a presence test over one field, that membership
is owned by `DSX-SPEC-085`, and that the check applies the identical path to every member of
`PARADIGM_JUSTIFICATIONS` and of `PARADIGMS` with no per-member branch.

Emit one `DecisionRecord` when a finding is emitted, using the existing
`report.context.setdefault("decisions", [])` idiom, with `layer="deterministic"`, empty `id` and

when the check emits no finding.
