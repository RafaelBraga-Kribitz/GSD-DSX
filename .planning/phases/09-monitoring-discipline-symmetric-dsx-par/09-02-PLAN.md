<objective>
Ship the two evidence artifacts that stand behind the pair's numbers: a real citation on the
function that produces `DSX-PAR-010`'s figures, and a seeded simulation that demonstrates
`DSX-PAR-011`'s two formulations behave differently.

paper. Leaving it that way while the new check citing it carries a full reference puts a visible
seam in the project's two-tier evidentiary story at exactly the place a v2.0.0 check depends on a
v1.5.0 computation (D-13). Separately, REQ-P9-07 needs proof that the prior-averaged bound and the
point-null formulation are different results — swapping them produces a test that passes at one
horizon and fails at another, which is the "implementation bug for a day" the brief warns about.

This plan is independent of every other Phase 9 plan. It touches no file any other plan touches and
introduces no symbol any other plan reads, so it runs in parallel with plan 09-01.

Output: an upgraded docstring with an honest unverified-locator flag, and a stdlib-only seeded
simulation that runs by default.
</objective>

  <action>
Create `tests/test_par_monitoring_simulation.py`. Standard library only: `unittest`, `random`,
`math`, `ast`, `pathlib`, `sys`. The repository has no `pyproject.toml`, `requirements.txt` or
`setup.py` anywhere, and `scripts/check.sh` runs the suite with nothing installed — introducing
`numpy` here would be the repository's first external dependency, in a project whose stated argument
is that a gate which breaks on a missing dependency is a gate that gets turned off.

Give the module a docstring stating: what it proves, that it is evidence and never gate logic, the
literal seed value, and the single command that runs it on its own.

Seed every random draw from one `random.Random(<a literal integer>)` instance. Never
`random.seed()`, never wall-clock time, never `os.urandom`. Budget the whole module under one second
— a few thousand trials per assertion. Resolution is not the goal; reproducibility and the direction
of the property are.

Write the module as one `unittest.TestCase` with these tests:

**Point-null / law-of-iterated-logarithm trend.** Simulate accumulating data under the null across a
fixed ladder of look counts, for instance 1, 2, 5, 10 and 20 looks, counting the fraction of trials
that ever cross a fixed nominal threshold. Assert the sequence of observed fractions is
non-decreasing across the ladder, and assert the last is strictly greater than the first. Do **not**
assert any fixed ceiling here, and say why in the test's docstring: under this formulation the
type-I error tends to one as the horizon grows, so a fixed number cannot be asserted and asserting
one would produce a test that passes at one horizon and fails at another.

**Prior-averaged `1/(K+1)` ceiling.** Simulate trials drawn from a mixture over the null and the
alternative with the prior odds the derivation assumes, stopping the first time the posterior odds
reach `K = 19`. Among the trials that stopped and rejected, compute the observed false-discovery
rate and assert it is at or below `1/(K+1)` plus a stated one-sided margin of three standard errors,
with the standard error computed from the number of rejecting trials. State the tolerance contract
in the test's docstring: this is a one-sided Monte Carlo bound with an explicit margin, never an
exact floating-point equality against a simulated statistic.

**Exact arithmetic on the bound.** Assert `1/(19+1)` equals `0.05`, `1/(24+1)` equals `0.04` and
`1/(15+1)` equals `0.0625` — the boundary at the `P(B>A) > 0.95` decision threshold and one step
either side of it. These are exact in binary64. Also assert `1/19` is greater than `1/(19+1)` and
that `round(1/19, 4)` equals `0.0526`, with a docstring sentence naming this as Ville's inequality's
different bound over a different conditioning event, never a rounding of the same number.

**Determinism.** Run one of the simulations twice from two freshly constructed generators seeded with
the same literal, and assert the two summary statistics are equal.

**Gate-path isolation.** Walk every `.py` file under `dsx/` with `ast`, and assert none of them
imports the top-level `tests` package or any submodule of it, absolute or relative. Location is the
enforcement mechanism for REQ-P9-07, and until this test exists nothing in the repository enforces
it — `tests/test_frame_boundary.py` only scans `dsx/frame/` and only forbids `dsx.checks`.

**Docstring evidence.** Assert `inflation_from_peeking.__doc__` contains a `Citation:` line, a
`Reference value:` line, the year 1969, the digital object identifier, and a statement that the
locator is unverified. This is the automated half of Task 1's acceptance.

Add a `# D-05: DSX-PAR-011` marker comment next to the prior-averaged ceiling test. The catalogue's
D-05 enforcement requires that marker to exist somewhere under `tests/` for the code, and this is
the test that proves the reference value.
