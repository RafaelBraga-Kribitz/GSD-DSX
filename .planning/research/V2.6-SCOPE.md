condition ("real phases produce `EDA.md` files that gates ignore"); the operator
promoted it by direction on 2026-09-06 (HQ-39, reversing HQ-38 of the same day)
because the portfolio work starting now should consume hash-bound numbers from day
one rather than generate the evidence first.

Phase 26 is SEED-001's deferred E-26: five downstream skills gain one named-input
read step so the artifact Phase 25 enriches is actually consumed. Its entry
condition ("`templates/EDA.md` stable across two real phases") is likewise
overridden by direction; the override is recorded on the seed.

**Half B — Backlog evidence (Phases 27–29).** The 2026-08-20 evaluation of *The AI
Data Scientist* (arXiv:2508.18113; record at `docs/literature/the-ai-data-scientist.md`)
left three positive ideas on `brief.md` §6.5 with D-13 entry conditions, each of
which asks for a **corpus case**: a known-bad fixture the current gate misses, whose
miss is attributable to one specific absent code. None of the three cases has ever

unmet by default. These phases build the cases and measure them. The honest outcome
is either "live miss → promote, mint, cite" or "already caught → record, no mint".
Both close the phase. The brief's D-13 rule is restated at the top of `LOOP-BRIEF.md`
because it is the one rule most at risk under schedule pressure.

**Phase 30** is the terminal calibration re-baseline every milestone since Phase 12

## 3. Phase content

### Phase 25 — Hermetic profile depth (SEED-002)

**Goal.** `dsx profile` produces, stdlib-only and hash-bound, the trust-core numbers
the explore protocol currently asks the agent to compute, so `EDA.md` copies them
("never invent profile numbers") and two runs of the protocol over one extract
carry identical numbers by construction.

**Produce (additive keys; existing keys and values byte-stable):**
- per numeric column: `min`, `q1`, `median`, `q3`, `max`, `mean`, `sd`, `n_zero`,
  `n_negative` (step 4a's five-number summary and the zeros/negatives count);
- per categorical column: `share_top1`, `share_top10`, `rare_share`, `n_singleton`
  (steps 4b/4e — the definitions the skill already states: rare = levels with
  fewer than 10 rows or under 0.1 %);
- time column: `rows_per_day {min, median, max}`, `first_period_ratio`,
  `last_period_ratio`, `share_at_hour_00` (steps 3/3a);
- a declared `--unit <column>`: `rows_per_unit {p50, p95, max}`,
  `largest_unit_share` (step 1a);
- a declared `--target <column>` (binary or 0/1): weekly table, `overall`,
  `weekly_range`, `verdict: stable | drifting` at the skill's ±20 % relative rule
  (step 4f).

**Do not produce:** null cross-tabs against the target (step 2 — target-informed on
the full frame; stays agent-side and split-first), the outlier taxonomy (4c —
needs categorical search and time windows; judgement-shaped), impossible pairs (4d —
needs invariants the analyst enumerates), robust recomputes of declared metrics
(4a second half — needs the metric definition). These are named exclusions with
reasons, not omissions.

**Definitions are declared and cited.** The quantile method must be named by its
Hyndman & Fan (1996) type — *Sample Quantiles in Statistical Packages*, The American
Statistician 50(4):361–365 — as the type `statistics.quantiles(method=…)` actually
implements, **verified at plan time against the Python documentation and the paper,
not assumed** (the stdlib docstring describes "exclusive"/"inclusive" behaviour
without naming a type number; the mapping is a plan-time fact to establish). `sd` is
the sample standard deviation (n−1). `share_at_hour_00` follows the skill's
definition. Each statistic gets a reference-value test on a hand-computed fixture CSV
committed under `tests/fixtures/`.

**Boundary (D-01/D-02, and the seed's own).** The profiler is a producer. No gate
reads a new key this phase; `dsx/checks/dq.py`, the assertion vocabulary and the gate
profiles are byte-unchanged; zero codes (276 → 276, re-measured). Growing the
assertion vocabulary so gates can compare, e.g., `max_skew` is a later, separate
decision with its own D-06 mint — explicitly out of scope here.

**Ripple.** `templates/DATA-PROFILE.yaml`, `references/data-quality-assertions.md`,
and the explore skill's steps 1a/3a/4a/4b/4e/4f say "copied from the profile" where
the profiler now supplies the number; the executor fragment's "never invent profile
numbers" rule is unchanged in wording and wider in reach. Installed copies re-synced.

**D-05 read burden:** 1 (Hyndman & Fan type identification).

### Phase 27 — Evidence case: a leak attributable only through feature origin (§6.5 item 7)

**Entry condition (brief, verbatim):** "The M5 corpus contains at least one case
whose target defect is attributable **only** through feature origin — no name pattern
matches, no fit call is visible, and no declaration contradicts."

**Build the case first.** A churn-style known-bad fixture whose entrypoint reads a
pre-joined warehouse extract in which one innocuously named column (e.g.
`account_health_index`) is recomputed nightly from activity that includes the
outcome window — so the column's value at training time is not the value that would
exist at the declared prediction moment. No name in `LEAKAGE_PATTERNS` matches; the
entrypoint contains no cleaning, no scaler, no test-sees-target idiom (it splits
temporally and fits a pipeline on the training fold, correctly); the spec declares
`preprocessing_fit_on: train_only`, a temporal split, a prediction-time definition,
a baseline the model beats, a complete selection ledger and a plausible score. Every
declaration is honest. Measured at plan/execute/verify/ship: the case must clear
every point at the default threshold, or block only on documented incidental
corpus-gap codes — that measurement is the entry-condition test.

**If it is a live miss — the declaration and the check.** Optional
`model.feature_provenance[]`, one row per feature or per source: `{feature, source,
available_at, derived_from}` where `available_at` is a declared moment on the same
closed vocabulary `model.prediction_time_definition` uses (or a declared ordering:
`before_prediction | at_prediction | after_prediction | unknown`). A declaration-only
check fires when a feature is declared `after_prediction` (CRITICAL) or `unknown`
without a waiver (HIGH); nothing is inferred from names or code. **This buys
attribution, not detection** — a spec that lies still passes (README's standing
"a frame that lies passes" limit) — which is exactly the brief's own framing of the
item.

**D-05 candidate (UNVERIFIED until the human read):** Kaufman, S., Rosset, S.,
Perlich, C. and Stitelman, O. (2012), *Leakage in Data Mining: Formulation,
Detection, and Avoidance*, ACM Transactions on Knowledge Discovery from Data
6(4), article 15 — the *legitimacy* condition: a feature is legitimate for a
prediction if it would be available at prediction time. The author list must be
confirmed at the locator (the 2011 KDD version and the 2012 TKDD version differ). The
existing `references/leakage-taxonomy.md` states the same rule in DSX's words;
the citation attaches the primary source to the code that enforces it.

**D-06.** Next free `DSX-ML-*` number from a live-measured catalogue. If the case is
caught by an existing code, record which and mint nothing.

**D-05 read burden:** 1.

### Phase 28 — Evidence case: a magnitude no reported test computed (§6.5 item 8)

**Entry condition (brief, verbatim):** "A corpus case passes all claims checks while
asserting a magnitude no reported test computed. The paper-shaped instances all fire
`DSX-CLM-070` and the per-test effect-size finding already."

**Build the case first.** A spec whose `results.tests[]` reports, with effect sizes
and intervals, two tests on metrics A and B, and whose `claims[].text` asserts
"customers with fewer than two products churn at 27 % against 18 %" — a magnitude on
metric C that appears in no test, with `base_n` declared so `DSX-CLM-070` clears and
absolute percentages so no relative-% rule is triggered. Measured live: it must pass
every claims, narrative and stats check at the default threshold for the entry
condition to hold.

**If it is a live miss — the declaration and the check.** `claims[].supported_by`
names the `results.tests[]` entry (by index or `metric`) a claim rests on; the check
extracts every numeric literal from the claim text and requires each to appear among
that test's reported numbers — `effect`, `ci` bounds, `from_value`, `to_value`,
`base_n`, `p_value` excluded — within a declared rounding tolerance
(`claims[].rounding`, default two significant figures). Declaration-only: a text-to-
declared-number overlap, the `DSX-REP-061` precedent, never a recomputation. A claim
with no `supported_by` under a causal/prescriptive/predictive question fires HIGH; a
number outside the referenced test fires CRITICAL.

**D-05 candidates (UNVERIFIED):** Wilkinson, L. and the Task Force on Statistical
Inference (1999), *Statistical Methods in Psychology Journals: Guidelines and
Explanations*, American Psychologist 54(8):594–604 (report effect sizes and
intervals for primary results); Appelbaum, M. et al. (2018), *Journal Article
Reporting Standards for Quantitative Research in Psychology* (APA JARS–Quant),
American Psychologist 73(1):3–25. The plan must pick one locator that states the
operational rule the check enforces, or record that neither does and fall back to
the structural criterion alone with the citation marked as context.

**D-06.** Next free `DSX-CLM-*` number. Caught-already → record, no mint.

**D-05 read burden:** 1–2.

### Phase 29 — Evidence case: subgroup harm under a prescriptive recommendation (§6.5 item 9)

**Entry condition (brief, verbatim):** "A primary source with operationalisable
criteria (D-05) **and** a corpus case where subgroup harm was the documented
failure. Until promoted, the question lives in the architect and storyteller prompts
as an agent guardrail."

**Build the case first.** A prescriptive spec ("offer the retention bundle to all
at-risk accounts") with a positive overall effect and four declared
`results.segments[]`, three positive and one — a minority segment with n above the
floor — negative, with no disposition declared anywhere. Because fewer than half the
segments oppose, `DSX-MET-030`/`031` structurally cannot fire (verified in
`dsx/checks/metrics.py`, 2026-09-06); the architect's and storyteller's prompts ask the
question but nothing reads an answer. Measured live.

**The primary source, and what "operationalisable" means here.** The criterion the
check needs is *when does a segment count as harmed*: a treatment effect of opposite
sign to the recommendation's direction, in a pre-declared segment, with an interval
that excludes zero or an n above a declared floor. Candidate (UNVERIFIED): Gail, M.
and Simon, R. (1985), *Testing for qualitative interactions between treatment
effects and patient subsets*, Biometrics 41(2):361–372 — the qualitative-interaction
definition (effects of opposite sign across subsets) is the published criterion; the
test itself is computation and stays off the gate path (D-02); only the definition is
enforced as a declaration. The **documented failure case** is a research deliverable:
a public post-mortem where an average benefit masked harm to a subgroup. If phase
research cannot find one with a primary source, that is recorded and the item stays
on the backlog with the half-met condition stated — no mint.

**If both conditions hold — the declaration and the check.** Optional
`decision.subgroup_harm[]`: `{segment, effect, ci, n, disposition: accept | exclude |
mitigate, rationale}`. For a prescriptive question, a declared segment whose effect
opposes the recommendation's direction and meets the declared floor must have a
disposition row, or the check fires CRITICAL; a disposition of `accept` without a
rationale fires HIGH. The storyteller's existing "say who bears the cost" rule then
has a field to read.

**D-06.** Next free `DSX-COH-*` (the decision-coherence family owns
recommendation-level obligations, cf. `DSX-COH-040`). Caught-already or source not
confirmed → record, no mint.

**D-05 read burden:** 2 (Gail & Simon locator; the case source).

## 5. Critique register (what a sceptical reader will ask, answered up front)

1. *"Growing the profiler is computation — doesn't that breach D-02?"* No. D-02
   binds gates. The profiler has always computed (null rates, duplicate rates, gaps)
   and no gate reads the new keys this milestone. The boundary is stated in the
   requirement, tested by the byte-identical `dq.py`, and the assertion vocabulary
   stays frozen.
2. *"SEED-002's own entry condition was unmet — why promote it?"* Operator direction,
   recorded (HQ-39 reversing HQ-38, same day, with the reason: the portfolio work
   starting now is the evidence the condition asked for, and it is cheaper to have
   the numbers hash-bound from the first phase than to retrofit). D-13 governs the
   loop's own promotions; the operator may direct scope, and the record says so.
3. *"Phases 27–29 could manufacture misses to justify mints."* The brief's top rule
   forbids it: measure first, and a case caught by an existing code closes the phase
   without a mint. The corpus harness makes the measurement reproducible on every
   test run, and the golden ledger pins each fixture's blocking set.
4. *"Per-feature provenance is a declaration a liar can fill in."* Yes — so is every
   other declaration in the contract; the brief's own row says the item "buys
   attribution, not a catch". The value is that a *stated* origin can be audited by
   `dsx-ml-integrity-auditor`, where an unstated one cannot.
5. *"Isn't the magnitude check just `DSX-REP-061` again?"* Same mechanism, different
   object: `DSX-REP-061` compares a reproduce report to `results.tests`; this compares
   a claim's numbers to the test it cites. Both are text-to-declared-number overlaps,
   which is why the precedent is named rather than a new mechanism invented.
6. *"Gail & Simon is a test — D-02 bans computing it."* The check enforces only the
   *definition* (opposite-sign effect in a declared subset) as a declaration
   obligation; the test statistic is never computed on the gate path. If the human
   read finds the paper does not state a usable definition, the phase records that
   and does not mint.
7. *"Eighteen requirements, six phases — is that the smaller, provable claim?"* Each
   phase is individually small (one artifact, one case) and the two halves are
   separable by the pre-agreed contingency. What makes the claim provable is that
   every phase ends in a measured number: byte-identical regenerations, a repo-
   integrity test, a live gate measurement, or a re-baselined catch rate.
