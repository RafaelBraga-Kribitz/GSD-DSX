### Why all nine Phase 7 requirements read `partial`

Phase 7 executed all 8 plans and its UAT closed 35 of 36 tests. The one failure — UAT
test 4, gap **G-07-4**, severity major — was a D-05 citation contradiction: `val.py`
asserted Kish (1965) "section 8.2, page 258" and then stated four lines later that only
the page numbers were confirmed. The user pinned remedy **reading_b** at UAT close, and
plan **07-08** implemented it on 2026-08-14.

`07-VERIFICATION.md` was **not re-run after that closure** — deliberately, because a
concurrent `/gsd-secure-phase 08` session held the tracking files at the time. So the
phase's verifying gate still describes the pre-closure state and still carries a
`human_needed` verdict on two items that UAT has since resolved.

Per this project's working agreement — *do not mark requirements complete until the
verifying gate has actually passed* — none of the nine can be scored `satisfied` yet.
The code evidence says they will pass: the full suite is green and every `DSX-VAL-*` code
is gate-reachable. This is a **paperwork gap with a one-command fix**, not a code gap —
with the single exception of REQ-P7-08, which is genuinely partial on substance.

## Tech debt

18 open items across four phases. None blocks any Success Criterion; all were surfaced by
the phases' own reviews and are carried forward honestly rather than hidden. Full detail
in the frontmatter `tech_debt:` block. The items most worth a decision:

1. **`design.alpha: 0` silently defaults to 0.05** (`dsx/frame/paradigm.py`, falsy-`or`).
   Recorded independently by both the Phase 8 and Phase 9 reviews — one bug counted twice,
   still open. A declared alpha of 0 is nonsense input, but silently rewriting a declared
   value is exactly the class of behaviour this tool exists to catch elsewhere.
2. **The D-11 boundary blind spot** — reproduced live in this audit: neither the AST nor
   the text detector sees `spec.get("inference", {}).get("paradigm")`. Not exploited today,
   but it is the one unwatched door into the invariant three phases depend on.
3. **CRLF in `dsx/decisions.py::append`** — a trail written on Windows will not byte-match
   one written on Linux CI. Phase 10 is about to promote `DECISIONS.jsonl` from a side
   channel to a **gate input** (content-lock reconciliation), which raises the stakes on
   byte-level trail fidelity considerably.
4. **README says `# 121 tests`; the suite is 543.** Re-confirmed live.
5. **Package descriptions name none of this milestone's surface** — `capability.json` and
   `plugin.json` describe a v2.0 chart-lookup feature and mention no `validity_frame:`,
   no `DECISIONS.jsonl` / `dsx explain`, no `DSX-PAR-001`.
6. **Decision trails grow unbounded during test runs** — `examples/DECISIONS.jsonl` is
   11.6MB, `examples/known-bad/DECISIONS.jsonl` 1.3MB. Both gitignored (confirmed:
   `.gitignore` carries `DECISIONS.jsonl`, and `git ls-files` matches neither), so there
   is no commit pollution — but the growth is real and recorded as a residual in
   `08-SECURITY.md`.

## What the milestone's definition of done still requires

The v2.0.0 core value is *"a statistically invalid analysis must fail at the gate, before
the data is touched."* Against that bar:

- **Delivered.** The contract surface (M1), the paradigm-independent frame checks (M2a),
  the interference/triggering/stability family (M2b), and symmetric monitoring discipline
  (M2c) — 18 finding codes, all gate-reachable, all carrying D-05 citations.
