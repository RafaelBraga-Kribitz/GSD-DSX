<objective>
Move the argument-inspecting half of the scanner — principally DSX-CODE-021 — off the
per-physical-line regular-expression scan and onto argument extraction over `ast.Call`
nodes, and fix `_read_source` so a notebook contributes code cells only without moving a
single reported line number.

Purpose. DSX-CODE-021's extractor is blind to five shapes at once, and every one of them is
a real leak that the gate currently answers with an affirmative pass line: a keyword
argument (`model.fit(X=data)`), the second and later fit calls on one physical line, a call
whose argument sits on a different physical line, a chained-call argument, and
`partial_fit`. They are not five bugs. They are one mechanism reading text where it needed
to read structure. Separately, the notebook reader concatenates MARKDOWN cells with code
cells, so a notebook whose prose *warns against* leakage is blocked CRITICAL for saying so —
the false-positive direction, which erodes trust in a blocking gate faster than a blind spot
does.

Output. `dsx/checks/code.py` with AST first-argument extraction feeding DSX-CODE-021, a
code-cells-only notebook reconstruction that preserves line geometry character for
character, a magic repair that runs only after a failed parse, and a text fallback hardened
to agree with the AST path instead of contradicting it; regression tests in
`tests/test_dsx.py::TestPhase11_1Code` covering every firing shape, every silence shape, the
path-parity cases, the notebook geometry in both trailing-newline shapes, and two timing
bounds measured against these mechanisms rather than inherited from a sibling.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired on this phase with `kind: pluralization` — a second thing
appears where there was one. It is still right under the new mechanism, and the noun it
points at is the same one.

**The noun that is now primary:** *the fit-call argument tokens in a file* — plural. Today
`_fit_call_arguments` returns a list but can only ever put one token per line into it, so the
plural type is a lie the singular implementation tells.

**Decision: promote, on both mechanisms.** On the AST path the plural form is the only form
that exists — a walk yields every call node and there is no singular variant to leave behind.
On the fallback the single-match `search` is replaced in place by `finditer`; no "get every
match" helper is added beside a still-primary single-match one.

**Rationale, in one line:** a surviving single-match path is how a future caller silently
reintroduces exactly the bug SC3 closes, and it would read as ordinary code rather than as a
regression, so nothing would catch it.

**Invariant that encodes the generalized intent** (implemented in task 1, not merely
suggested): `test_every_fit_call_on_a_line_is_extracted_in_source_order` asserts that a line
carrying three fit calls yields three tokens in left-to-right order, and that a nested pair
`m.fit(a).fit(b)` yields `a` first. Called twice on the same input and compared for equality,
pinning stability. A future narrowing back to single-match extraction turns it red on the
count; a future change of walk order or sort key turns it red on the order.

This checkpoint is advisory. It records a decision; it does not block the phase.
</assumption_delta_decision>

<uncaught_after_this_plan>
Written here so that plan 03's README section is derived from a list the code actually
produces, and so that nothing in this plan can be read as a soundness claim. These are REAL
leaks the scanner does not see after this plan lands. This list is not exhaustive either.

**Because the callee or the argument cannot be resolved**
1. Dynamic dispatch — `getattr(model, "fit")(data)`, `handlers["fit"](data)`.
2. A bound method in a variable — `f = model.fit` on one line, `f(data)` on another.
3. A fit inside a helper module the entrypoint imports — only the declared entrypoint is read.
4. A keyword outside `FIT_FIRST_PARAM_NAMES` — `model.fit(training_frame=data)` draws nothing.
   Deliberate: an allowlist trades this miss for immunity from the false-positive flood a
   blocklist produces (T-11.1.1-07).
5. A starred first argument — `model.fit(*args)`.
6. A full frame laundered through a training-frame-shaped name — `X_train_like = data;
   model.fit(X_train_like)` passes, because `_is_training_frame` prefix-matches the name and
   never follows the assignment.
7. A constant first argument is reported as nothing rather than as a leak — deliberate, and
   it is today's behaviour, not a new one.

**Because the file did not parse**
8. On the fallback everything the regex era missed returns: no multi-line calls, no
   chained-call arguments, no backslash continuation (the joining helper is deliberately never
   written), and prose in a docstring or a comment can still block CRITICAL.
9. A cell magic whose body is not Python (`%%bash`, `%%sql`, `%%R`, `%%writefile`) and the
   `?`/`??` introspection suffix are not repaired, so those notebooks scan on the fallback.

**Coordinate space**
10. For a `.ipynb`, `Line N` indexes the reconstructed cell concatenation, not any file the
    user can open at that offset. This plan preserves that numbering exactly rather than
    fixing it, and does not claim to fix it.

**Because the gate does not run the code**
11. Anything that exists only at runtime — `exec`/`eval`'d source, generated code, a frame
    mutated between the split and the fit. Note for plan 03: source assembled in a string and
    `exec`'d is caught TODAY by the text scan and is NOT caught by a call-node walk. That is a

    only in a limits list.
