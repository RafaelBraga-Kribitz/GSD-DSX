Convention confirmed: every compiled pattern is a **module-level, ALL-CAPS (or
`_LEADING_UNDERSCORE_ALL_CAPS` for internal-only) constant**, declared once at
import time, immediately preceded by a comment block that states (a) which
phase/requirement introduced it, (b) the exact linearity/backtracking property,
measured, not assumed, and (c) which timing test pins that property. No pattern
in this file is compiled inline inside a function. `FIT_CALL_RE`'s widened form
in this phase must be edited in place at its existing module-level declaration
(current line 114-116), keeping the same comment-then-constant shape — do not
move it or make it a local/inline compile.

**CRLF check confirmed:** grepped the full module — no pattern contains `\r`,
`\n`, `\\n`, or `os.linesep`. `check()` calls `source.splitlines()` upstream
(confirmed at `dsx/checks/code.py:205`-area per RESEARCH.md), which strips line
terminators before any regex in this file ever runs. **Do not add `\r?\n`** to
`FIT_CALL_RE` or any new pattern — it would be dead/wrong, since no per-line
string this module operates on ever contains a terminator character. This
matches the CLAUDE.md CRLF rule's *intent* (tolerate `\r\n`) but the correct
implementation here is "operate after `splitlines()`, which already normalizes
it," not "add `\r?\n` to a regex."

**Precedent for "delete a redundant/falsely-justified check and document why"**
(lines 53-74, the block introduced by commit `06ff2d7` for CR-01/CR-02): this is
the exact house idiom for how this file explains a correction to previously
wrong logic — state what was wrong, what is now true, the measured evidence, and
which test pins it. Any new comment accompanying the CR-03 literal-check
deletion or the CR-04 `FIT_CALL_RE` widening should follow this same block shape
(reproduced in RESEARCH.md's own Code Examples section — no need to re-derive).

```python
class TestPhase11_1Code(unittest.TestCase):
    ROOT = Path(__file__).resolve().parent.parent

    def _entrypoint(self, tmp: str, text: str, name: str = "entry.py") -> str:
        Path(tmp, name).write_text(text, encoding="utf-8")
        return name

    def _check(self, tmp: str, entry: str):
        from dsx.checks import code as code_mod

        return code_mod.check(
            {
                "model": {"task": "binary_classification"},
                "reproducibility": {"entrypoint": entry},
            },
            tmp,
        )

    # ── DSX-CODE-020: full-frame cleaning before the split ──────────────────

    def test_fillna_mean_before_split_is_critical(self):
        # D-05: DSX-CODE-020
        with tempfile.TemporaryDirectory() as tmp:
            entry = self._entrypoint(
                tmp,
                "from sklearn.model_selection import train_test_split\n"
                "df['Age'] = df['Age'].fillna(df['Age'].mean())\n"
                "train_test_split(df)\n",
            )
            report = self._check(tmp, entry)
            found = [f for f in report.findings if f.code == "DSX-CODE-020"]
            self.assertEqual(len(found), 1)
            self.assertEqual(found[0].severity, Severity.CRITICAL)
```

New SC1/SC2/SC3 tests should follow this exact idiom: build the entrypoint text
inline as a multi-line string via `self._entrypoint(tmp, ...)`, call
`self._check(tmp, entry)`, then assert on `codes(report)` (the module-level
helper already used throughout the file — see `TestPhase3Code` below) or on
`report.findings` directly when severity or count matters, exactly as this
method does with `report.findings`.

**Gate-exit-code assertion** (quoted verbatim,
`tests/test_known_bad_corpus.py:611-644`):

```python
    def test_every_spec_blocks_only_on_its_target_defect_at_critical_threshold_points(self):
        """... at each of `_CRITICAL_THRESHOLD_POINTS` (`plan`, `execute`), a
        fixture with no expected code for that point in `_effective_target_map()`
        clears it (exit 0) ... A fixture with one or more expected codes for
        that point MUST block (exit 1) with every one of them among the
        CRITICAL findings ..."""
        specs = self._spec_paths()
        self.assertTrue(specs, "no known-bad specs found to gate")
        for path in specs:
            slug = path.name[: -len(SPEC_SUFFIX)]
            effective = _effective_target_map()
            for point in _CRITICAL_THRESHOLD_POINTS:
                with self.subTest(spec=path.name, point=point):
                    code, findings = self._gate_findings(path, point)
                    problems = _classify_target_defect(
                        slug, point, code, findings, effective
                    )
                    self.assertEqual(problems, [], "; ".join(problems))
```

Confirms RESEARCH.md's own claim: this existing test already asserts every
fixture's `plan`/`execute` exit code against `_TARGET_DEFECT_CODES` on every
run — **no new harness code is needed** for SC4. The planner's proof procedure
is simply: run `python -m unittest tests.test_known_bad_corpus -v` before and
after the code.py edit and diff, relying on this existing per-fixture assertion
to fail automatically if any fixture's exit code moves unexpectedly.
