## The three defects, in one paragraph each

**GAP-1 (criterion 2).** The text fallback's `FIT_CALL_RE` only recognises an allowlisted
keyword when it is the first token after the opening parenthesis.
`model.fit(y=y_train, X=full_frame)` is a genuine post-split leak, is caught CRITICAL on the
parsed path, and produces zero matches on the fallback path. Any file that falls back for an
unrelated reason silently loses this class of leak — the gate exits 0 over a file that leaks.
The shipped comment above the pattern claims the two mechanisms agree; they do not.

**GAP-2 (criterion 4).** `_prose_line_indices` builds a prose mask with exactly one consumer,
the split-marker scan. `_first_full_frame_cleaning_line` (feeding DSX-CODE-020, CRITICAL) and
`_stat_test_lines_referencing` (feeding DSX-CODE-030 CRITICAL and DSX-CODE-031 HIGH) neither
accept nor receive it. A module docstring that merely describes a cleaning idiom still blocks
the file CRITICAL over code that never calls it.

**GAP-3 (criterion 5).** `_read_source`'s notebook branch guards only `json.loads`. The
`.get()` calls that follow assume the document is a dict and every cell is a dict. Content of
`[]` is valid JSON and raises `AttributeError` uncaught out of `check()` — a raw traceback and
exit code 1, the same number the gate uses for "blocked", violating the project's own contract
that exit 2 means "check could not run".
