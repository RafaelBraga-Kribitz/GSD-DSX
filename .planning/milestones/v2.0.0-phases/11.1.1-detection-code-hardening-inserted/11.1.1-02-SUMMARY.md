# Phase 11.1.1 Plan 02: DSX-CODE-021 AST argument extraction Summary

**Moved DSX-CODE-021's first-argument extraction off the line-ordered regex scan onto `ast.Call` node resolution (keyword arguments, chained calls, multi-line calls, `partial_fit`, semicolon-joined second calls all now fire), widened the fallback to agree instead of contradict, and closed a BOM-notebook read gap the same class of fix plan 01 already applied to `.py`.**

## Accomplishments

- `DSX-CODE-021` is resolved from `ast.Call` sites on the parsed path via two new functions,
  `_first_argument` (positional-then-allowlisted-keyword resolution, `ast.Starred` skipped,
  `ast.Constant` returning `None`) and `_render_token` (`ast.unparse`, one rendering path),
  consuming the SAME `call_sites` tuple plan 01 built for `DSX-CODE-001` — never re-walked.
- Closes five real blind spots at once: keyword arguments (`model.fit(X=data, y=target)`),
  `fit_transform` keyword arguments, `partial_fit` after the split, a chained-call argument
  (`model.fit(loader.get_full_frame())`), and a second fit call on a semicolon-joined line
  that a safe first call used to mask entirely.
- The fallback's `FIT_CALL_RE` is widened to AGREE with the AST path instead of contradicting
  it: `partial_fit` joins the alternation and an optional keyword prefix is gated on the SAME
  `FIT_FIRST_PARAM_NAMES` allowlist the AST path uses, so `model.fit(y=y_test)` stays silent
  on both mechanisms rather than firing a false positive on the fallback alone.
  `_fit_call_arguments` is promoted from `search` to `finditer` — exactly one extraction path
  per mechanism, as the plan requires.
- `.ipynb` is now read with `utf-8-sig`, closing the same BOM-silently-drops-the-scan gap
  plan 01 already closed for `.py`; a BOM'd notebook previously read as "could not be read"
  (NOT scanned) rather than being scanned.

  ALREADY closed by plan 01 (character-wise blanking landed one task early there, per its own

## Decisions Made

- **`test_constant_first_argument_draws_nothing_on_both_paths` scoped to `42`/`'x'` only, not
  `model.fit(None)` as the plan's prose named.** Measured against unmodified source before
  writing the test (per the plan's own "if a silence test fails here, stop: the fixture is
  wrong" instruction): `model.fit(None)` actually FIRES `DSX-CODE-021` on the pre-task-2 code,
  because `DSX-CODE-021` was not yet wired to the AST path at all (it ran unconditionally
  through the OLD `_fit_call_arguments`/`FIT_CALL_RE`, which has no bareword-constant
  exclusion — `"None"` reads as an ordinary identifier to a regex, unlike a numeric literal,
  which the `[A-Za-z_]` anchor already excluded). Added a separate test,
  `test_bareword_constant_first_argument_draws_nothing_on_the_ast_path`, pinning the AST-only
  fix task 2's `ast.Constant` rule introduces; the fallback keeps this pre-existing,
  out-of-scope miss (named in a comment, not silently absorbed).
- **`test_nested_fit_calls_report_the_textually_first_token` already passes against unmodified
  source.** `m.fit(full_frame_a).fit(full_frame_b)`'s single-line `.search()` finds the
  leftmost `.fit(` occurrence, which happens to be the textually-first call, so this test was
  NOT part of task 1's RED failure set — the same pattern plan 01's SUMMARY documented for the
  multi-line open-paren case. Kept as the committed pin for the `(line, col, end_col)`
  tie-break `_call_sites` implements; documented rather than silently reclassified.
- **Plan 01's three-element `_call_sites` ordering key `(line, col, end_col)` verified
  sufficient, not amended to the design doc's four-element `(line, col, end_lineno,
  end_col_offset)` key.** Every SC2/SC3 shape — including the nested-collision tie-break test
  — passes under the existing key; no fixture in this plan requires the fourth element, and
  the `_CallSite` class docstring already documents the chosen tie-break with its own
  measured evidence. Verifying rather than editing an already-correct symbol.
- **Task 3's genuine remaining gap, found by measurement rather than assumed from the plan's
  framing:** `.ipynb` was still read as plain `"utf-8"`, not `"utf-8-sig"` — a BOM'd notebook
  silently read as "could not be read" (NOT scanned) instead of being scanned. Fixed
  identically to the `.py` read's existing `utf-8-sig` handling (plan 01). The notebook
  markdown false positive and both trailing-newline geometry shapes this task's own objective
  named as still-open were confirmed already closed by plan 01 — not re-implemented, cited via
  the existing tests instead.
