### 1. WR-02 -- the declared-but-unscannable entrypoint's missing DecisionRecord

When a declared entrypoint resolves to a path that does not exist, or
resolves but cannot be read -- an unsupported suffix, an unreadable file,
or, after plan 04, a structurally malformed notebook -- `check()` returns
before either `record_decision` call runs. Two consequences, both
unchanged by this plan:

1. `DECISIONS.jsonl` gets zero entries for that run of the code check, so
   `dsx explain` can replay nothing for it, even though a real judgment was
   made (that this entrypoint could not be scanned).
2. `Report.render()` only prints passed checks under `--verbose` (default
   off), so by default `dsx gate` prints a bare passing line for the code
   check that is, on its face, indistinguishable from a real clean scan.

Plan 04 made this path REACHABLE for one more input class (the malformed
notebook), which raises how often this gap matters without changing the
gap itself. Verified this plan: `grep -c "scan_path:not-scanned"
dsx/checks/code.py` reports 0 -- no task in this plan (or plan 04)
implemented the `scan_path:not-scanned:<reason>` decision input
`11.1.1-AST-DESIGN.md`'s blocker table specified for this case.

**The decision required:** is this an acceptable known gap to ship, or must
it close before the phase counts as done? If it must close, it is a new
plan, not an edit to this one or to plan 04.
