**Section — What triggers the pair.** Both halves trigger on `design.peeking_policy` normalizing to
`uncontrolled_continuous` and nothing else. Neither reads `results.interim_looks` (D-04). State the
reason plainly: at `dsx gate plan` a spec has no `results:` block yet, so a trigger reading it would
silently become verify/ship-only and ROADMAP Success Criterion 1 would be false.

**Section — Clearing conditions, per paradigm.** A table with one row per member of `PARADIGMS`:

  - `frequentist` → code `DSX-PAR-010`, cleared by a non-blank `inference.alpha_spending` **or** a
    non-blank `inference.threshold_calibration`.
  - `bayesian` → code `DSX-PAR-011`, cleared by a non-blank `inference.prior_justification` **or** a
    non-blank `inference.threshold_calibration`.

State the three structural facts that make this symmetric: each paradigm has exactly two clearing
declarations; exactly one of the two (`threshold_calibration`) is shared by both; and each
paradigm-specific declaration is a non-blank free-text scalar evaluated by the same predicate. No
per-paradigm and no per-member code path exists.

**Section — The honest fix versus the cheap fix.** The honest fix for either half is to change
`design.peeking_policy` to `sequential_obf`, `sequential_pocock` or `always_valid` — that is what
"declaring a sequential or anytime-valid method" means in this contract (REQ-P9-01), and it removes
the trigger for both halves identically. The cheapest dishonest fix is to type any non-blank string
into the paradigm-specific clearing field. Say explicitly that this cheapest dishonest path costs
exactly the same on both sides — one free-text declaration — and that this equality, not the
existence of two codes, is what brief D-12 requires.

**Section — What the gate cannot adjudicate.** A declared `prior_justification` is checked for
presence, never for quality; prior-justification quality is `DSX-PAR-020`'s job and is deferred
under brief D-12a. Likewise a declared `threshold_calibration` is the operator's own claim about
their own calibration. Name this as the project's standing known limit ("a frame that lies passes")
rather than presenting the check as stronger than it is.

**Section — The undeclared-paradigm case.** With no `inference.paradigm` declared, every row of the
per-paradigm map applies, so both `DSX-PAR-010` and `DSX-PAR-011` can fire. State the brief-D-10
property this preserves: declaring a paradigm never adds a finding, it only ever removes one, so an
honest declaration is never more expensive than silence. `DSX-PAR-002` (HIGH) additionally names the
missing declaration, but the block at `dsx gate plan` comes from the pair's CRITICAL severity.

**Section — Reference values and their sources.** `DSX-PAR-010` reuses
`dsx.mathx.inflation_from_peeking()`; at a nominal alpha of 0.05 that function returns `0.142` at
five looks and `0.248` at twenty. `DSX-PAR-011`'s reference value is `1/(K+1)`, which is `0.05`
exactly at `K = 19`, the posterior odds implied by a `P(B>A) > 0.95` decision threshold, cited to
Deng, Lu & Chen (2016) — Theorem 1 for what licenses the figure under optional stopping, and the
paper's unnumbered §3.2 prose for the bound in its operational "at most `1/(1+K)`" form. State that
Theorem 1 does not itself state `1/(K+1)`, and that Ville's inequality is a different result giving
`1/k`, which is about `0.0526` at `k = 19` and is never a substitute. Do not use the word "rounded"
anywhere near these two numbers; a guard in `tests/test_known_bad_corpus.py` blocks that phrasing
across the planning documents and the corpus.

Then add one sentence and one link to `README.md`'s existing "Two tiers of evidentiary rigour"
section pointing a reader at `references/paradigm-symmetry.md` as the symmetry argument behind the
`DSX-PAR-*` family. Do not restructure that section.
