<objective>
Close the numeric and boolean hole in the clearing predicate, then make the committed symmetry
audit state what the code actually does.

Purpose: `dsx/spec.py::is_blank()` has no branch for `int`, `float` or `bool`, so a bare `0`, `0.0`
or `false` reads as "declared". `dsx/frame/paradigm.py::_blank_clearing_declarations()` reuses it
as the sole predicate deciding whether the CRITICAL pair fires. Reproduced by direct execution
against the shipped code on 2026-08-13: declaring `inference.threshold_calibration: 0` on an
uncontrolled-continuous design clears both `DSX-PAR-010` and `DSX-PAR-011`, and declaring
`inference.alpha_spending: 0` on a frequentist spec clears `DSX-PAR-010`. That is cheaper than the
"type any non-blank string" path `references/paradigm-symmetry.md` records as the cheapest
dishonest fix, so the committed audit's headline claim is factually wrong — and ROADMAP Phase 9
Success Criterion 5 is specifically the requirement that the audit gets that claim right.

The cost-symmetry property itself (brief D-12) is not broken: the escape is equally cheap on both
paradigms. What is broken is the audit's accuracy, and this plan closes the hole rather than
documenting it, so the audit becomes true by the code changing rather than by the claim shrinking.

Output: one new predicate, one rerouted call site, a regression test across the full type domain of
all three clearing declarations, and a corrected audit.
</objective>

<resolved_decision>
The verifier recorded two acceptable resolutions for this gap and required the plan to choose one
and say why. This is that choice, made — not handed back.

DECISION MADE: How to make the symmetry audit's "cheapest dishonest path" claim true again.

Option A: Close the hole with a new, narrowly scoped text-only predicate — CHOSEN
  In practice: add `is_blank_text(value)` to `dsx/spec.py` immediately after `is_blank`, returning
    True for anything that is not a string and for any string that is empty or whitespace-only.
    Change the one line in `dsx/frame/paradigm.py::_blank_clearing_declarations` to call it instead
    of `is_blank`. Leave `is_blank` itself byte-identical. Pin the resulting behaviour with a test
    over the full type domain for all three clearing declarations.
  This locks in: the three clearing declarations are free-text scalars, enforced rather than merely
    documented, and the audit's claim becomes true by the code changing.
  Cost later: a future clearing declaration that is legitimately structured (for example a
    `{method:, fpr:}` mapping for `threshold_calibration`) would need its own predicate, and the
    symmetry argument would have to be re-made across two shapes rather than one.
  Reversibility: cheap to undo

Option B: Amend the audit to document the bare-`0` path and accept it
  In practice: leave all code untouched and rewrite `references/paradigm-symmetry.md` to say the
    cheapest dishonest path is a bare zero or false, with a recorded decision to accept it.
  This locks in: a CRITICAL, gate-blocking check that a placeholder-looking value clears, which the
    project's own documentation then has to defend as intentional.
  Cost later: every future reader of the audit has to be told that "declared" includes a value
    carrying no content, and the next clearing declaration inherits the same hole silently.
  Reversibility: cheap to undo

Option C: Change `is_blank` itself to treat numbers and booleans as blank
  In practice: add an `int`/`float`/`bool` branch to `dsx/spec.py::is_blank`.
  This locks in: new semantics for 138 `is_blank` call sites across 18 modules (counted directly in
    this repository on 2026-08-13), including checks where a declared `0` or `False` is meaningful
    data rather than a dodge.
  Cost later: any of those call sites could start reporting a legitimately declared zero as missing,
    and nothing in the suite is scoped to catch that class of change.
  Reversibility: expensive to undo

Recommendation and decision: Option A, because it closes the hole at exactly the place it is
load-bearing while leaving the 138 unrelated `is_blank` call sites untouched — the blast-radius
survey is what rules Option C out, and `09-REVIEW.md` IN-01 independently says a blanket change to
`is_blank` needs its own audit across every caller.
If this had not been decided: Option A is also the default, so silence and the recommendation agree.

Dropped: a fourth option that type-checks the three fields in `dsx/spec.py::_validate_inference_shape`
and emits a new `DSX-SPEC-08x` for a non-text clearing declaration. It spends a permanent, never
renumbered finding code (brief D-06) on a shape rule, and it would still leave the pair's own
predicate deciding the block.
</resolved_decision>
