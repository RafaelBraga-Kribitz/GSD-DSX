# Phase 11.2 Plan 07: dsx explain self-reported trust-boundary section Summary

**`dsx explain` now renders a labelled "self-reported (taken on trust, not verified by dsx)" section after the decision trail, listing validity_frame.*, inference.* (incl. declared_at), and analysis.test read from the spec, with frame_digest structurally excluded and escalate still unrendered.**

- **Completed:** 2026-08-26T17:48:15-03:00

## Accomplishments
- `dsx/cli.py::_self_reported_fields` flattens `validity_frame.*` and `inference.*` (dotted-path leaf values, lists joined) and pulls `analysis.test` alone, excluding the rest of the `analysis:` block.
- `_render_decision_trail` appends a clearly-labelled block after the decision-record loop, fed from `cmd_explain`'s existing `find_spec`/`load` call, itself guarded so a missing or unparseable spec yields no section rather than an error.
- `frame_digest` remains exclusively in the computed invocation-header line; a test asserts its literal value is absent from the self-reported section text.
- `escalate` remains unrendered; no block-contract primitive (severity ladder, threshold table, `Report`) was imported. `cmd_explain` still returns 0 by construction on every path, verified both by unit tests and a direct source inspection of the function body.

## Files Created/Modified
- `tests/test_explain_self_reported.py` - RED-phase test module: section labelling/position, validity_frame/inference/analysis.test field listing, frame_digest exclusion, escalate exclusion, returns-0 on every path (happy, missing-spec, no-trail).
- `dsx/cli.py` - Added `_self_reported_fields(spec)` helper; extended `_render_decision_trail(records, spec=None)` to append the labelled section; `cmd_explain` now loads the spec dict (guarded, falls back to `None`) and passes it through.

## Decisions Made
- Field set scoping: `validity_frame.*` and `inference.*` in full (matching the plan's "compared-but-never-computed" framing literally), `analysis.test` alone (not the whole `analysis:` block, since only `test` is a declared-but-never-computed comparison input — `outcome_type`, `n_per_group`, etc. are derived from the analyst's own data, not a trust-boundary declaration).
- Rendering format: `dotted.path: value` lines, one per leaf, under a `self-reported (taken on trust, not verified by dsx):` header — chosen for readability and to make the frame_digest-exclusion property trivially checkable (no nested-dict dump that could accidentally re-embed a computed value).
- Guard placement: the spec load lives inside the same defensive structure `root` resolution already uses (`path` from `find_spec` may be `None` on `CheckError`; `load()` failures are caught locally rather than bubbling to the outer catch-all), so a missing/corrupt spec degrades to "no self-reported section" rather than changing the exit code or the "no readable decision trail" fallback message.
