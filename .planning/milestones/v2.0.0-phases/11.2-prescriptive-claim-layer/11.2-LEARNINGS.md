# Phase 11.2 Learnings: Prescriptive Claim Layer

## Decisions

### D-02: land vocabulary member, strength row, and remedy text in one slice
Adding `prescriptive` to `CLAIM_TYPES` (spec.py) had to happen in the same commit slice as adding `CLAIM_STRENGTH["prescriptive"] = 4` (coherence.py) and correcting both `DSX-SPEC-061`/`DSX-SPEC-062` remedy strings from "four claim types" to "five claim types."

**Rationale:** Before this phase, a `type: prescriptive` claim tripped `DSX-SPEC-062` HIGH "unrecognised type" and was then silently skipped by `_check_claim_ceiling`'s `if ctype not in CLAIM_STRENGTH: continue` — a HIGH typo-looking warning with zero CRITICAL ceiling finding. Landing only the vocabulary member without the strength row (or vice versa) would recreate this exact silent-pass gap for any future closed-vocabulary extension.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-01-PLAN.md, 11.2-01-SUMMARY.md

### D-03: prescriptive claims reuse DSX-CLM-020/021 at causal parity, with no hedge exemption
Rather than minting a new `DSX-CLM-022` at flat HIGH (the Architect's original proposal), the phase widened `_check_causal_support`'s ctype gate from `!= "causal"` to `not in {"causal", "prescriptive"}` — a strict superset — so prescriptive claims are held to the identical CRITICAL-none/HIGH-weak severity split as causal claims, and (unlike causal) hedging does not rescue a weak prescriptive claim.

**Rationale:** The Statistician showed a flat-HIGH new code would create a causal→prescriptive severity-relabel dodge; reusing the identical codes/severities for both types means relabelling buys zero severity arbitrage — a recommendation is an action commitment, not a probabilistic statement, so hedge language cannot soften it.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-DISCUSSION-LOG.md, 11.2-05-PLAN.md

### D-04: gerunds are ordinary verb hits, not a hedge — two-tier lexicon is a false-positive gate, not epistemic softening
`CAUSAL_VERBS` was restructured into an always-hit tier (finite verbs + gerunds) and a purpose-gated tier (bare infinitives/noun-homographs like "reduce," "increase"), with the purpose-gated tier firing only inside a bounded purpose/recommendation-marker window. `HEDGE_TERMS` remains the sole epistemic softener; gerunds are never routed through it.

**Rationale:** The requirement's original wording ("gerunds via the hedging path") was a category error the Statistician flagged, anchored on Hernán 2018: a gerund ("reducing churn") is unambiguously verbal, not a probabilistic hedge. Routing it to the softer MEDIUM path would let "increasing spend drives revenue" (no hedge) escape as MEDIUM instead of firing CRITICAL.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-DISCUSSION-LOG.md, 11.2-02-PLAN.md

### D-08/D-09/D-10: fail-closed top-level spec_id plus an identity-free whole-trail floor as an un-renameable backstop
`spec_id` is a required, top-level-only field (never inside `validity_frame`/`inference`, so it never enters `frame_digest`) for any prescriptive question or experiment design. Beyond the identity-scoped amendment check, an identity-free floor also counts distinct `frame_digest` values across the ENTIRE trail root regardless of `spec_id`, so renaming the identity cannot erase the signal. An amendment clears the finding only when its `reason` passes `is_placeholder_or_refusal` AND both `prev_frame_digest`/`new_frame_digest` match recorded trail headers.

**Rationale:** The Auditor showed all derived identities are gameable (an operator can rename `spec_id` to reset the amendment count) and that Phase 10 deliberately omitted any spec identity to avoid cross-spec false positives on a shared trail root. The identity-free floor deliberately re-opens that Phase-10 cross-spec FP as the accepted cost of a rename-proof backstop (T-11.2-07, disposition: accept).
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-DISCUSSION-LOG.md, 11.2-03-PLAN.md, 11.2-03-SUMMARY.md

### D-07: a new sibling predicate, never a mutation of the shared falsifier
`revisit_when_is_discriminating(x)` is a brand-new function that calls `falsifier_is_discriminating(x)` unchanged and conjoins a window-token clause — it does not modify `falsifier_is_discriminating`'s body, signature, or `FALSIFIER_DISCRIMINATORS`.

**Rationale:** `falsifier_is_discriminating` has two existing estimand callers (val.py:236, val.py:637) that validate a windowless logical falsifier, and the good fixture's own estimand falsifier (good:303) has no window. Adding a window requirement directly to the shared function would have newly fired `DSX-VAL-011` on that fixture — a cross-family regression the phase's own regression test (test_frame_val) was written to catch.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-06-PLAN.md, 11.2-06-SUMMARY.md

### D-14: quarantine reader-less scaffold fields, never delete them
`decision.reversible` and `decision.deadline` — confirmed by grep to be read by no check in `dsx/` — were moved into an explicitly labelled "Documentation-only — NOT gate-read" block in the template, keeping their keys and example values rather than removing them.

**Rationale:** Operator specs already carry these fields and their human-documentation value (a decide-by date, a reversibility note) is real even though no gate enforces them. Deleting them would lose that value; the honest fix is the explicit label, paired with an AST/text invariant test (`test_scaffold_quarantine.py`) that keeps the label from silently becoming a lie.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-04-PLAN.md, 11.2-04-SUMMARY.md

### WR-01: exempt prescriptive from DSX-CLM-011 rather than leaving the two checks in contradiction
Code review found that a well-identified prescriptive claim could clear the DSX-CLM-020/021 clean path yet still be blocked CRITICAL by DSX-CLM-011 the moment it named its effect with a lexicon verb, because `_check_causal_language`'s early return exempted only `ctype == "causal"`. The fix widened the exemption to `{"causal", "prescriptive"}`.

**Rationale:** The Architect and Statistician split on timing (FIX-NOW vs DEFER), resolved FIX-NOW on the rigour tie-break because the fix was empirically proven catch-preserving: the flagship known-bad fixture's ship-time set lost only DSX-CLM-011 and gained nothing, still blocking on DSX-CLM-020 + DSX-COH-001 + DSX-COH-010, all CRITICAL.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-REVIEW.md

## Lessons

### InvocationHeader's dataclass field ordering constrains where a new field can go
`spec_id` had to be added as the LAST field on `InvocationHeader`, after `frame_digest`, defaulted to `None`.

**Context:** Dataclasses require non-default fields to precede defaulted ones, and the frozen `InvocationHeader` already had 4 non-default fields plus 9 pre-existing call sites (cli.py, tests/_trail_seed.py, and seven test modules) that construct it with no `spec_id`. Any other field position or a non-default field would have broken every one of those call sites at import or call time.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-03-PLAN.md, 11.2-03-SUMMARY.md

### RECORD_TYPES is decorative, not enforced — to_dict() hardcodes its literal
`AmendmentRecord.to_dict()` hardcodes the string `"amendment"` for `record_type` rather than reading it back from the `RECORD_TYPES` constant, mirroring `DecisionRecord`'s existing (unenforced) convention.

**Context:** A naive implementation might assume updating `RECORD_TYPES` alone would propagate the value; it does not — the set only documents valid values, it is never consulted at serialization time. This was flagged explicitly as a "landmine" in RESEARCH before Task 1 executed, avoiding the bug.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-03-PLAN.md, 11.2-03-SUMMARY.md

### A planned "RED" test case can already be green before the fix lands
The plan's Task 1 for causal-verb tiering expected the gerund-no-hedge case ("increasing spend drives revenue") to fail RED, but it already passed against unmodified source, because the finite verb "drives" was already a pre-existing lexicon member — the sentence fired DSX-CLM-011 regardless of whether "increasing" was recognised.

**Context:** The test was still kept as a regression guard (it pins that the gerund path is never accidentally routed to the MEDIUM/hedge branch); this is recorded as a documentation note against plan wording, not a code defect. Executors should verify each TDD case's RED-ness independently rather than trusting the plan's characterization of which cases will fail.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-02-SUMMARY.md

### CR-01: a purpose marker as broad as bare "to" matches every English infinitive, not just recommendation clauses
The purpose-gated causal-verb tier's marker set included the bare token `"to"`, which introduces every infinitive complement — so "usage tends to increase," "the pilot failed to reduce error rate," and any raising/negated-infinitive construction fired DSX-CLM-011/DSX-COH-010 CRITICAL as false positives, undetected because the only negative test covered the bare-noun case, not the "to <verb>" non-purpose case.

**Context:** Found in deep code review after the phase's own tests were all green — the existing test suite exercised the intended catches but never a non-purpose infinitive. Fixed by requiring a recommendation-head token (recommend/should/offer/roll out/…) before a bare "to," while keeping unconditional multiword markers ("in order to," "aimed at," "designed to").
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-REVIEW.md

### WR-02: a time window's own digits can satisfy an unrelated numeric discriminator
`revisit_when_is_discriminating(x) = falsifier_is_discriminating(x) AND _has_window_token(x)`, but `falsifier_is_discriminating` accepts ANY numeric via a bare `\d+` pattern — so a date window like "2026-Q4" (digits "2026") or a duration like "30 days" (digits "30") satisfied the numeric half by itself, letting a revisit trigger with no named metric and no threshold clear a CRITICAL check whose own remedy text explicitly demanded "a metric, a threshold, and a time anchor."

**Context:** Discovered via cross-file code review, not by the phase's own tests (one of which, `test_bare_duration_reassessment_is_accepted`, had actually pinned the bug as a passing case). Fixed by stripping the matched window span from the text before running the discriminator test, so the window's own digits cannot double as the threshold.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-REVIEW.md

### The finding-catalogue AST extractor silently drops a code if its title is a computed variable
`scripts/gen-finding-catalogue.py`'s `_literal()` helper returns `None` for any non-literal AST node, so a `title = f"..."` computed-variable approach to parameterizing a message by claim type would have removed DSX-CLM-020/021 from `references/finding-codes.md` entirely rather than merely picking one variant.

**Context:** The fix was to split the message into two literal `report.add()` call sites (one per claim type) — mirroring the existing DSX-COH-030/DSX-VAL-060 precedent — and to add the resulting divergent-title pair to `_CANONICAL_DECLARATIONS` in the catalogue's own test pin, since the generator's dedup step also warns "declared twice with different text" on divergent titles for one code.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-05-SUMMARY.md

### The real, committed DECISIONS.jsonl trail files already carried multiple distinct frame_digest values
`examples/DECISIONS.jsonl` (~5 distinct historical digests) and `examples/known-bad/DECISIONS.jsonl` (14) already tripped the new identity-free amendment floor the moment it existed, because years of accumulated test runs against the shared root recorded more than one frame_digest with no clearing amendment.

**Context:** 8 test methods across `tests/test_dsx.py` and `scripts/check.sh`'s gate-contract smoke test called `dsx gate verify`/`ship` directly against the real, shared `examples/` root (or a `shutil.copytree` that copied `DECISIONS.jsonl` along with everything else) and started failing once DSX-PRE-041 went live. Every affected call site had to be isolated into a fresh per-spec tempdir copy that excludes `DECISIONS.jsonl`.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-03-SUMMARY.md

## Patterns

### Ordering-precondition pattern for closed-vocabulary extensions
When adding a member to a closed vocabulary (e.g. a claim-type set), land the vocabulary member, every parallel ladder/strength dict that ranks it, and every remedy string that names the vocabulary's cardinality in the same commit slice.

**When to use:** Any future extension of a closed enum/vocabulary that has more than one consumer (a membership set, a ranking dict, and human-readable remedy text). Splitting the landing across commits recreates the "unrecognised-type finding fires, then the real check silently skips the now-recognised-but-unranked value" silent-pass shape.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-01-SUMMARY.md

### Sibling-predicate-over-mutation
When a shared predicate needs a stricter variant for one caller, write a NEW function that calls the original unchanged and conjoins the additional clause, rather than widening the original predicate's contract.

**When to use:** Any time a shared validation function has multiple callers with different tolerance requirements (here: estimand falsifier checks tolerate a windowless value; the new revisit-trigger check does not). Mutating the shared function risks a silent regression on callers that were never re-examined; the sibling pattern makes the byte-diff on the original function provable (a pure addition) and testable as a positive regression assertion.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-06-SUMMARY.md

### Golden-file (characterization) finding-set-equality pinning across the whole fixture corpus
After a lexicon/vocabulary widening that touches many code paths, measure every fixture's CRITICAL/HIGH finding set at the strictest gate point (ship) and commit it as a golden baseline; assert equality in a dedicated test module going forward.

**When to use:** Closing gate for any phase that widens a shared scanner/lexicon (here: the causal-verb tiering) across a corpus of many fixtures — proves the widening's union of effects is exactly the expected union (not a superset/regression, not a subset/landmine left open), and any future lexicon change is automatically caught by the same test.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-08-PLAN.md, 11.2-08-SUMMARY.md

### Point-scoped catch-attribution for fixtures whose defects split across gate points
For a fixture whose defects are caught by check families that register at different gate points (e.g. coherence at plan but not execute; claims at verify/ship but not plan), use a point-scoped `_TARGET_DEFECT_CODES` map keyed per gate point rather than a whole-set map contributed identically at every point.

**When to use:** Any known-bad fixture whose target defect codes come from checks with non-uniform `GATE_PROFILES` registration. Using the wrong (whole-set) map produces a false expectation that the fixture also blocks at a gate point where the relevant check family never runs.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-08-PLAN.md, 11.2-08-SUMMARY.md

### Two literal report.add() sites for a claim-type-parameterized message under one code
When one finding code needs different wording per claim type (or other discriminator) but must stay the same code/severity, write two separate literal `report.add()` call sites rather than a single call with a computed title variable.

**When to use:** Any time a message needs to vary by a runtime condition while the AST-based catalogue generator (`gen-finding-catalogue.py`) must still document every variant — a computed title is invisible to the generator's literal-node extractor and silently vanishes from the documentation.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-05-SUMMARY.md

### Two-layered invariant scanner (blunt text scan + precise AST scan) with self-firing subtests
For a regression guard that has no genuine production RED state to exercise (the bug it prevents doesn't currently exist), pair a text-level detector with an AST-level detector, and add subtests that deliberately trigger each detector against synthetic bad input to prove the scanner's own firing capability.

**When to use:** Any "this must never happen" invariant test (e.g. "no check reads this quarantined field") authored preventively rather than as a fix for an observed bug — the self-firing subtests are what makes the test's own correctness verifiable without a real failing baseline.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-04-SUMMARY.md

## Surprises

### The two identification checks disagreed with each other on a well-identified prescriptive claim
Before the WR-01 fix, a prescriptive claim with strong identification (e.g. `identification: randomized_experiment`) would clear DSX-CLM-020/021's clean path entirely, yet still be blocked CRITICAL by DSX-CLM-011 the instant its text used a lexicon causal verb — meaning no natural, well-identified prescriptive recommendation that states its own effect could ever pass.

**Impact:** This was invisible to the phase's own test suite because the only prescriptive fixture exercised (the flagship) was ALSO identification-bad, so the contradiction on a well-identified claim was never surfaced until a human/AI code reviewer read the two checks side by side.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-REVIEW.md

### The persona round overturned the requirement's own literal wording twice, loudly
The expert-persona round (Architect/Statistician/Auditor) amended REQ-P11.2-02 (severity delivery: new-code-flat-HIGH → reuse DSX-CLM-020/021 at causal parity) and REQ-P11.2-03 ("gerunds via the hedging path" → gerunds via ordinary verb-hit routing, HEDGE_TERMS as sole softener) — both flagged explicitly for human veto via the daily summary rather than applied silently.

**Impact:** Demonstrates that a headless persona-decision process can correct a requirement's stated design when it would otherwise reopen a severity-arbitrage or category-error hole, provided the amendment is recorded loudly (not silently) and left vetoable.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-DISCUSSION-LOG.md

### A candidate citation was found to argue the opposite of what it was cited for
Nosek et al. 2018 was initially considered to anchor the DSX-PRE-040/041 "firing" half (amendment-discipline discipline), but was found to actually argue that declared deviations are LEGITIMATE — the opposite of a firing justification. It was re-anchored to Simmons/Nelson/Simonsohn 2011 + Gelman & Loken 2014 + Wagenmakers 2012 for the firing half, keeping Nosek 2018 only for the clearing half (where a declared amendment is legitimate).

**Impact:** A near-miss citation-honesty failure caught before ship by the persona round's own re-examination, not by an automated check — reinforces why this project gates every new citation behind a human D-05 source read before it can be relied upon.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-DISCUSSION-LOG.md

### WR-01's fix was provably catch-preserving, resolving a genuine persona split empirically
The Architect and Statistician disagreed on whether to fix WR-01 now or defer it; the disagreement was resolved not by further argument but by empirically measuring the flagship fixture's finding set before and after the fix — it lost exactly one code (DSX-CLM-011) and gained none, still blocking CRITICAL on three other codes.

**Impact:** Shows a concrete technique for resolving a "fix now vs defer" disagreement: measure the fix's actual effect on the corpus rather than reasoning abstractly about risk.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-REVIEW.md

### A TDD-tagged task can have no genuine RED state to give
Plan 11.2-04's Task 3 was marked `tdd="true"`, but the invariant it tested (no check reads `decision.reversible`/`decision.deadline`) already held true after Tasks 1-2 completed — the fields were never read by any check to begin with. The executor could not produce a real failing-then-passing cycle and instead proved the test's own bug-catching capability via self-firing detector subtests.

**Impact:** A reminder that not every task requiring `tdd="true"` will yield an authentic RED phase; when the underlying condition is already true, the honest path is a documented regression guard with proven detection capability, not a fabricated RED.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-04-SUMMARY.md

### A plan's own literal verification command can be wrong about its own scope
Plan 11.2-06's Task 3 verify script globbed ALL of `examples/known-bad/*-ANALYSIS-SPEC.yaml`, which by execution time contained a 9th fixture (`weak-identification-mmm`, added by a different, earlier phase) that was correctly OUT of this plan's `revisit_when` requirement (it is `design.kind: observational`, not `experiment`). Running the plan's literal command reported a false "miss" even though the plan's actual acceptance criterion (all EIGHT of its own listed fixtures carry `revisit_when`) was fully satisfied.

**Impact:** The executor caught and documented the discrepancy rather than either (a) blindly adding a semantically meaningless field to the out-of-scope fixture to silence the literal command, or (b) silently ignoring the failure — illustrating that a plan's verify command scope should be checked against the actual corpus state at execution time, not assumed frozen from plan-authoring time.
**Source:** .planning/phases/11.2-prescriptive-claim-layer/11.2-06-SUMMARY.md
