## Decisions Made

- **spec_id field position and default:** last field on `InvocationHeader`, after `frame_digest`, defaulted to `None` — the only ordering a frozen dataclass with 4 pre-existing non-default fields and 9 no-spec_id construction sites permits without breaking any of them.
- **AmendmentRecord shape:** mirrors `DecisionRecord`'s hardcoded-literal `to_dict()` idiom rather than reading `RECORD_TYPES` back, matching the existing (decorative, unenforced) convention documented for that constant.
- **DSX-PRE-041 clearing rule:** `not is_placeholder_or_refusal(reason)` AND both digests present among recorded headers — deliberately not a phrase stoplist, so a plausible-sounding but digest-mismatched reason (e.g. "updated analysis" paired with digests the trail never recorded) still fails to clear.
- **Identity-free floor scope:** counts distinct `frame_digest` across every recorded header in the root, regardless of `spec_id` — by design, this re-opens the Phase-10 cross-spec false positive on a shared root (T-11.2-07, accepted residual). This is not a bug; it is the deliberate cost of a backstop a `spec_id` rename cannot defeat.

**3. [Rule 3 - Blocking issue] The real, committed (gitignored) `examples/DECISIONS.jsonl` and `examples/known-bad/DECISIONS.jsonl` trip the new identity-free floor**
- **Found during:** Task 2/3 full-suite verification (`python -m unittest discover -s tests`)
- **Issue:** `examples/DECISIONS.jsonl` already carries 5 distinct historical `frame_digest` values (years of accumulated test runs against the shared root — a pre-existing, documented landmine, "shared trail is 4.8MB and growing"); `examples/known-bad/DECISIONS.jsonl` carries 14. `DSX-PRE-041`'s identity-free floor (deliberately, per D-09/T-11.2-07) fires HIGH on any trail root recording more than one distinct digest with no clearing amendment — which this dirty, shared, already-existing root always does now. 8 test methods across `tests/test_dsx.py` (`TestCLI`, `TestAdmissibilityGateRegistration`, `TestAdmissibilityCorpusRegression`, `TestPhase11_1Code`) called `dsx gate verify`/`ship` directly against the real `examples/` root (no `--phase-dir` isolation, or a `shutil.copytree` that copied `DECISIONS.jsonl` along with everything else) and started failing once `DSX-PRE-041` existed. `scripts/check.sh`'s gate-contract smoke test additionally ran the good and bad specs through one *shared* isolated root per gate point, so even after isolating away from the real trail, the two specs' own headers collided with each other in the same way (T-11.2-07's cross-spec false positive, self-inflicted by the script's own loop structure).
