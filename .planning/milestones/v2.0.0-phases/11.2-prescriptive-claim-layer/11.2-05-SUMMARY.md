# Phase 11.2 Plan 05: Prescriptive Identification Parity Summary

Held prescriptive claims to the same identification standard as causal ones by widening the
`_check_causal_support` ctype gate to the superset `{causal, prescriptive}`, reusing DSX-CLM-020
CRITICAL / DSX-CLM-021 HIGH with no new code, and removing the weak-path hedge exemption for
prescriptive claims only — so relabelling causal→prescriptive buys zero severity arbitrage.

## What was built

- **RED (0405e47)** `tests/test_prescriptive_identification.py` — six stdlib-unittest cases:
  prescriptive none→DSX-CLM-020 CRITICAL, weak-unhedged→DSX-CLM-021 HIGH, weak-HEDGED→still HIGH,
  a message-differs-from-causal assertion, plus two causal-parity guards (hedged weak causal →
  no finding; unhedged weak causal → HIGH). The four prescriptive cases failed RED naming the
  missing DSX-CLM-020/021; the two causal cases passed unchanged.
- **GREEN (58ed8f2)** `dsx/checks/claims.py::_check_causal_support`:
  - Gate at line 147 changed `if ctype != "causal": return` → `if ctype not in {"causal", "prescriptive"}: return` (strict superset; causal path untouched).
  - DSX-CLM-020 none/blank branch and DSX-CLM-021 weak branch each split into two **literal**
    `report.add()` sites — one causal, one prescriptive — parameterising the message on claim
    type while keeping the identical code and severity.
  - Prescriptive weak claims fire DSX-CLM-021 regardless of `HEDGE_TERMS`; causal weak claims keep
    the hedge exemption (`elif not hedged`).
  - Identification is read from the claim layer (`claim.get("identification") or strategy`, resolved
    at :156), never `validity_frame.identification.strength` (D-11).
  - No `report.add` with a new code string; `dsx/findings.py` untouched.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Divergent-code pin update in tests/test_gen_finding_catalogue.py**
- **Found during:** Task 2 (GREEN), full-suite gate.
- **Issue:** The finding-catalogue generator scans source for `report.add` and pins the set of
  codes emitted with divergent (severity, title) text. Splitting DSX-CLM-020/021 into two literal
  sites each made both codes newly divergent, tripping
  `TestCanonicalDeclarations.test_divergent_code_set_is_exactly_the_pinned_five` — whose own message
  instructs "add it to `_CANONICAL_DECLARATIONS` deliberately."
- **Why literals (not a variable title):** `scripts/gen-finding-catalogue.py::_literal()` returns
  `None` for a non-literal AST node, so a computed `title` variable would have dropped DSX-CLM-020/021
  from `references/finding-codes.md` entirely — a documentation regression. Two literal sites mirror
  the existing divergent codes (DSX-COH-030, DSX-VAL-060) and keep both variants catalogued.
- **Fix:** Added the four pinned `(severity, title)` tuples for DSX-CLM-020/021 to
  `_CANONICAL_DECLARATIONS`. The generated `references/finding-codes.md` regenerated **byte-identical**
  (render keeps the last-seen causal row), so no catalogue file change was committed.
- **Files modified:** tests/test_gen_finding_catalogue.py
- **Commit:** 58ed8f2

No architectural changes (Rule 4) were needed. No authentication gates occurred.
