# Phase 11.3: Reporting completeness and missing-data discipline - Context

**Gathered:** 2026-08-27 (assumptions mode + expert-persona round — Statistician-led / Architect / Auditor)
**Status:** Ready for planning

<domain>
## Phase Boundary

The examined-but-unreported comparisons and the imputation method become **first-class
declarations the gate holds to account**. An under-declared multiplicity family (declaring one
hypothesis while reporting five) no longer buys silence; a single imputation treated as if
observed, under a declared missing-at-random mechanism, blocks **before the data is touched**;
declared row-exclusion rules must carry a justification; an unrecognised effect-size kind is a
visible MEDIUM rather than a silent skip; and the adversarial chart-audit report
(`CHART-REVIEW.md`) is validated for structural conformance by four deterministic codes with no
stochastic agent verdict allowed to gate.

**In scope (REQ-P11.3-01 … -07):**
- Multiplicity family counted as `max(declared family, reported tests)`; a non-empty family
  smaller than the reported set fires HIGH naming the absent metrics (REQ-01).
- `comparisons_looked_at` exceeding the reported results fires HIGH with the ratio quoted,
  **independent of whether a family is declared** (REQ-02).
- `missingness.method_implied` registered as a closed vocabulary in the existing frame-membership
  table; single-imputation-as-if-observed under MAR blocks **at plan** (REQ-03).
- A `validity_frame.exclusions` sub-block (rule, action, applied_before_split, justification); a
  rule without justification is HIGH; row counts live in results/profile, **never in the frame**
  (REQ-04).
- An unrecognised effect-size kind fires MEDIUM instead of silently skipping the magnitude guard
  (REQ-05).
- Four **structural** conformance codes validate `CHART-REVIEW.md` against
  `references/chart-review-schema.md`; no stochastic agent verdict gates (REQ-06).
- Fixtures/tests/catalogue current; full corpus re-run green (REQ-07).

**Out of scope, and not to be widened during planning:**
- **Missingness-rate reconciliation** (declared `missingness.rate` vs the profile's actual null
  rates). This is an OPEN ITEM in the ROADMAP, **not** a numbered requirement, and it is
  **deferred** by the Statistician-led persona round (D-07). It would false-positive on the
  canonical good fixture and force a frame-layer check to read the profile (a D-11 boundary
  breach). The concrete defect it targets is already covered by shipped checks. Entry condition
  recorded in `<deferred>`.
- A firing check on **post-split exclusions** (`applied_before_split: false` without a
  post-treatment-safety justification). The field is carried **record-only** in 11.3 (D-10); a
  MEDIUM-firing check is deferred.
- Computing any test statistic or posterior on the gate path (brief D-02).
- Making a frame-layer (`dsx/frame/*`) check read the data profile or `inference.paradigm`
  (brief D-11; `tests/test_frame_boundary.py`).
- Retrofitting the new closed-key shape guard (D-09) to the **legacy** `validity_frame` /
  `inference` blocks — the guard is born strict on the new `exclusions` sub-block only.
</domain>

## Implementation Decisions

### Locked upstream — do NOT re-litigate

- **brief.md is binding.** Load-bearing here: **D-01** stdlib-only on the gate path; **D-02** no
  test statistic/posterior computed on the gate path; **D-05** every check ships a primary-source
  `Citation:` + a `Reference value:`/`Structural criterion:` line + a test against a published
  value; **D-06** finding codes are never renumbered and getting the *count* wrong is worse than
  the digits; **D-11** frame-layer checks never read the profile or `inference.paradigm`;
  **D-14** reversing a decision needs a reversal record.
- **The reuse doctrine (`PROJECT.md` M-02, M-09).** One concept → one field/code; reuse the
  shipped vocabulary rather than add a parallel one. Governs REQ-02 (reuse `DSX-EXP-051`), REQ-03
  membership (reuse `DSX-SPEC-082`) and REQ-03 severity (reuse `DSX-VAL-060`).
- **Phase 4 multiplicity machinery.** `dsx/checks/design.py` `_check_multiplicity` (~:362-394)
  and `_check_exploratory_looks` (:399-441) already emit `DSX-EXP-050` (no correction declared),
  `DSX-EXP-051` (`comparisons_looked_at` > family) and `DSX-EXP-052` (missing count). `DSX-EXP-051`
  is already wired into the chart-review schema's **Gate B** proxy (`chart-review-schema.md:52`).
- **Phase 7 frame-membership + missingness machinery.** `_VALIDITY_FRAME_MEMBERSHIP`
  (`dsx/spec.py:1116-1126`) is a tuple of `(block, field, vocab)` rows fed to one membership loop
  emitting `DSX-SPEC-082` HIGH (`spec.py:1220-1239`); `missingness.mechanism` is already a row,
  `method_implied` is not. `_MISSINGNESS_METHOD_VALIDITY` (`dsx/frame/val.py:187-198`) denies
  `{complete_case, available_case}` HIGH under MAR and allows `{mechanism_model, selection_model,
  pattern_mixture_model}` under MNAR; `DSX-VAL-060` already branches HIGH/CRITICAL (`val.py:1145-1177`).
  **`missingness.rate` is read by no module today, by design** (`val.py:519`, `:1104-1106`: "a rate
  of zero must not become the cheapest way past it").
- **Phase 10 content lock.** `frame_digest()` (`dsx/decisions.py:245-250`) is sha256 over
  `{validity_frame, inference}` with `sort_keys=True` — it hashes the **whole `validity_frame`
  subtree recursively**. `DSX-PRE-020` (`dsx/frame/prereg.py:575-601`) fires CRITICAL when the
  current digest is absent from the recorded plan-gate set and `declared_at: pre_data`. Any new
  sub-field under `validity_frame` enters the digest automatically.
- **The frame→profile boundary.** Frame checks (`dsx/frame/val.py::check(spec)`) receive **only
  the spec**; no profile path is ever passed to a frame check, and `tests/test_frame_boundary.py`
  forbids `dsx.frame` from importing `dsx.checks` and from reading `inference.paradigm`. The data
  profile's `null_rate` is read **only** in the checks layer — `dsx/checks/dq.py::_check_null_rates`
  fires `DSX-DQ-030` against declared `assertions.max_null_rate` (`dq.py:211-248`).
- **Phase 11 code discipline.** One stable fact per finding code; two codes for one defect is
  forbidden; broadening a *shipped* code's firing set is acceptable only when no committed spec's
  verdict changes.

### Multiplicity: family undercount and comparison-vs-reported (REQ-P11.3-01, -02)

- **D-01: REQ-01 mints `DSX-EXP-053` HIGH — "declared multiplicity family is non-empty but
  smaller than the reported test set."** The family count used becomes `max(len(declared family),
  len(results.tests))`; when the family is smaller, the finding **names the absent metrics** (the
  reported test metrics not present in the declared family) and the remedy is "expand the family
  to every reported test." This is a genuinely distinct concept from `DSX-EXP-050` (no correction
  declared — orthogonal: a spec can declare `holm` and still undercount) and `DSX-EXP-051`
  (`comparisons_looked_at` scalar > family — a different field). *(Analyzer + Architect, one-fact-
  one-code confirmed; `DSX-EXP-053` verified free repo-wide.)*

- **D-02: REQ-02 REUSES `DSX-EXP-051`, mints no code.** Drop the `multiplicity.family`
  early-return at `design.py:403-404` so the check runs **independent of family presence**, and
  rebase the comparison from `len(family)` to `max(len(family), len(results.tests))`; quote the
  ratio ("N examined, M reported") in the detail. Verified verdict-neutral on the canonical good
  fixture: family=3, `results.tests`=3, `comparisons_looked_at=3` → `max(3,3)=3`, `3 ≯ 3` → no
  fire. The bad fixture (`comparisons_looked_at: 20`, family 5) still fires. *(Reuse doctrine;
  `DSX-EXP-051` already exists and is already a Gate-B proxy.)*

- **D-03: REQ-01's "stale cross-reference comment" fix uses STABLE function-name references, not
  new line numbers.** The target is the `PREREG_FACTS` block comment at `spec.py:469-472`, which
  hard-codes `design.py:452` (alpha), `:446` (interim_looks), `:407` (comparisons_looked_at) —
  all of which REQ-01/02's edits to `_check_multiplicity`/`_check_exploratory_looks` will shift.
  Replace the hard line numbers with the **reading functions** (`comparisons_looked_at` read by
  `_check_exploratory_looks`; `interim_looks` and `alpha` read by `_check_peeking`) so the comment
  cannot drift again — eliminating the staleness class rather than resetting a clock REQ-01 has
  already proven drifts. *(Architect amendment; rigour.)* Bonus (optional, `<deferred>`): the
  already-stale falsifier comment at `spec.py:143` is unrelated to multiplicity.

### Missingness: closed vocabulary + single-imputation blocks at plan (REQ-P11.3-03)

- **D-04: REQ-03 membership REUSES `DSX-SPEC-082`** — add a closed `MISSINGNESS_METHODS` vocab as
  a new `("missingness", "method_implied", MISSINGNESS_METHODS)` row in
  `_VALIDITY_FRAME_MEMBERSHIP` (`spec.py:1116-1126`); mints no code. **The vocabulary MUST be a
  superset of ≥7 methods:** `{multiple_imputation, single_imputation, complete_case,
  available_case, mechanism_model, selection_model, pattern_mixture_model}`. It must include
  `multiple_imputation` (the good fixture declares it, `good-ANALYSIS-SPEC.yaml:351`) or the
  canonical good fixture regresses to red; it must include `single_imputation` as
  **recognised-but-blocked** (D-05) or the block path is unreachable (an omitted method fires
  `DSX-SPEC-082` "unrecognised" instead of the intended plan-time block); and it must cover every
  method the existing `_MISSINGNESS_METHOD_VALIDITY` table already adjudicates, or the two checks
  contradict each other. *(Auditor blocker — the exact member list is locked here so it is not
  re-derived at plan time.)*

- **D-05: REQ-03 single-imputation-as-if-observed under MAR → CRITICAL (blocks at plan), REUSING
  `DSX-VAL-060`.** This requires a **per-method severity split** in `_MISSINGNESS_METHOD_VALIDITY`
  (`val.py:187-198`, currently one severity per mechanism): the MAR deny set splits into a HIGH
  subset `{complete_case, available_case}` (unchanged) and a new CRITICAL subset
  `{single_imputation}` plus its as-if-observed instances (mean/median/mode/LOCF treated as real
  observations). **Rationale (Statistician, unanimous):** single imputation **fabricates
  precision** — treating imputed values as observed sets `n` to the full sample and omits the
  missing-data variance component (Rubin's `T = W̄ + (1+1/m)·B` with `B` forced to 0), producing
  anti-conservative CIs and understated p-values. Complete-case under MAR only sacrifices power
  while reporting honest uncertainty, and has a documented unbiased sub-case (White & Carlin 2010);
  single imputation has none. Corrupting calibrated uncertainty in the anti-conservative direction
  is the gate's north-star sin — a structural defect no downstream evidence rescues, which is what
  CRITICAL/blocks-at-plan encodes. *(Statistician vote CRITICAL over HIGH; rigour.)*

- **D-06: the single-imputation-CRITICAL branch gets its OWN D-05 primary source** — Rubin (1987)
  *Multiple Imputation for Nonresponse in Surveys* §3.1 (the `T = W̄ + (1+1/m)·B` variance
  decomposition) or Little & Rubin (2019) Ch. 4 on single-imputation variance understatement.
  **Do NOT reuse the White & Carlin (2010) complete-case citation** already at `val.py:158-165` —
  it concerns *bias*, not the *SE fabrication* that makes single imputation strictly worse. The
  remedy string must name the escape: declare `multiple_imputation` or an explicitly
  variance-propagating method, so the CRITICAL is not a dead end. *(Statistician D-05 amendment.
  The primary-source read itself is owed at the formal 11.3 UAT/ship round — non-blocking for
  plan/execute, see `<deferred>`.)*

### THE named decision — missingness-rate reconciliation (Statistician-led): DEFER (Option B)

- **D-07: DEFER missingness-rate reconciliation as a gated-backlog entry-condition. It is NOT
  shipped in Phase 11.3.** `missingness.rate` stays read by no check (as today). **This closes the
  ROADMAP open item.** *(Statistician-led round, Auditor concurring, unanimous; tie-break
  rigour > reliability > flexibility.)*

  **Evidence that decided it (verified first-hand against the fixtures):**
  1. The concrete defect a rate check would target — "a column has more nulls than the author
     declared" — is **already covered by shipped, boundary-clean checks**: `DSX-DQ-030` reconciles
     the profile's `null_rate` against the declared `assertions.max_null_rate` cap
     (good fixture: `country` cap `0.05` ≥ observed `0.012` → passes, `good-ANALYSIS-SPEC.yaml:115-117`,
     `good-DATA-PROFILE.yaml:24`), and the mechanism↔method pairing is adjudicated by `DSX-VAL-060`.
  2. Under MAR + multiple imputation, the missingness **rate governs efficiency, not bias** — a
     declared analysis-column rate of `0.0` is simultaneously true while a non-estimand column
     (`country`, no region filter in the sampling frame) carries 1.2% nulls. There is no
     contradiction to flag.
  3. **No principled tolerance survives.** Reconciling against the *max column* null_rate fires on
     the benign `country` 0.012 (false positive); against *analysis columns only* it is vacuous
     (0.0 == 0.0) **and un-computable** — the frame has no machine-resolvable join from
     `missingness.rate` to specific profile columns.
  4. Option A would force **re-baselining the canonical good fixture** (declared rate → ~0.012, or
     a tolerance floor ≥ 0.012 every other spec then inherits) — the tell of a mis-specified
     check, and a floor that silently swallows a real 0.012 discrepancy elsewhere in the corpus.
  5. Rate-reconciliation is an **OPEN ITEM, not a numbered requirement**; REQ-03 is fully delivered
     by the closed-vocabulary membership (D-04) + single-imputation-blocks-at-plan (D-05).

  **Entry condition (all must hold before the backlog item may be admitted):** (1) the contract
  carries a machine-resolvable estimand-variables → profile-columns join so the check reconciles
  analysis columns like-with-like; (2) it lives in the **checks/dq layer** (reads the profile;
  frame stays D-11-clean) and reconciles analysis columns only; (3) its tolerance derives from a
  cited efficiency/bias threshold, reusing the per-column `max_null_rate` mechanism, not a magic
  constant; (4) the good fixture passes at `rate: 0.0` **without loosening any threshold** — if it
  cannot, that is the proof the check is wrong.

  **This is a LOUD persona decision, vetoable by the human via the daily summary. It is NOT a
  HUMAN-QUEUE re-scope** (§4): no numbered requirement is dropped or reworded — the ROADMAP asked
  discuss to decide this open item, and this is the decision.

### Exclusions sub-block (REQ-P11.3-04)

- **D-08: REQ-04 mints `DSX-VAL-080` HIGH — "a declared `validity_frame.exclusions` rule carries
  no justification."** A new frame-layer check in `dsx/frame/val.py` (spec-only), guarding on
  presence (fires only when `exclusions` is a declared dict/list carrying a rule), matching the
  `_check_measurement`/`_check_sampling_frame` pattern. **Placement UNDER `validity_frame` (not
  top-level) is load-bearing:** because `frame_digest` hashes the whole `validity_frame` subtree
  (`decisions.py:245-250`), a changed exclusion cutoff changes the digest and is caught by the
  existing content lock `DSX-PRE-020` with **zero new machinery**. A top-level `exclusions` (like
  `spec_id`, deliberately outside the digest) would escape the lock — **BLOCK any top-level
  placement.** *(Architect + Auditor confirm; `DSX-VAL-080` verified free.)*

- **D-09: REQ-04's "row counts never in the frame" is enforced DECIDABLY, not by honor system —
  mint `DSX-SPEC-083` HIGH ("unexpected key in the closed `validity_frame.exclusions` sub-block").**
  A closed-key shape guard scoped **only** to the new `exclusions` sub-block (born strict; key set
  `{rule, action, applied_before_split, justification}`), added alongside the existing
  `_validate_validity_frame_shape` membership loop (`spec.py:1220-1239`). **Rationale (Architect
  REVISION, rigour > reliability):** the shape validator accepts unknown keys silently today
  (`spec.py:1262-1269` says so for the sibling `inference` block), so "enforced structurally"
  would reduce to an honor-system convention. Leaving an *anticipated* prohibition (REQ-04 names
  it) as a silent no-op interacts destructively with the content lock — a hand-added `n_excluded`
  count is data-dependent, trips `DSX-PRE-020` on every data refresh, and trains operators to
  reflexively re-register (eroding the very control REQ-04 reuses). The guard is **not** retrofitted
  to the legacy tolerant blocks (that would be a regression-prone change); a new sub-block may be
  born strict without contradicting the legacy inference-block tolerance. *(`DSX-SPEC-083` verified
  free; sits catalogue-consistently in the 080-082 validity_frame-shape band — note the SPEC family
  already extends to 085/086, so 083 is a deliberate in-band choice, not merely "next free".)*

- **D-10: `applied_before_split` is RECORD-ONLY in 11.3, with an explaining comment.** The field
  is carried for the audit record; changes to it are already caught by the content lock (it is
  inside `validity_frame`, so `frame_digest` covers it), and no check reads its value in 11.3.
  This follows the `decision_threshold` record-only precedent (T-9-01). A firing MEDIUM check on
  post-split exclusions (`applied_before_split: false` with no post-treatment-safety justification)
  is a distinct concept/code and is **deferred** (`<deferred>`) rather than collected-and-ignored.
  *(Architect offered read-it-OR-record-only; taken record-only to hold 11.3 scope, with the honest
  comment + lock coverage that distinguishes this from the collect-and-ignore anti-pattern.)*

### Effect-size kind coverage (REQ-P11.3-05)

- **D-11: REQ-05 mints `DSX-STA-012` MEDIUM — "unrecognised `effect_size_kind`."** Fired from a
  membership guard that **PRECEDES** any `interpret_effect` call at `stats.py:278-289`: on the
  branch where `kind` is not in the recognised set, emit the MEDIUM and do **not** call
  `interpret_effect` (which `raise`s `ValueError` on an unknown kind at `mathx.py:302` — a
  gate-path traceback forbidden by D-01). **No `try/except` substitute** — that still routes an
  exception through the gate path. The guard's recognised set must be **single-sourced** with the
  `interpret_effect` table keys (`mathx.py:295-299`), or a test asserts the two sets are equal, so
  they cannot drift apart. **MEDIUM, not LOW** (too close to the silent skip it replaces — LOW is
  advisory noise-floor and would leave the magnitude guard `DSX-STA-011` effectively disabled) and
  **not HIGH** (we do not know the effect is negligible, only that we could not check — HIGH would
  over-claim and block). *(Statistician vote MEDIUM; Auditor guard-precedes ruling.)*

### Chart-review structural conformance (REQ-P11.3-06)

- **D-12: REQ-06 mints a NEW `DSX-CRV-*` family in a NEW module `dsx/checks/chart_review.py` —
  NOT `DSX-FIG-*`.** Four codes mirroring the schema's rule order (`chart-review-schema.md:84-87`):
  - `DSX-CRV-010` **HIGH** — frontmatter `schema` ≠ `dsx-chart-review-v1` (contract identity broken).
  - `DSX-CRV-011` **MEDIUM** — forbidden `X/10` substring present (schema mandates a 1–4 scale).
  - `DSX-CRV-012` **HIGH** — file does not end with `## CHART AUDIT COMPLETE` (the completeness
    sentinel — literally "reporting completeness"; its absence means the audit may be truncated).
  - `DSX-CRV-013` **MEDIUM** — a finding line carries neither a `DSX-` code nor `UNMAPPED`
    (traceability gap).

  **Rationale (Architect, all three tie-break axes → CRV):** reuse-FIG is a trap — the schema's
  own **Gate-D proxy** (`chart-review-schema.md:53`) wildcards open `DSX-FIG-*` at CRITICAL/HIGH,
  so a malformed `CHART-REVIEW.md` minting a `DSX-FIG-*` code would be swept into Gate D **inside
  the report that reports the gates** (circular, unreliable). Chart-review conformance is
  orthogonal-new (report structure ≠ figure byte-seal), not a *parallel form* of an existing
  concept, so the reuse doctrine does not bar a new family. Reserve `001-009` for a future
  "CHART-REVIEW.md declared but missing/unparseable" (analogous to `DSX-FIG-001` "not found");
  **mint only the four** (D-06: do not pre-mint unused codes). *(D-06 persona decision — new
  family, loud, vetoable via daily summary; all four codes + the CRV prefix verified free
  repo-wide.)*

- **D-13: REQ-06 "no stochastic agent verdict gates" — FORBIDDEN inputs to the four CRV codes.**
  A code's fire/no-fire condition must NEVER read: `final_assessment`; any of the seven `scores.*`
  (`analytical_framing`, `analytical_logic`, `data_confidence`, `statistical_integrity`,
  `visualization_quality`, `communication_quality`, `confidence_in_correctness`); the
  **agent-transcribed** `gates.A/B/C/D` `Pass|Fail` values (dsx recomputes gates itself from open
  findings — trusting the frontmatter copy lets a stochastic call gate); or the verdict prose of
  `## Executive Verdict` / `## Final Assessment` / `## Per-Exhibit Disposition` / Evidence bullets.
  **ALLOWED** (structure, not judgement): the `schema` tag value, the absence of `X/10`, the
  terminal `## CHART AUDIT COMPLETE` sentinel, the `DSX-`/`UNMAPPED` token on finding lines, and
  the presence/ordering of the fixed H2 headings. *(Auditor invariant.)*

- **D-14: REQ-06/07 — the schema Gate-proxy table must route `DSX-CRV-*` as a report-ACCEPTANCE
  precondition, not into Gate D.** `references/chart-review-schema.md:45-53` must be updated so
  `DSX-CRV-*` gates the validity of the report *as an artifact* (a precondition), rather than being
  folded into Gate D's `DSX-FIG-*` wildcard (which would re-introduce the circularity D-12 avoids).
  In-scope under REQ-07 ("catalogue/tests/corpus current"). *(Architect + Auditor.)*

### Fixtures, tests, catalogue (REQ-P11.3-07)
