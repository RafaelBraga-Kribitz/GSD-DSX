## Persona Round — Decisions and Votes

### DECISION 1 (Statistician-led) — missingness-rate reconciliation: **B (defer)**, unanimous
- **Statistician (lead):** B. The concrete defect is already caught by `DSX-DQ-030` (the good
  fixture's `country` cap 0.05 ≥ observed 0.012) and `DSX-VAL-060` (method pairing); under MAR+MI
  the rate is efficiency not bias; no principled tolerance survives (max-column false-positives,
  analysis-columns-only is vacuous and un-joinable); Option A forces re-baselining the gold
  fixture — the tell of a mis-specified check; it is an OPEN ITEM, not a numbered requirement.
- **Auditor:** B. Semantically ill-posed (raw null-rate vs post-imputation missingness);
  re-baselining is corrosive / introduces an author-gameable tolerance floor; deferring leaves no
  exploitable hole. Hard boundary ruling: any rate check reads the profile → **must** live in
  `dsx/checks/`, never `dsx/frame/` — a frame profile read is a D-11 BLOCK.
- **Outcome:** Defer with the four-part entry condition (D-07). Not a HUMAN-QUEUE re-scope.

### DECISION 2 — single_imputation under MAR: **CRITICAL**, unanimous
Statistician: single imputation fabricates precision (forces Rubin's `B=0`, anti-conservative
CIs/p-values) on top of bias, with no White-&-Carlin unbiased sub-case; complete-case only loses
power while reporting honest uncertainty → strictly worse → blocks at plan. Amendments recorded:
per-method severity split (D-05); the SI branch gets its own Rubin (1987) §3.1 citation (D-06).

### DECISION 3 — unrecognised effect-size kind: **MEDIUM**, unanimous
Statistician: LOW is too close to the silent skip it replaces (leaves `DSX-STA-011` effectively
disabled); HIGH over-claims (we could not check, not "the effect is negligible"). Auditor: the
guard must precede `interpret_effect` (no try/except), recognised set single-sourced with the
mathx table (D-11).

### DECISION A (Architect-led) — REQ-06 code family: **CRV (new family + new module)**
Architect: reuse-FIG is a trap — the schema's Gate-D proxy (`chart-review-schema.md:53`) wildcards
`DSX-FIG-*`, so a malformed report minting a FIG code would be scored inside its own Gate D
(circular). CHART-REVIEW conformance is orthogonal-new (not a parallel form), so the reuse doctrine
does not bar a new family. All three tie-break axes → CRV. Four codes `DSX-CRV-010..013` mapped to
the schema's rule order; 001-009 reserved, only four minted (D-12/D-13/D-14).

### DECISION B — REQ-04 exclusions: **CONFIRM placement + REVISE the "no counts" clause**
Architect + Auditor confirmed placement under `validity_frame` and the zero-new-machinery
content-lock claim (verified against `decisions.py:245-250` + `prereg.py:575-601`). Architect
raised a real flaw: "row counts never in the frame … enforced structurally" is a silent no-op
(shape validator accepts unknown keys, `spec.py:1262-1269`) and interacts destructively with the
lock — resolved by minting `DSX-SPEC-083`, a closed-key guard born strict on the new sub-block only
(D-09). `applied_before_split` resolved record-only with an explaining comment (D-10).

### DECISION C — REQ-01/02 one-concept-one-code split: **split-as-proposed**
Architect confirmed the three EXP concepts are orthogonal (050 no-correction / 051
comparisons-vs-family / 053 family-vs-reported-tests); overloading would break suppression
granularity and remedy clarity. Comment fix amended to STABLE function-name references, not new
line numbers (D-03).
