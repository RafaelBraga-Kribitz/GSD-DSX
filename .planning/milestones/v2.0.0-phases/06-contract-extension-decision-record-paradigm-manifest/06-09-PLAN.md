<objective>
Wire the decision trail end to end: `dsx gate` writes it, `dsx explain` renders it, and neither
touches the other's contract (REQ-P6-07, REQ-P6-08, D-04, D-14, D-16, D-18).

Purpose: D-04 puts `dsx explain` permanently outside the block contract — it always exits 0 and
carries no blocking flag, because a `--block-on` on a command that always passes is a lie in the
help text. The mirror of that rule is that the write path must never be able to change a gate's
verdict either: a trail that cannot be written is a missing trail, not a failed gate.

Output: the `add_common` refactor, the `explain` subcommand, the gate-path emission with sequential
id assignment, and the tests that pin every failure mode.
</objective>
