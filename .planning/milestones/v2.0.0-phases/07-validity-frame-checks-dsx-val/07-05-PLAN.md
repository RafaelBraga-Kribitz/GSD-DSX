<objective>
Ship the dependence check and the two identification checks, and land the two repairs those
checks would otherwise break in the same commits.

Purpose: these three codes carry the phase's sharpest claims. A declared dependence structure with
no method family is an analysis that already knows its observations are correlated and has decided
not to account for it. Weak identification declared with no constraint at all is the case the new
corpus fixture in plan 07-07 exists to demonstrate. Strong identification whose constraint carries
parameter-scale information is the quieter one — it is not necessarily wrong, which is why the
roadmap fixes it at the high severity that prints at plan and blocks only later.

Output: two new private helpers, one new module constant, a repaired template, a documented
corpus allow-list entry, and a gate-level proof that the severity split behaves as the roadmap
specifies.
</objective>

<recorded_decision>
The bayesian continuous-monitoring corpus fixture declares strong identification with informative
priors. Once `DSX-VAL-041` ships, that fixture surfaces the code at high severity, and the corpus
ship-gate test admits no blocking code that is not documented. Decision D-14 left the resolution
open between editing the fixture and adding an allow-list entry. This plan settles it: add the
allow-list entry, and do not edit the fixture.

The reason is that the fixture's declaration is true. It is a Bayesian analysis and it does use
informative priors. Editing it to say otherwise would make a Bayesian fixture claim it uses no
prior information, which is false, and would degrade the corpus's value as a record of real
analyses. The finding is a correct secondary observation about a fixture built to demonstrate a
different defect, which is exactly what the incidental-gap allow-list exists for. The test that
polices that allow-list forbids listing a code belonging to a target family, and the validity
frame family is not a target family for that fixture, so the entry is permitted rather than
smuggled in.

Cost of being wrong: if a later phase makes the validity frame a target family for that fixture,
the entry has to move. That is a one-line change guarded by an existing test that will fail
loudly, so it is cheap to undo.
</recorded_decision>
