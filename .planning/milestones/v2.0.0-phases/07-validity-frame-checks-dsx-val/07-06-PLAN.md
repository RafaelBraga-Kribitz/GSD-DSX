<objective>
Ship the last three checks — sampling frame, missingness and measurement — and repair the good
fixture in the same commit as the check that would otherwise block it.

Purpose: these three are the presence-and-internal-consistency end of the family. Two of them are
deliberately narrow, and the narrowness is a decision rather than a shortfall: no text comparison
strong enough to catch a sampling frame that quietly excludes part of its claim population also
lets the good fixture through, and the gate path may not compute anything heavier. The third, the
missingness pairing, is the one place in the phase where a single code carries two severities, and
that needs stating rather than discovering.

Output: three new private helpers, one new module constant, a repaired good fixture, a repaired
template, and a fixture-matrix regression test that runs the whole family against every spec file
in the repository.
</objective>

<recorded_decision>
Three decisions are settled here rather than left to the executor. Each was open in the inputs.

First, the severity of the missingness code varies by pairing. Decision D-03 lists it under high
severity; decision D-07 says a missing-not-at-random mechanism with no mechanism model stays
critical. These conflict on their face. D-07 wins, because it is the specific decision about this
code and it gives its reason: a published sub-case exists in which complete-case analysis is
unbiased under a missing-at-random mechanism, so a critical severity there would block honest
specs, while a missing-not-at-random mechanism with no model licenses no method at all. So the
code emits high severity for the missing-at-random pairing and critical for the
missing-not-at-random one. D-03's list is the headline, not the whole rule. This is stated in the
plan so a reader who checks the two decisions against the code finds the reconciliation rather
than an apparent contradiction.

Second, a mechanism declared as not assessed is skipped entirely. All three existing corpus
fixtures declare it alongside complete-case analysis, and neither corpus test has any allowance
for a finding on those three files. Skipping keeps them untouched. The deeper reason is that the
check adjudicates a declared mechanism against a declared method; an author who has declared that
they have not evaluated the mechanism has not made the claim this check judges. Whether an
unassessed mechanism is a defect in its own right is a real question and a different check.
Reversibility: cheap to undo, at the cost of three allow-list entries added deliberately.

Third, an unrecognised implied-method string is treated conservatively only where conservatism is
warranted. The implied-method field has no closed vocabulary in the contract, so free text can
appear there. Under a missing-completely-at-random or missing-at-random mechanism an unrecognised
string produces no finding, because the check cannot tell whether it names a valid method and
guessing would produce false positives at the highest-friction gate. Under a missing-not-at-random
mechanism an unrecognised string produces the critical finding, because that mechanism licenses
nothing except an explicit model of the mechanism, and a string the check cannot recognise is not
evidence that one exists.
</recorded_decision>
