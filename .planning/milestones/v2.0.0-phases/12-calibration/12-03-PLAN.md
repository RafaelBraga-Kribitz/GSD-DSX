<objective>
Validate the attribution sidecars authored in plan 12-01: first structurally (every sidecar names a real slug, a code in the closed catalogue∪backlog union, and a real §6.5 item id), then dynamically (each tag is falsified or confirmed against a live gate run so it cannot lie). This is the validation step — it is what makes the §6.5 counts trustworthy rather than a hand-maintained ledger.

Purpose: Close the tampering path where a hand-authored sidecar names a hallucinated code or launders a catch as a miss to game a §6.5 promotion count.
Output: Two new tests in the corpus harness — sibling-integrity (D-07) and live falsifiability (D-08) — plus the validated-union and §6.5-item-id helpers they share.
</objective>
