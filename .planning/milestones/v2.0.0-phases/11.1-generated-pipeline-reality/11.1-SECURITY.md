> Per-phase security contract: threat register, accepted risks, and audit trail.

**Register origin:** authored at plan time. All 8 `*-PLAN.md` files carry a `<threat_model>`
block with trust boundaries and a STRIDE register, so this audit verifies stated mitigations

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| analyst entrypoint file to regex engine | `dsx/checks/code.py` reads arbitrary analyst-authored `.py`/`.ipynb` text and runs pattern scans over it | untrusted source text, unbounded line length |
| repository fixtures to regression suite | the committed good/bad specs are what `scripts/check.sh` measures the gate contract against | test fixtures (trusted, version-controlled) |
| build tooling to shipped catalogue | `scripts/gen-finding-catalogue.py` decides which codes owe a citation | policy data (allowlist) |
| specification file to gate | declared vocabularies (`fit_on`, `model_score_source`, `selected_on`) read from analyst YAML | untrusted declared values |
| gate to decision trail | append-only decision records written once per run | local operator output |

## Audit Method and Its Limits

Stated plainly so nothing here reads as stronger than it is.

- **Directly verified in this audit (7 threats):** `T-11.1-01`, `T-11.1-02`, `T-11.1-03`, `T-11.1-12`, `T-11.1-22`, `T-11.1-27`, `T-11.1-32`. Each was executed or
  measured against the live code, not read from a document.
- **All 9 compiled patterns** in `dsx/checks/code.py` were timing-tested on non-matching lines.
  After the `T-11.1-01` fix, none is super-linear.
- **Closed by documented acceptance (7 threats):** disposition `accept` in the plan-time
  register, carried into the Accepted Risks Log above.
- **Not individually re-verified (30 threats):** closed on L1 corroboration —
  `11.1-VERIFICATION.md` (status `passed`), 807/807 tests green, and the gate contract unchanged
  at all four gate points. This is grep-depth evidence appropriate to `asvs_level: 1`. It is
  **not** per-threat execution, and a level-2 audit would not accept it.
- **Adjacent findings deliberately left as tracked work**, none of which is a registered threat:
  `CR-03` (whitespace defeats `DSX-CODE-001`), `CR-04` (keyword-argument fit calls invisible to
  `DSX-CODE-021`) and `WR-01` (only the first fit call per line is read) are routed to ROADMAP
  phase 11.1.1; `WR-02` and `IN-01` to `deferred-items.md`. These are detection-coverage gaps,
  not threat-register entries, and they do not affect `threats_open`.

**2026-08-21 — `T-11.1-01` found open, fixed, re-closed.** The plan-time mitigation claimed every
new pattern was "bounded, non-nested and linear". Measured: `FULL_FRAME_SPREAD_FILTER_RE` at a
fitted exponent of 3.05 (400 characters 0.17s, 800 characters 1.43s) and `FULL_FRAME_IMPUTE_RE`
at 2.00. Both run once per non-comment line of an analyst-supplied entrypoint with no length cap,
inside the blocking `execute` gate profile (`dsx/cli.py:102`) — and because the scan stops at the
first match, the cost fell on clean files rather than leaky ones. Fixed in commit `06ff2d7` by
splitting each pattern into two unambiguous sub-patterns combined in Python: measured linear at
2,000,000 characters in 0.048 seconds, with zero match differences across 14 probe cases. The
false comment at `code.py:53-60` and the citation forwarding it at `code.py:99` were corrected in
the same commit.
