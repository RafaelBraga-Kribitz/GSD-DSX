# Phase 11.1 Plan 03: Detect Statistical Tests That See the Declared Target (DSX-CODE-030/031) Summary

**Added a statistical-test marker family and a target-reference co-occurrence scan to `dsx/checks/code.py`, closing the blind spot where the reproduction's hypothesis stage never calls `.fit()` at all — it cross-tabulates a candidate feature against the target column and runs a chi-square test, then folds the accepted hypotheses back into the dataset.**

- **Duration:** single continuous session (not separately timed per task)

- **Files modified:** 4 (`dsx/checks/code.py`, `tests/test_dsx.py`, `scripts/gen-finding-catalogue.py`, `references/finding-codes.md`)

## Accomplishments

- `STAT_TEST_CALL_RE` added to `dsx/checks/code.py`: a bounded alternation over the seven statistical-test call names named in the plan (`chi2_contingency`, `ttest_ind`, `ttest_rel`, `pearsonr`, `mannwhitneyu`, `f_oneway`, `kruskal`), with a leading `\b` so a longer identifier that merely contains one of those names does not match.
- `_stat_test_lines_referencing(lines, target)` added: finds every non-comment, non-import line matching `STAT_TEST_CALL_RE` whose own line, or one of the three lines immediately preceding it, references `target` — the three-line lookback exists because the reproduction's idiom (`references/The AI Data Scientist.md`, Table 1) builds the contingency table (the line carrying the actual reference) one line before the test call that consumes it.
- The target reference is recognised in exactly three forms: single-quote subscript, double-quote subscript, and attribute access — all built from `re.escape(target)` so a column name containing regex metacharacters cannot change the pattern's meaning (threat T-11.1-11). A target that is a substring of a longer identifier is correctly excluded in both forms — brackets are exact by construction (the quote is the boundary), attribute access requires a literal `.` immediately before the target text and a trailing `\b` after it.
- `check()` reads the target via `model_section.get("target")` (the same `model` section already resolved for `has_model`) gated by the already-imported `is_blank()` — no change to `check()`'s signature; `git diff dsx/cli.py` confirmed empty.
- `check()` emits `DSX-CODE-030` (CRITICAL) for the first before-split (or no-split) match and `DSX-CODE-031` (HIGH) for the first at-or-after-split match, at most one of each, using the same strictly-less-than / greater-than-or-equal split `DSX-CODE-020`/`DSX-CODE-021` already use — verified with a test where the triggering call sits on the exact same line index as the split marker (graded HIGH, never CRITICAL).
- A second `DecisionRecord` (layer `deterministic`) is appended per `check()` run, covering both new codes, following the same shape plan 11.1-01 established for `DSX-CODE-020`/`DSX-CODE-021`.
- `check()`'s docstring gained the citation and structural-criterion lines for both new codes, with an explicit UNVERIFIED marker on the section locator (the full Kaufman et al. 2012 paper text was not independently re-read this session, consistent with plan 11.1-01's precedent).
- `DSX-CODE-030`/`DSX-CODE-031` added to `_D05_ALLOWLIST_CODES` (not `_D05_ALLOWLIST_PREFIXES`, byte-identical to its pre-plan value); `references/finding-codes.md` regenerated (233 → 235 total codes, exactly +2).

## Decisions Made

- Read the target via `model_section.get("target")` + `is_blank()` rather than `normalize()` (the pattern `dsx/checks/ml.py::_check_features` uses for the same field) — `normalize()` lowercases and cannot be used to build a case-sensitive source-text regex; `is_blank()` was already imported in this module and covers the plan's exact blank-target requirement (absent, empty, whitespace-only) in one call.
- Interpreted "require a non-identifier character before an attribute-form match" as requiring the literal `.` (not merely a generic `\b`) immediately precede the escaped target text — this is what excludes a bare identifier reference to a variable literally named `target` from being treated as an attribute-form reference, while a trailing `\b` independently blocks the target-as-prefix-of-a-longer-identifier case. Verified both directions with dedicated tests (`test_target_substring_of_longer_identifier_not_a_reference`, `test_target_reference_recognised_bracket_both_quotes_and_attribute`).
- Gave DSX-CODE-030/031 their own `DecisionRecord`, appended immediately after the existing DSX-CODE-020/021 record rather than merging into it — the plan's own phrasing ("a decision record covering both codes") scopes the new record to only the two codes this plan adds, and the two records judge structurally different questions (index/membership comparisons vs. a bounded-window co-occurrence match).
- Split the plan's two tasks into three commits (test/feat/chore) along RED/GREEN/wiring boundaries, mirroring plan 11.1-01's precedent — task 1's `<behavior>` and the docstring/decision-record pieces of the same function body are naturally one GREEN commit; task 2's D-05 allowlist + catalogue regeneration is cleanly separable.
