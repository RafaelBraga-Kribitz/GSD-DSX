# Phase 11.1 Plan 04: Unconditional Prediction-Time Check and Undeclared-Positive-Rate Finding (DSX-ML-043) Summary

**Moved the prediction-time-definition check (DSX-ML-033) out from behind `_check_features`'s early return so it fires whenever a model is declared, and added DSX-ML-043 (HIGH) so an undeclared or unparseable positive rate under an imbalance-unsafe primary metric produces a finding instead of silence.**

## Performance

- **Duration:** single continuous session (not separately timed per task)
- **Tasks:** 2
- **Files modified:** 4 (`dsx/checks/ml.py`, `tests/test_dsx.py`, `scripts/gen-finding-catalogue.py`, `references/finding-codes.md`)

## Accomplishments

- `_check_prediction_time_definition(model, report)` extracted from `_check_features`'s tail into its own module-level function, unchanged in code number (`DSX-ML-033`), severity (MEDIUM), title, detail, remedy and location string. Wired into `check()`'s dispatch as a sibling of `_check_features`, placed immediately after it. `_check_features`'s early-return condition (`if not isinstance(features, list) or not features: ... return`) is byte-identical before and after — confirmed by `git diff` showing no change to that block at all, not merely an unmatched hunk.
- `DSX-ML-043` (HIGH) added to `_check_metric_choice` as a sibling `elif` branch to the existing `DSX-ML-041` branch: fires when the task is a decision task (`binary_classification`/`multiclass_classification`), the primary metric is a member of `IMBALANCE_UNSAFE_METRICS`, and the positive rate — read from `model.positive_rate`, falling back to `results.positive_rate`, both via `as_number()` — is `None`. `as_number()` already returns `None` for a boolean and for any string it cannot parse, so an unparseable string arrives at this branch identically to an absent field; this is documented in the function's docstring so a future reader does not "fix" it into a separate exception-avoidance branch.
- The existing `DSX-ML-041` branch, its strictly-less-than comparison against `IMBALANCE_THRESHOLD`, and its finding text are untouched — verified by boundary tests at, one step below, and one step above the threshold, plus a positive-rate-of-one-half test.
- `_check_metric_choice` gained a docstring citation (Saito, T. and Rehmsmeier, M. (2015), "The Precision-Recall Plot Is More Informative than the ROC Plot When Evaluating Binary Classifiers on Imbalanced Datasets," PLOS ONE, 10(3), e0118432) with an explicit UNVERIFIED marker on the exact figure/table locator (the paper's figures were not independently re-read pixel-by-pixel this session; the DOI itself is real and was not invented), and a structural-criterion line naming the joint-absence-and-membership test DSX-ML-043 performs.
- `_check_metric_choice` now emits `dsx/checks/ml.py`'s first-ever `DecisionRecord` (via the shared `record_decision()` helper from `dsx/decisions.py`, the same import shape `dsx/checks/code.py` established in plan 11.1-03 — `dsx/checks/*.py` modules are forbidden from the `dsx/frame/*.py` inline `report.context.setdefault("decisions", ...)` idiom by `tests.test_dsx::test_no_check_module_appends_to_a_decisions_list`). The record is appended once a primary metric is declared, covering all four outcomes: `DSX-ML-041` fired, `DSX-ML-043` fired, cleared (declared rate not risky), or not applicable (task/metric outside the imbalance-risk scope) — a cleared or not-applicable judgment is still a judgment.
- `DSX-ML-043` added to `_D05_ALLOWLIST_CODES` (not `_D05_ALLOWLIST_PREFIXES`); `DSX-ML-040`/`041`/`042` — the three legacy codes sharing `_check_metric_choice` — deliberately left out of the allowlist, matching plan 11.1-03's precedent for `DSX-CODE-*`. `references/finding-codes.md` regenerated: 235 → 236 total codes, exactly +1.
- Full suite: 750 tests (up from 733 pre-plan, +17 new tests in `TestPhase11_1ML`; `OK`). `./scripts/check.sh` green end to end. `tests/test_known_bad_corpus.py` untouched (`git diff --stat` empty) and 23/23 green. `examples/good-ANALYSIS-SPEC.yaml` exits 0 at plan/execute/verify/ship; `examples/bad-ANALYSIS-SPEC.yaml` exits 1 at execute/ship; `templates/ANALYSIS-SPEC.yaml` exits 0 at plan — the fixture gate contract this plan's own automated verify command checks.

## Decisions Made

- Read `DSX-ML-041`'s existing branch and `DSX-ML-043`'s new branch as two structurally different tests on the same underlying question (a numeric threshold test vs. a presence-and-membership test) rather than trying to unify them into one comparison — this is stated explicitly in `_check_metric_choice`'s docstring so the plan's prohibition against retuning `DSX-ML-041`'s threshold or comparison operator reads as a design choice, not an oversight.
- Emitted the metric-choice `DecisionRecord` for every `_check_metric_choice` call that gets past the "primary metric not declared" early return, including the "not applicable" case (task not a decision task, or metric not imbalance-unsafe) — this extends plan 11.1-03's code.py precedent (record a judgment whether it fires or clears) to a fourth possible outcome the metric-choice function has that the code.py checks did not.
- Followed the plan's instruction to import `DecisionRecord` "the same way `dsx/frame/val.py` does" as a plain `from ..decisions import DecisionRecord` import, but paired it with `record_decision()` (not `dsx/frame/val.py`'s inline `report.context.setdefault(...)` append) because `dsx/checks/ml.py` lives under `dsx/checks/`, where `record_decision()`'s own docstring states it is "the shared write path for `dsx/checks/*.py` modules," and `test_no_check_module_appends_to_a_decisions_list` forbids the inline idiom specifically inside that directory.
