<objective>
Make D-05 bind the ontology data exactly as it binds check code: an uncited family entry fails the
build, and the two new finding codes come under the existing citation enforcement.

Purpose: REQ-P11-06 describes one mechanism and the script has two distinct code paths. The
existing `check_d05()` walks abstract syntax trees for `report.add(...)` call sites and resolves
Python docstrings; it has no file-path parameter for a data file and the script has never inserted
the repository root on the import path, so it cannot read the ontology at all. This plan adds the
capability that was missing and switches on the capability that already existed.

Output: `check_families_citations()` and its `sys.path` insertion, its wiring into the `--check`
branch under a `D-24:` prefix, `"DSX-ADM-"` added to `_D05_ALLOWLIST_PREFIXES`, and tests for both.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository working tree → release | The build-time gate is the last automated point at which an uncited claim can be stopped before it ships to an operator. |
| data file → build script | `references/families.yaml` is read by a script that runs in continuous integration and in pre-commit, outside the gate path. |
| import path mutation → test process | The script inserts the repository root on the import path, and the test suite loads the script by path inside the same process that runs every other test. |
