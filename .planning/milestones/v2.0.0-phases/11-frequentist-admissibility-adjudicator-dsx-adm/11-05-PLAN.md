<objective>
Create `dsx/frame/admissibility.py` and give it the two things everything downstream needs: a loader
that refuses rather than degrades, and exact-match alias resolution scoped to a candidate set.

Purpose: REQ-P11-02 asks that named tests resolve as aliases into families rather than being
enumerated as a test catalogue. The alias table is derived from the families themselves at load
time, so an alias cannot drift from the family whose citation justifies it. D-18 makes an
unrecognised alias escalate, and that refusal is the mechanism that bounds this phase's scope —
there is no completeness pressure on the alias list precisely because an unknown name is a decidable
outcome rather than a guess.

Output: the module, its ontology dataclasses, `load_ontology()`, `alias_index()`,
`candidate_families()` and `resolve_declared_procedure()`, with tests. No finding is emitted yet.
</objective>

| Boundary | Description |
|----------|-------------|
| installed data file → adjudicator | `references/families.yaml` sits on disk beside the package and is read at gate time. Anything with write access to the install directory can change what the gate considers admissible. |
| spec author → alias resolver | `inference.primary_procedure` is untrusted operator text that selects a family and therefore a set of assumptions the tool will report as bought and charged. |
| `dsx/frame/` ↔ `dsx/checks/` | The two packages must stay independently extractable. This module is the first with a real incentive to cross the boundary in either direction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-18 | Tampering | a hand-edited `references/families.yaml` adding an uncited family | high | mitigate | `load_ontology()` drops any entry whose `citation` is blank or absent and records the dropped id, so an uncited family can never be ranked even when the build-time gate was skipped. This is the run-time half of D-24 and does not depend on the build-time half having run. |
| T-11-19 | Spoofing | a procedure label crafted to resemble a real alias | high | mitigate | Resolution is equality after `normalize` and nothing else. A test asserts that a one-character variant of a real alias resolves to `unresolved`, and the plan's prohibition forbids introducing any distance or containment comparison. |
| T-11-20 | Denial of service | an absent or unreadable ontology file at gate time | medium | mitigate | The absence raises `CheckError`, which the CLI maps to exit 2 with a message naming the path and the installation. The failure is loud and correctly attributed, rather than degrading into a blocking finding against the analyst's frame. |
| T-11-21 | Repudiation | an alias owned by two families in one axis pair | medium | mitigate | `alias_index` raises `CheckError` on the collision naming both ids, so the resolver never silently picks one by traversal order and the reported family is always reproducible. |
| T-11-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package and adds no runtime dependency; the module uses only the standard library and already-shipped in-repository modules. No package-legitimacy checkpoint applies. |
</threat_model>
