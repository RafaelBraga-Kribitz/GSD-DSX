<objective>
Deliver REQ-P16-04: a non-vacuous, positive-controlled static test proving that no `dsx/checks/` or
`dsx/frame/` module executes the analysis entrypoint. It AST-walks every module under those two
directories and denylists the execution-primitive family, asserts the scan examined a named non-empty
set including `code.py` and `repro.py`, and proves via a positive control that a synthetic
`subprocess.run([entrypoint])` / `runpy.run_path(entrypoint)` is flagged — while a negative control
proves `ast.parse`/`ast.walk`/`ast.unparse` and `re.compile` are not.

Purpose: this is the orthogonal complement to `tests/test_gate_path_hermetic.py`. That test forbids a
forbidden IMPORT reaching the gate closure; this one forbids a gate module EXECUTING the entrypoint —
and `subprocess`/`runpy`/`os.system` are stdlib, so they pass the import-based test silently (Auditor
T3). REQ-P16-04's assertion is currently true (baseline: zero execution primitives) but UNTESTED; this
plan gives it teeth. It runs in wave 2 after 16-01, so the scan covers the `repro.py` that already
carries `_check_reproduce_report` — the guard bites on the merged file.

Output: `tests/test_no_entrypoint_execution.py` (new).
</objective>
