## 1. CLI sweep (run, not trusted)

```
$ node ~/.claude/gsd-core/bin/gsd-tools.cjs query audit-uat --raw
{ "results": [], "summary": { "total_files": 0, "total_items": 0,
  "by_category": {}, "by_phase": {} } }
```

The CLI reports **All Clear (0 files, 0 items)**. This is a **false negative** and is
**not accepted**. Exact mechanism, confirmed by reading
`~/.claude/gsd-core/bin/lib/uat.cjs`:

- **Defect A (frontmatter-status gate, lines 78–94).** The `-VERIFICATION` filename
  filter *does* match all four `NN-VERIFICATION.md` files, but the CLI only emits a
  verification file when `extractFrontmatter(content).status ∈ {human_needed,
  gaps_found}`. Phases 18/19/20 carry frontmatter `verdict: PASSED` (no `status:`
  key); Phase 17 carries no frontmatter at all → `status` resolves to `unknown` →
  every file is silently dropped. A `PASSED` phase with human sign-off items batched
  to the queue is therefore invisible to the CLI.
- **Defect B (heading-level parse).** `parseVerificationItems` recognizes a level-2
  `## Human Verification` heading while the verifier template writes level-3
  `### Human Verification Required` — so even a `human_needed` file's items would not
  be counted. (Recorded at v2.0.0; still present.)

Net: the CLI cannot see the outstanding end-of-phase human sign-offs. The hand-check
below is the authoritative S5-1 result.
