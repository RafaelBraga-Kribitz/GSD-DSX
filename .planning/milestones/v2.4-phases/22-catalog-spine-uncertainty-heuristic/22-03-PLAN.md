<objective>
Ship the merged, citable chart catalog as a new reference document — 75-90 rows, each with
three axes (function, data signature, Cleveland–McGill perceptual rank) and a per-row
citation, DSX-admissible vs reference-only vs refusal clearly flagged — plus the two
off-gate-path repo-integrity tests that keep it honest: catalog↔vocabulary conformance and
the perceptual tie-break structural criterion.

This produces one reference artifact (not a gate check — the catalog documents, it does not
adjudicate) and one test module. It implements REQ-P22-01 (the merged catalog with three
axes + citation) and the REQ-P22-05 perceptual tie-break (a pure ordering assertion, off the
gate path, no computation). The catalog is built AFTER the vocabulary is final (Plans 22-01
and 22-02): its dsx_admissible rows are the live 60-mark universe (50 inherited + the ten
uncertainty marks) and its seven refusal rows cross-reference the live seven BANNED_TYPES,
so the conformance test reads the live dicts and a drift is caught at commit.

Purpose: the catalog is the milestone's centre of gravity and carries the D-05 citation
load. Its correctness is not prose judgement — it is machine-checkable: every admissible
mark has exactly one row, every refusal row is backed by a real ban, the rank data obeys
D-1, and every citation traces to the signed pack. Splitting the work into acquisition,
authoring, and verification keeps each within budget and keeps the citation provenance
auditable.

Output: references/chart-catalog.md with a fenced json payload, and
tests/test_chart_catalog_invariant.py proving band, shape, conformance, tie-break, and
citation traceability.
</objective>

<threat_model>
## Trust Boundaries

This plan adds one human-facing reference document (explicitly not a gate check) and one
off-gate-path test. No network, no untrusted input, no auth/session, no persistence beyond
the repo's own Markdown/test files. The realistic threats are integrity/drift threats on the
catalogue's authority claims and on citation provenance — a catalog that asserts a ban the
gate does not enforce, or a citation presented as verified that is not.

| Boundary | Description |
|----------|-------------|
| catalog → reader trust | The catalog makes authority claims (this mark is admissible; this type is refused; this citation backs it). The conformance test is the control that keeps those claims true to the live gate and the signed pack. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-07 | Tampering | A catalog refusal row claiming a ban the live BANNED_TYPES does not enforce, or an admissible row for a mark not in the live universe (the drift surface Phase 21's doctrine forbids) | medium | mitigate | The catalog↔vocabulary conformance clauses (Task 3 c/d) read live BANNED_TYPES and _mark_universe() and assert set-identity both directions; a stale catalog turns the test red at commit (REQ-P22-01). |
| T-22-08 | Repudiation | A shipped citation tracing to an HQ-27 still-unverified item, or to Abela 2008 / Few's Graph Selection Matrix (never submitted), presented as verified; or a triangulation claim across the Ribecca lineage | medium | mitigate | The citation-traceability negative guard (Task 3 g) fails on any forbidden token; the acquisition task (Task 1) drops any citation not traceable to a signed HQ-27 row as [ASSUMED]; lineage rows name the lineage, not triangulation (cross-cutting finding). |
| T-22-09 | Tampering | A reference_only row silently widening what the gate admits (a documented type mistaken for an admissible one) | low | mitigate | The reference-only isolation clause (Task 3 e) asserts every reference_only mark is NOT in _mark_universe(); the gate reads the live dicts, never the catalog. |
